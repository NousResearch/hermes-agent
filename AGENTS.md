# Hermes Agent — Working Guide

Hermes runs one personal-agent core across CLI, messaging gateway, TUI, and Electron desktop. Keep the core narrow and capability at the edges. **Never give up on the right solution.**

This root contains critical invariants and task routing. The [retained development manual](docs/development-guide.md) preserves the detailed upstream guidance. Before editing a subsystem, read its complete relevant sections from the table below; they remain operative policy. Update the reference alongside any changed contract, and reconcile upstream guidance changes when merging upstream. Do not copy the full manual into unrelated tasks.

## Contribution And Authority

- Verify the reported behavior and original intent against current code and `main` before calling a limitation a bug. Reproduce the symptom, identify where it manifests, and cover sibling paths in the same bug class. Preserve contributor authorship when salvaging external work.
- Product breadth, adapters, providers, desktop/TUI features, and declared module extractions are welcome. Restraint applies to permanent core/model-tool footprint: extend existing code → CLI + skill → service-gated tool → plugin → catalog MCP server → new core tool as last resort. Reuse shared interfaces; avoid speculative hooks without a concrete consumer.
- Plugins must not modify core files or add vendor-specific logic there. New memory providers and third-party-product integrations belong in standalone plugin repos; existing in-tree providers may receive fixes. Preserve native plugin compatibility, deprecation windows, and state replay/migrations in the reference.
- Automated triage may close only for `implemented_on_main`, `cannot_reproduce`, or `incoherent` with evidence. Taste and won't-implement decisions belong to a human maintainer; uncertain design intent is not automated closure authority.
- Follow the approved task's edit/review/delivery scope. Preserve unrelated work; examples in the manual do not authorize reset, overwrite, publication, or deployment. Before merging, reconcile current `main` safely and inspect the final diff for unrelated reversions.

## Critical Runtime And Security Invariants

- Keep each conversation's cached prefix and system prompt byte-stable. Do not alter past context, change toolsets, reload memories, or rebuild prompts mid-conversation; context compression is the exception. Cache-affecting slash commands defer invalidation to the next session by default and require opt-in `--now` for immediate invalidation. Preserve strict message-role alternation; never inject a synthetic user message mid-loop.
- Surface capability comes from the session, not the backend process environment. Named toolsets gate desktop/project surfaces; `check_fn` answers reachability or user opt-in, never per-session surface identity. Cover a GUI session with `HERMES_DESKTOP` absent. Do not hardcode cross-tool schema references to tools that may be unavailable; resolve conditional references dynamically in `model_tools.py`.
- State paths use `get_hermes_home()` and user-facing paths use `display_hermes_home()`. Profile selection precedes imports; profiles stay independent. Profile-management roots are intentionally HOME-anchored. Credential-bearing adapters acquire/release scoped token locks.
- Multiplexed profile credentials **and authorization** must fail closed: use `_get_scoped_secret()`, `_auth_env()`, or `_platform_gate_env()` as appropriate. A scoped miss must never borrow the default profile's `os.environ`; only genuinely unscoped/default or single-profile paths retain that fallback. Read the complete profile rules before changing adapters or config resolution.
- Non-secret behavior belongs in `config.yaml`; `.env` is for secrets. Check CLI, setup, and gateway loader coverage. Bump `_config_version` only for an actual config transformation, not an additive default. Do not add outbound telemetry/attribution without generic user-facing opt-in (config, setup, and `hermes tools`). Security fixes must preserve the feature's purpose.
- Bound dependency versions: PyPI lower/upper bounds (including the reference's pre-1.0 rule), Git/GitHub Actions commit SHAs, CI-only pip exact pins. Regenerate `uv.lock` when adding Python dependencies.
- Approval/control commands must bypass **both** active-session guards (base adapter and gateway runner) and dispatch inline. Stream-is-the-message adapters require prefix-stable drafts, consumer-owned final payloads, `_interim_send` metadata for nonfinal sends at every egress, and edit-first reconciliation of sealed streams.
- Preserve transactional update stages: plan, snapshot every profile, apply, restart per kind, verify every live gateway's code revision, and report all outcomes. ZIP fallback only follows a Git failure and refuses dirty trees; never weaken snapshot coverage or widen process tree kills. The messaging gateway survives closing desktop; `hermes serve` is the app-owned child. Use canonical argv matchers and gateway control-socket coordination, not new substring scan heuristics.
- Bots resolve exactly one hidden `Bot Chat` by `(profile, title)`, adopt before creating, and share that registry identity for preview and opening. Never restore a session-id pin, recency fallback, or per-bot session browser.
- Curator touches agent-created skills only, archives rather than deletes, and exempts pinned skills from automatic transitions/review. Cron retains its hard interrupt, duplicate tick lock, catchup/grace bounds, skipped memory, and separate delivery session. Kanban's board is the hard isolation boundary; tenant is a namespace within it.

## Validation

- Python tests **always** use `scripts/run_tests.sh`, never direct `pytest`. Prefer the closest affected file/directory; the wrapper supplies CI-parity credential isolation, locale/timezone, and per-file processes. Treat reported flakes as bugs.
- Tests must never write to real `~/.hermes`. Use temporary `HERMES_HOME`; profile tests also mock `Path.home()`. For config propagation, resolution, security, remote backends, or file/network I/O, exercise the real path with real imports against temporary state. Do not wire dead code into a live path on mocks alone.
- Test behavior and invariants, not changing catalog/version/count snapshots or source-code text. Put JS artifact/config tests in the JS suite so change-classified CI runs them. Test host-specific behavior on the real host using `linux_only`, `macos_only`, or `windows_only` markers; do not fake `sys.platform`, use bare `skipif`, or skip non-host parameter rows. Windows process-topology claims require the documented live `wine2e` lane when authorized.
- TypeScript follows the reference's feature-owned nanostores, thin route roots, narrow hooks/actions, and explicit async-handler guidance. Desktop work also follows [apps/desktop/AGENTS.md](apps/desktop/AGENTS.md). The web dashboard embeds the Ink TUI for primary chat; Electron desktop has its own chat surface and shared transport, independent of the dashboard frontend. Preserve user-enabled skill/quick-command completions.
