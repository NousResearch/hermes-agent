# Candidate Python API and bounded coverage contract

This documents the actual isolated candidate, not installed behavior or activation approval. Actor: Hermes CLI worker, not BUREAU/CLIENT. Independent review remains required.

## Supported authority and enrollment

One authoritative SQLite board database, accessed through candidate hermes_cli.kanban_db APIs. No sole-authority proof across copied databases, external fencing, recovery, publication or old-worker execution-tree exclusion. Caller-provided non-secret identity strings are assertions, not independently authenticated identity.

- `connect(path)` / `connect_closing(path)` perform the owned additive schema initialization. Ordinary boards get empty authority tables but remain unenrolled. Existing experimental history schemas with different exact table/guard definitions are refused, not upgraded, repaired or backfilled; this candidate has never been activated here.
- `authority_history_capability(conn)` returns None or `{version, incarnation, coverage_start}`. Capability is enrollment metadata, not a statement that all retained records or live ownership have been validated. Reader and audited writes perform those additional validations.
- `enroll_authority_history(conn)` permanently enrolls the board, generating a UUID incarnation. Repeat enrollment returns the same capability. Board enrollment does NOT enroll any task, assert historical vacancy, or cover all board activity.
- `bind_authority_task(conn, task_id, repo_id=..., project_id=...)` permanently binds a task. Task must have no prior runs, claim or current run, and status todo/ready/triage/blocked/scheduled. Emits `history_bound` in the same transaction: this is that task's prospective coverage start, not its creation time. Equal rebinding is idempotent; conflicting rebinding refuses.
- `bind_authority_owner(conn, task_id, claimer=..., consumer_id=..., runtime_id=..., owner_ref=...)` prebinds an exact claim credential to non-secret identity. `runtime_id` must identify the intended runtime INSTANCE, not just a product/version label; uniqueness is caller responsibility. There is no separate instance field or external registry. Run identity is the retained run ID plus authority incarnation/task binding. Credential hashes stay private in DB tables; public records do not export bearer tokens or token hashes. Public identifiers must themselves be non-secret.
- Claims still use the existing `claim_task` / `claim_review_task` arbitration; enrollment adds capture/validation, not another scheduler. Unbound credentials cannot grant enrolled ownership.

## Writer and reader contract

Supported authority writes use `write_txn`, the existing IMMEDIATE transaction plus before/after audit and a connection-local owned-writer gate. Persistent task/run mutation and authority-table insert triggers refuse raw autocommit/explicit-BEGIN callers, including additional SQLite connections. UPDATE/DELETE and replacement guards retain identity/history. This is an accidental/unsupported-writer boundary, NOT protection from administrators who can replace schema, register their own UDF, use internal writer contexts deliberately, or rewrite files.

Capture occurs in `_append_event`, before COMMIT, in the same DB. Journal errors roll back operational tasks/runs/source events and retained bindings/history. Audit validates final live task/run/credential relationships and the last observed snapshot per changed/observed task/run. Intermediate SQL statements are not individually committed ownership facts. Exceptions do not grant execution exclusion: non-DB process side effects cannot be rolled back by SQLite.

`read_authority_history(conn, incarnation=..., after=0, limit=1000)` requires its own read snapshot and a matching incarnation; after must be an exact nonnegative int, limit an exact int in 1..10000. Returns capability plus highwater, after, records, next_sequence. Sequence is global to the board's enrolled stream, exact positive adjacency 1..N. Source-event IDs may legitimately have gaps. No partial page is returned if validation finds a malformed retained record, even before the requested cursor; the entire retained stream is validated. `after > highwater` refuses, but this does NOT detect all filesystem rollback/fork histories. Empty records do not mean global vacancy.

Each public record includes sequence, version, incarnation, immutable task binding, event kind, source_event_id, observed_at (actual source created_at integer seconds), task_state, run_state, owner. Task snapshot: status/current_run_id/claim_expires. Run snapshot: id/status/claim_expires/started_at/ended_at. Owner snapshot: version/consumer_id/runtime_id/owner_ref. Strict JSON rejects duplicate keys/non-finite values; validator checks types, schema, retained task/run/owner/source provenance, sequence and source uniqueness. Legitimate synthetic unowned terminal runs remain allowed. Original operational source rows may be GC'd; retained provenance is separate and immutable.

Raw event payloads, error strings, arbitrary prose, title/body/priority, worker PID, filesystem receipts and process state are not exported. Kinds recognized by `kanban_history.KINDS` include informational events (comments, attachments, edits, links etc.); such events are snapshots, not new authority grants or proof of work. Raw dashboard event inserts that only change prose/priority are not promised as lossless journal coverage. The journal does not reconstruct every operational event or physical process transition.

## Deletion and identity copy

Enrolled active task deletion refuses; ordinary-board behavior is preserved. Completion/archive closes and journals the run first; subsequent hard deletion retains that terminal record plus logical task tombstone, independent of operational GC. A deleted tombstone is not a claim that a process died.

`remove_board` refuses any enrolled board. Ordinary removal first commits an irreversible reservation, preventing a racing enrollment. Failed filesystem removal leaves ordinary use possible but subsequent enrollment permanently refused; the current-board pointer may already have been cleared before filesystem failure. No automatic reversal/new incarnation exists.

Supported profile clone-all/import inspects the staged standard Kanban databases before moving the copied profile into place. ZIP import and quick-snapshot restore refuse incoming enrolled identity or an enrolled target before overlay. Discovery covers root kanban.db, kanban/**/kanban.db and nested profiles. Config-only clone does not copy the standard board DB. Export alone is not activation. External/custom DB paths, symlink aliases, arbitrary filesystem copies, online-copy races and filesystem snapshot rollback are outside the continuity guarantee: UNKNOWN/unsupported, not automatically reconciled. No cross-database fencing/new-epoch procedure is provided.

## Limits and review gates

Not exhaustive dynamic-SQL/caller coverage, administrator tamper detection, power-loss durability, synchronized contention stress, full legacy variant testing, arbitrary whole-install attestation, end-to-end deployed worker/recovery testing or whole-repository regression testing. Strict-stream tests cover the listed malformed cases, not all possible coherent administrator rewrites or complete retained-binding/first-history_bound bijection proofs. Full-stream validation cost is unbenchmarked. Unsupported event kinds fail closed rather than being silently skipped.

Windows broken-symlink fixture privilege remains an explicit verification limitation (WinError 1314 before export is exercised). POSIX secret-file permission test is pre-existing platform-skipped. No test assertions were disabled to conceal a functional failure. Independent reviewer must assess the final sources and these bounded claims before any integration decision.
