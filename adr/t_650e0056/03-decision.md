## Follow-up review finding — cancel commit vs claim snapshot (before implementation)

Fresh review `deleg_cd0fb1d7` returned `passed=false` with a P2 stale-snapshot finding. Read-only source trace confirms the relevant ordering: `_claim_next` holds `live.mutation_lock` while it reads and publishes the async pending snapshot; `cancel_queued` currently does not acquire that lock, and `_commit_cancel` commits via `asyncio.to_thread` before `_settle_cancelled` publishes. `SessionEvents.pending_revision` advances only when a changed pending-bearing `session.info` is published; `_publish_pending(admission_rows=...)` and `pending_rows(..., admission_rows=...)` use the supplied rows rather than re-reading storage. Therefore a claim can publish a snapshot taken before a cancellation commit while the cancel's loop-side publication is still pending. The inspected user/API/automation cancellation call sites add no `mutation_lock` around `cancel_queued` (the automation completion caller holds only `_heartbeat_lock`).

Superseded initial proposal (broad `live.mutation_lock`, rejected after the no-retry regression): make the tracked cancellation coroutine itself acquire the per-session `live.mutation_lock` before re-reading the receipt, then hold it through `_commit_cancel` and `_settle_cancelled` publication. `cancel_queued` continues to use `track_mutation` plus `asyncio.shield` around that helper; the tracked task—not the outer request task—owns the lock, so a cancelled caller cannot release it while a committed write is awaiting settlement. Release the lock when settlement is complete, before media collection. This shares the exact lock already held by `_claim_next`; it yields a valid order either claim-publish then cancel-commit/publish, or cancel-commit/publish then claim-read. Keep SQLite writes off-loop and outside `event_stream.lock`. Reject an outer `async with mutation_lock` around a shielded tracked task: `CancelledError` would unwind the outer lock while the inner tracked task continues. Reject a second storage read under the event lock (would block the loop) and an unsynchronized second async reread (still has a commit-to-publish race). The new regression must show the old path can expose the cancelled admission as queued after commit and that the selected synchronization prevents it, including when the outer caller is cancelled.
