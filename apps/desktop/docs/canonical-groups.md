# Gateway-owned groups in Desktop

A Group Chat is either a **gateway room** (the gateway owns its log and runs its turns; `canonical-group*` in `src/plugins/hermes-bots/`) or a **classic room** (Desktop runs its rounds; `group-*`). Opening a gateway room captures its exact authority (connection, profile, room id); changing the foreground profile does not retarget its controls.

## Which rooms are gateway rooms

One classifier, `groupExecutionMode`, reads `groups.capabilities`. Two surfaces answer it: the gateway's own (`gateway/session_group_controls.py`) and the standalone server's older one, reached by SSH, URL and Cloud connections (`hermes serve`, `hermes dashboard`; `tui_gateway/methods_groups.py`).

- **Gateway rooms:** an answer with `driver: true`, from either surface. Both run their own room driver, so these rooms keep working while Desktop is closed. An answer without a running driver is unavailable (below), but a room Desktop has already bound (opened from the gateway list, or earlier in this session) still opens and says its group driver is unavailable.
- **Classic rooms:** only a server that reports no room driver and owns no rooms (`driver: false`, `persistent_process: false`), as on `main`. Desktop runs those rooms itself; no other answer falls back to it.
- Anything else is unavailable, and the gate says why and offers **Retry**: a server without the group surface (`-32601`) or with an answer Desktop can't read is too old for group chats (update Hermes on that computer and reconnect); an answer whose driver isn't running asks to restart or update Hermes there; a transport error, or a socket that isn't open, could not reach the gateway.

A gateway room offers a control only when the answer's `methods` lists its method: Discard (`groups.discard`), Retry (`groups.retry`), Allow and Deny (`groups.approve`), file upload and download (`groups.attachment.upload`, `groups.attachment.download`), Rename (`groups.rename`) and End group chat (`groups.disband`). The standalone surface lists no `groups.discard` and no attachments, so Discard and file upload do not appear there and **Download** stays disabled. The list holds for one opening of the gateway socket: an update restarts the gateway, so when the socket reopens the list is read again, and a reply that started before the socket changed is dropped. Until a read for the current opening succeeds none of these controls is offered, and a failed read is tried again every two seconds while the room is visible; a successful answer without a method list keeps them all.

New Group Chat on a gateway connection offers only the Bots the gateway says it will seat (`seatable_profiles`) and creates a gateway room. When the gateway refuses, Desktop shows "The gateway couldn't create this group chat." followed by the gateway's own detail when it gives one; for a Bot it will not seat, that detail names the member.

A classic room opened on a gateway connection is first looked up by name in `groups.list`; a match opens that gateway room. Otherwise it never runs there, as on `main`, whichever computers its Bots are on: the gate says what happened, why, what to do and what happens to the earlier messages.

- Bots that can form a gateway group on this connection: the gate offers **Start new group**, a fresh gateway room with the same Bots that keeps working when Desktop is closed. Earlier messages are not copied into it.
- Bots on other connections, or on several (some here, some elsewhere): the gate names those connections and says to switch to the connection where the Bots run and start a group there, or to start a new group chat with Bots from this connection. Desktop does not offer one group across machines.
- Bots here that cannot form a gateway group as they are (two to six Bots, distinct profiles and handles, `@all` and `@everyone` reserved): the gate gives the reason and says to start a new group chat and choose its Bots.
- A failed lookup offers **Retry**.

Under the gate, a classic room's earlier messages stay readable, read only and inert, like gateway room history below: no `MEDIA:` path, Markdown image, file link or directive card resolves, rich fences show their source, and only an explicit web link to a public host opens, on a click. They stay on this Desktop.

## The room workspace

The gateway owns the log and the work. Desktop polls `groups.state` and `groups.log` every two seconds while the room is visible. It reads the log after the last event it showed, and from the start again when the room's `authority_epoch` changes.

- **Status:** the header lists each member as working or queued (`driver_status.member_activity`) and, beside that, what the room waits on: a blocked room (a stopped task that is still settling is not a block), approvals, and other pending actions. A gateway whose driver is down sends no driver status; the room then says its group driver is unavailable. A failed member never hides the others' live work.
- **Send** uses the native prepared-submission journal: one unresolved intent per room, shared by every Desktop window and written with compare-and-set. The entry counts the requests that may have posted its intent: one more is written before each request leaves, one less when the gateway proves that request posted nothing. Both gateway surfaces give that proof by marking a refusal `admitted: false` (on `4001`, `4111`, `4123` or `5112`), and only for a refusal raised before the user event commits or a Send no driver or worker could take; a code or reason alone proves nothing. At zero the words come back for editing, and the journal keeps them until a Send replaces them, so a room closed meanwhile shows them again when it reopens. Any other outcome (an unmarked refusal, a timeout, an unconfirmed reply) keeps the intent for **Retry**, which resends the same `event_id`; the gateway recognizes it, so it is never posted twice. A Send is delivered only by a receipt whose `client_event_id` is this intent's (and `accepted: true` when present); a failed journal cleanup after that receipt is retried before this window's next Send. When another window holds the room's intent, Send sends that one first and puts this window's words back afterwards; an intent another window finished with is neither resent nor offered as a new message. If the journal cannot be read, Send stays locked and **Try loading again** reads it again without writing.
- **Stop** (`groups.stop`) has its own pending state, so it works while a Send is in flight. It keeps one `cancel_id` until the gateway confirms how many replies it stopped. Stop also covers a Send in flight: one not yet sent is held back with its words kept; one on the wire is fenced again under a fresh `cancel_id` once it settles, unless the gateway proved it posted nothing.
- **Retry, Discard and approvals** come only from `driver_status.pending_actions` and send the exact member, task, generation and request identity. Each row names its Bot. An approval shows its description and its command; only the choices the gateway offered appear, and **Allow once** needs this exact request with a real command, or with the description a synthetic tool label stands for (a plugin approval rule sends `<tool> (plugin approval rule)`, as in the chat approval card). Discard asks first: side effects are not undone.
- **Attachments** upload with `groups.attachment.upload` and download with `groups.attachment.download`.
- **Rename** (`groups.rename`) keeps one `event_id` per intended name across retries. **End group chat** (`groups.disband`) asks first, keeps one `cancel_id`, and removes the room from Desktop and closes its tab only when the gateway returns its tombstone.

History shows messages and notices for failed, cancelled and deferred turns (a deferred turn names its reason, such as `member_unavailable`), a stop, the work limit (`room.activity` with status `bounded`), the room's end and lost ownership; every other event (`turn.started`, `turn.settled`, other `room.activity`, …) stays out. Your own messages read as **You**. Room text may come from another machine: its `MEDIA:` paths, Markdown images, file links and directive cards stay inert, rich code fences (`listing`, `mermaid`, `svg`) show their source, and an explicit web link to a public host (not loopback, link-local or a private network) opens only on a click.

Errors stay visible, and no failed gateway-room action falls back to Desktop-run execution. Membership editing is not offered.

## Contract tests

`canonical-group-contract-test-utils.ts` wraps each canonical group test's request double and, after each test, checks every `groups.*` request it captured against the generated gateway contract (`apps/shared/src/gateway-contract.openrpc.json`, the gateway's own `x-canonical-methods` entry before the shared one): a method the gateway does not list, an unknown parameter or a missing required one fails the test. The `groups.capabilities` fixtures for both surfaces are data, checked against the same contract when they load. `canonical-groups-contract.test.ts` covers the check itself.
