# Gateway-owned groups in Desktop

Bot Mode lists gateway rooms separately from legacy renderer rooms. Refresh gateway groups reloads the selected connection/profile's canonical room list. Opening a room captures that exact authority; changing the foreground profile does not retarget its controls.

With `groups.capabilities.driver` enabled, the existing creation dialog creates a canonical group. Desktop seats only same-authority local-profile members; Desktop connection descriptors are not peer grants. The gateway itself can seat a text-only bot from another gateway; Desktop does not offer that yet. These owner/lender rules apply to the canonical gateway (`hermes gateway run`), including when `hermes serve` forwards Desktop's group calls to it. The home must report `driver: true`, `persistent_process: true` and `groups.peer.register` in `groups.capabilities.methods`; it does not need its own `room_link.enabled`. The member gateway must report `room_link.enabled: true` with its catalog/endpoint and list `groups.peer.invite` in `methods` (see [the Bot Mode guide](../../../website/docs/user-guide/bot-mode.md#bots-from-another-gateway-in-a-gateway-owned-group-chat)). Standalone `hermes serve` answering for its own group chats derives `persistent_process` from its lending catalog and skips API-server and endpoint checks for `room_link`; clients should not use it as a home for gateway-owned group chats. Existing legacy rooms offer **Start gateway group** instead of renderer-owned execution. This starts a new room and deliberately does not replay legacy history.

The gateway owns the log and work. Desktop reads `groups.state` and `groups.log`, sends through `groups.send`, and stops through `groups.stop`. Pending actions come only from `driver_status.pending_actions`. The gateway now exposes approvals from bots on another gateway and accepts `once` or `deny`; the home answers the exact prompt using the lender's run generation. Discard requires explicit confirmation that prior side effects are not undone; Retry and approvals retain the exact member/task/generation/request identity. Errors remain visible and no failed canonical mutation falls back to hidden-session submission.

This initial canonical workspace is text-only. Rename, disband, membership editing and attachments are not offered here. Room discovery is durable on the gateway rather than replicated through Desktop ui_meta. Ambiguous send retries preserve their event identity while the workspace remains mounted; native crash-safe group-send journaling is not implemented.
