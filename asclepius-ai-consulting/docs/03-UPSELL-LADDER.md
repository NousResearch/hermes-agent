# 03 — Upsell Ladder

## Rule

Do not upsell during the diagnostic excavation. Wait until the Prescription delivery call, when the client sees the written diagnosis and trusts the logic.

## Diagnostic → Build

Trigger: the prescription contains at least one high-confidence workflow with measurable weekly savings or revenue recovery.

Talk track: “You can absolutely implement this internally. If you want speed and fewer false starts, I can take the first prescription line item and build it as a fixed-fee project. My recommendation is to start with the quickest operational win, prove it works, then decide whether to keep going.”

Email: “Based on the Prescription, I recommend we implement [workflow] first because it has the clearest payoff and lowest adoption risk. Fixed fee: $[amount]. Timeline: [timeline]. Deliverables: [bullets]. Want me to send the Build agreement?”

## Build → Retainer

Trigger: implementation is live, staff are using it, and the client asks “what else can we do?” or needs ongoing tuning.

Talk track: “The first workflow is installed. The way this keeps producing value is monthly tuning: new edge cases, staff onboarding, tool changes, and a quarterly re-diagnosis. I can handle that as your AI ops retainer instead of selling you a new project every time.”

## Retainer → Office Hours fallback

Trigger: client likes the relationship but is too small or too inconsistent for a monthly retainer.

Talk track: “No problem if a retainer is premature. We can keep this simple with paid office hours at $[rate]/hour, booked in blocks when you need help.”

## Offer discipline

- One primary next step per conversation.
- Never discount without removing scope or receiving something valuable, such as a testimonial.
- Frame Build as implementation of the written plan, not generic AI help.
