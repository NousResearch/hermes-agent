# Hermes/Ogma factory retrospective — 2026-W43

- Kanban card: `t_756b2843`
- Scope: Hermes Agent dispatch, QA, verification, and delivery loop.
- Evidence window: 2026-10-12 23:38–2026-10-19 23:38 UTC (seven days, read-only Kanban snapshot).
- No production, secret, publication, payment, or live schedule mutation was performed by this retrospective.

## Executive result

The factory delivered a high volume of completed work, but reliability problems concentrated in three edges: repeated capability-blocked QA, wrong-repository worktrees from decomposition, and worker lifecycle churn. Existing fixes measurably reduced duplicate QA and dependency-wait noise; the remaining improvements should be deterministic preflight/health checks rather than more prompt text.

## Verified observations

### 1. Lifecycle churn remained material

- Kanban events in the window: `41 reclaimed`, `37 crashed`, `12 gave_up`, `18 block_loop_detected`, `3 spawn_failed`, `2 completion_blocked_verification`, and `1 protocol_violation`.
- Run outcomes: `43 reclaimed`, `38 crashed`, `1 gave_up`, `3 spawn_failed`, `5 review_requested`, `1,252 done/completed`, and `1 failed` run. These are database event/run counts, not unique incidents or worker-hours.
- Concrete examples: `t_59c5b47f` and `t_5ce04e0d` were reclaimed under the same stale worker lock; `t_17b46388` recorded a protocol violation despite exit code 0; `t_02827165` first hit `completion_blocked_verification` for a missing deployed smoke-test artifact and later completed with the artifact.
- Root cause classification: the records prove lifecycle churn and one missing-artifact contract. They do not prove one common technical cause for every crash/reclaim.

### 2. Capability and environment gaps repeatedly re-entered the QA loop

- `t_904819c4` was rerun repeatedly on exact integrated head `5982cf9...`: static checks passed, Chromium/mobile-Chrome passed `30/30`, but `45/75` matrix cases could not launch because Firefox and WebKit executables were absent.
- `t_cb57609b` recorded a real exact command failure: `npm run test:e2e -- tests/a11y.spec.ts tests/keyboard-a11y.spec.ts` exited 1 with `14 passed`, `61 failed`; missing paths were `/home/hermes/.cache/ms-playwright/firefox-1532/firefox/firefox` and `/home/hermes/.cache/ms-playwright/webkit-2311/pw_run.sh`. Chromium produced real axe output; no full cross-browser PASS was claimed.
- The repeated block-loop evidence is a capability/preflight problem, not evidence that the implementation was repeatedly broken. Existing policy correctly prevented fabricated axe counts.

### 3. Wrong project/workspace routing created avoidable blocked work

- `t_998e5b15` and related `t_6378eaa3`/`t_17186acc` records show children launched in `/home/hermes/hermes-ogma/.worktrees/` without the Next.js application, while the actual code was in the `ogma-website` repository. Workers correctly refused speculative edits and left hotspot evidence.
- The deployment-side records in `10_Claude` report a project-inheritance patch (`c977710`) and a subsequent repair (`94da3c9`) that fixed new and existing decomposed cards. This is evidence that the failure mode was actionable; it is not proof that every historical card was repaired automatically.
- Root cause: project/workspace identity was not enforced at the decomposition/dispatch boundary strongly enough. Prompt guidance alone did not prevent recurrence.

### 4. Existing factory changes worked when they were deterministic

- The 2026-10-19 blocked-reduction log records dependency-wait blocks falling to `0`, QA cards/day dropping from `240` (10-15) to `5` (10-19), reviewer cards from `85` (10-12) to `3`, and `26` unblocker actions with `16 done`, `7 todo`, `2 archived`, and `1 re-blocked`. These are reported operational snapshots from the shared log, not independently recomputed here.
- The same log records `never_list_executed=0`, `reopen=0` during the measured unblocker checks, and a later `pr-done` rule archiving stale cards for already-merged PRs. The records support reduced duplicate work; they do not establish causal attribution for all throughput changes.
- `t_98d5b40f` added structured value-measurement fields/events and passed `57` scoped tests, but full `scripts/run_tests.sh` and `npm run check` timed out in that worker environment. This is a verification-capacity limitation, not a scoped-test failure.

## What worked

- Exact-head QA evidence and explicit “do not claim PASS” behavior prevented false browser certification (`t_904819c4`, `t_cb57609b`).
- Unblocker rules and capability probing reduced stale Chromium blocks and duplicate QA; the shared log records `dependency-wait blocks 0` after the rollout.
- Workers recorded hotspots instead of editing a neighboring repository, especially `t_998e5b15`. That protected repository boundaries even when dispatch metadata was wrong.
- Completion verification caught a missing deployment artifact in `t_02827165`; the second attempt supplied and read back the smoke-test evidence.

## Root causes versus hypotheses

Verified root causes:

1. Some decomposed cards lacked reliable project/workspace identity, demonstrated by the wrong-repository worktrees in `t_998e5b15` and siblings.
2. The configured QA matrix was larger than the browser capability available to workers, demonstrated by missing Firefox/WebKit executables and repeated exact-command blocks.
3. The completion contract could reject a card after otherwise successful work when the required artifact was absent, demonstrated by `t_02827165`.

Hypotheses requiring follow-up measurement:

- A bounded per-card run-health signal will reduce repeated crash/reclaim churn; the current data shows the volume but not the avoidable fraction.
- Browser preflight will reduce QA block-loop events; it must be measured against a comparable window.
- Project identity enforcement will reduce wrong-worktree blocks; historical repair results cannot serve as a prospective control.

## Three concrete improvements

### 1. Browser capability preflight before QA dispatch

- Owner: `[OPS]` / QA runner maintainers.
- Follow-up card: `t_0c6a2956`.
- Change: enumerate every configured Playwright project and report missing browser executables/system libraries before running the matrix. Preserve real partial results, but never label the matrix PASS.
- Acceptance: focused preflight fixture tests; a sample result naming each missing executable; `git diff --check`; rerun the exact E2E command only when the preflight is green.

### 2. Enforce project/workspace inheritance at decomposition

- Owner: `[ENG]` Kanban/decomposer maintainers.
- Follow-up card: `t_90568653`.
- Change: require project identity on every child when an ancestor has one, and reject or repair a child before creating a worktree from the wrong repository. Cover multi-level decomposition and workspace-repository identity in tests.
- Acceptance: focused decomposer/project-repair tests; a fixture proving child `project_id` and repository match the ancestor; `git diff --check`.

### 3. Add a bounded dispatcher run-health signal

- Owner: `[OPS]` dispatcher maintainers.
- Follow-up card: `t_d790749f`.
- Change: group repeated `reclaimed`, `crashed`, `gave_up`, and protocol events by task in a read-only health check. Emit one structured escalation signal after a configured rolling-window threshold, distinguishing stale lock from crash, capability block, and protocol violation.
- Acceptance: deterministic fixture tests, a read-only query sample, no task mutation, and `git diff --check`.
