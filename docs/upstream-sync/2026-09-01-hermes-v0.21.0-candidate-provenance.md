## Why a direct merge was rejected

An isolated Git-only merge probe between the release tree and the fork history produced 165 conflicted files. The endpoint comparison also showed hundreds of changed files because squash merges and old synchronization snapshots make commit-count and ahead/behind values poor proxies for retained behavior.

The accepted strategy is therefore release-first selective reconciliation:

1. Start from the immutable v0.21.0 release commit.
2. Preserve release implementations whenever they already satisfy or supersede a fork fix.
3. Reapply only the missing behavioral invariant and its regression coverage.
4. Treat old synchronization snapshots and merge-only commits as provenance, not patches to replay blindly.
5. Stop at every conflict and resolve against the current release design rather than choosing an entire historical side.

## Builder and probe safety

Reconciliation was performed through isolated GitHub runner checkouts and temporary worktrees. Candidate writes used ordinary fast-forward pushes only and were bound to the previously verified exact remote head. A concurrent writer or unexpected head movement causes the writer gate to stop instead of overwriting the branch.

## Current-head engineering review

The release-relative product tree was reviewed after the PR #19 and PR #20 reconciliations. The reviewed scope contains 49 files relative to `v2026.8.31`, including 41 Python files and six GitHub workflows.

The review found one blocking lifecycle regression: `groups.disband` had lost the durable admission barrier that prevents a second process from accepting work between Stop and the room tombstone. The regression was reproduced before the fix by three independent failures: a racing send was accepted, concurrent disband wrote two Stop events, and an existing barrier for another reason was ignored. The final implementation restores the authority-scoped `room-disband` barrier, preserves peer-route revocation, and rejects user events before they are written once admissions are closed.

Verification after the fix:

- focused disband lifecycle: 7 passed;
- concurrent disband regression: 5 consecutive isolated passes;
- Groups, HostedRoomService, driver-admission, and storage integration: 151 passed;
- Knowledge Sync and duplicate-test guard: 238 passed;
- temporary-profile Knowledge CLI smoke: dry-run, apply, and verify returned success; `USER.md` remained byte-identical;
- behavioral invariant checklist: 21 of 21 passed;
- changed-Python AST/compile checks, Ruff, and `git diff --check`: passed;
- changed workflow review: all external actions are pinned to immutable SHAs; no `pull_request_target`, write permission, or private runner label was introduced;
- production-risk review: migration SQL is constructed from internal allowlists, rollback deletion is CAS-guarded and limited to a file created by the failed transaction, subprocess delivery does not use a shell, and owner-liveness uncertainty fails closed.

No unresolved P0-P3 engineering finding remained after the disband fix. CI and Nix must still complete on the final documentation-inclusive SHA before the review label or merge gate can pass.
