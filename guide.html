۱ معرفی برنامه

Hermes Desktop رابط گرافیکی دسکتاپ برای Hermes Agent — عامل هوش مصنوعی خودبهبوددهنده ساخت Nous Research — است. این عامل از تجربه مهارت می‌سازد، حافظه ماندگار دارد، گفتگوهای گذشته را جستجو می‌کند و با هر نشست شناخت عمیق‌تری از شما پیدا می‌کند.

🔁 حلقه یادگیری بسته

پس از وظایف پیچیده مهارت جدید می‌سازد و مهارت‌های موجود را در طول استفاده بهبود می‌دهد.

🧠 حافظه ماندگار

خاطرات و نمای کاربر بین نشست‌ها حفظ می‌شود؛ گفتگوهای گذشته با جستجوی متنی قابل بازیابی‌اند.

💬 همه‌جا در دسترس

ترمینال، داشبورد، دسکتاپ، Telegram، Discord، Slack، WhatsApp و Signal — همه از یک دروازه واحد.

⏰ اتوماسیون زمان‌بندی‌شده

گزارش روزانه، پشتیبان شبانه یا ممیزی هفتگی — همه به زبان طبیعی و بدون حضور شما.

🛠 هر مدلی که بخواهید

Nous Portal، OpenRouter، OpenAI، Anthropic، نقطه پایانی محلی (Ollama و vLLM) و ده‌ها ارائه‌دهنده دیگر.

🌍 چندزبانه

این برنامه از فارسی پشتیبانی می‌کند و کل رابط به‌صورت خودکار راست‌به‌چپ (RTL) می‌شود.

۲ راه‌اندازی کامل روی سیستم

این بخش از صفر تا اجرای برنامه را پوشش می‌دهد: پیش‌نیازها، نصب نسخه آماده یا اجرا از سورس، و اولین اجرا.

پیش‌نیازها

مؤلفهحداقل نسخهتوضیح
Node.js22.22 / 24.11 / 26+برای اجرای رابط دسکتاپ (نسخه LTS توصیه می‌شود).
Python3.11 – 3.13برای باک‌اند عامل (Hermes Agent).
سیستم‌عامل—ویندوز ۱۰/۱۱ (نیتیو یا WSL2)، macOS یا Linux.
اتصال اینترنت—برای دریافت مدل‌ها و به‌روزرسانی‌ها؛ اجرای روزانه بدون اینترنت هم ممکن است (مدل محلی).
نصب‌کننده رسمی همه پیش‌نیازها را خودش نصب می‌کند (Python، Node.js، ripgrep، ffmpeg و Git Bash پرتابل در ویندوز) — نیازی به نصب دستی نیست. مسیر دستی فقط برای توسعه‌دهندگانی است که از سورس اجرا می‌کنند.

راه اول: نصب نسخه آماده (توصیه‌شده برای کاربر عادی)

  1. به صفحه دانلود بروید: hermes-agent.nousresearch.com و نصب‌کننده Hermes Desktop را برای سیستم‌عامل خود بگیرید.
  2. نصب‌کننده را اجرا کنید. در ویندوز نیازی به دسترسی مدیر (Admin) نیست؛ همه‌چیز زیر %LOCALAPPDATA%\hermes نصب می‌شود.
  3. Hermes را از منوی استارت (ویندوز) یا پوشه Applications (مک) اجرا کنید.

راه دوم: اجرا از سورس (برای توسعه‌دهندگان)

  1. Node.js و Python را طبق جدول بالا نصب کنید (در ویندوز، Git Bash هم لازم است).
  2. وابستگی‌های ریشه را نصب کنید: npm install
  3. باک‌اند عامل را آماده کنید: python run_agent.py --help باید بدون خطا اجرا شود.
  4. برنامه دسکتاپ را اجرا کنید: cd apps/desktop && npm install && npm run dev — این فرمان هم سرور رابط (Vite) و هم پوسته Electron را با هم بالا می‌آورد.
  5. پنجره‌ای با عنوان «Hermes» باز می‌شود؛ همان برنامه اصلی است. نشانی 127.0.0.1:5174 را در مرورگر باز نکنید — فقط رابط است و بدون پوسته دسکتاپ بالا نمی‌آید (بخش «تفاوت مرورگر و برنامه دسکتاپ» را ببینید).

اولین اجرا

  • اجرای اول چند دقیقه طول می‌کشد: برنامه باک‌اند را از صفر راه می‌اندازد (نصب وابستگی‌ها و ساخت ایندکس‌ها). صفحه پیشرفت «راه‌اندازی Hermes Desktop…» را باز بگذارید.
  • پیکربندی برنامه در ویندوز زیر %APPDATA%\Hermes و در لینوکس/مک زیر ~/.hermes ذخیره می‌شود. حذف برنامه این پوشه را پاک نمی‌کند.
  • برای کار با مدل‌ها، از صفحه نخست یا بخش تنظیمات ← «ارائه‌دهنده‌ها» کلید API خود را وارد کنید (Nous Portal، OpenRouter، OpenAI، Anthropic، Ollama محلی و ده‌ها ارائه‌دهنده دیگر). ساده‌ترین مسیر: راه‌اندازی یک‌مرحله‌ای Nous Portal — پایین‌تر در همین بخش.
  • زبان فارسی از مسیر تنظیمات ← «زبان» فعال می‌شود؛ کل رابط خودکار راست‌به‌چپ می‌شود.

راهنمای گام‌به‌گام اولین اجرا

این تصاویر از خودِ برنامه (نسخه فارسی‌شده) گرفته شده‌اند و دقیقاً همان چیزی را نشان می‌دهند که در اولین اجرا می‌بینید:

راه‌اندازی یک‌مرحله‌ای Nous Portal (ورود، مدل و دروازه ابزارها)

پیشنهاد ما بعد از نصب: به‌جای واردکردن کلید API هر ارائه‌دهنده به‌صورت جداگانه، یک‌بار با Nous Portal وارد شوید. یک اشتراک، بیش از ۳۰۰ مدل و همزمان دروازه ابزارها (Tool Gateway): جستجوی وب، تولید تصویر، تبدیل متن به گفتار (TTS) و خودکارسازی مرورگر — همه از طریق همان اشتراک.

hermes setup --portal
  1. ورود: اگر هنوز وارد نشده باشید، برنامه یک کد دستگاه (Device Code) نشان می‌دهد و مرورگر را روی portal.nousresearch.com باز می‌کند. کد را در مرورگر تأیید کنید تا ورود کامل شود. همین فرمان معادل hermes portal است.
  2. انتخاب مدل: فهرست مدل‌های پیشنهادی نمایش داده می‌شود و مدل دلخواه را انتخاب می‌کنید؛ Nous به‌طور خودکار به‌عنوان ارائه‌دهندهٔ اصلی ذخیره می‌شود.
  3. دروازه ابزارها: در پایان، اگر اشتراک شما شامل Tool Gateway باشد، پیشنهاد فعال‌سازی آن نمایش داده می‌شود؛ با تأیید، ابزارهای مدیریت‌شده (وب، تصویر، گفتار، مرورگر) به حساب شما وصل می‌شوند.
  4. پایان: پیام «Portal setup complete» را می‌بینید؛ از این‌جا به بعد اجرای hermes یا بازکردن برنامه دسکتاپ کافی است.
# بررسی سلامت اتصال و مسیریابی ابزارها پس از راه‌اندازی
hermes portal info
hermes portal tools
  • hermes portal info: خلاصهٔ وضعیت ورود و مسیر سرویس‌دهی هر ابزار — «مدیریت‌شده» از طریق Portal یا موتور محلی (مثل Edge TTS و مرورگر محلی Playwright که بدون هیچ کلیدی کار می‌کنند). این فرمان اصلیِ بازرسی است (hermes portal status هم به‌عنوان نام قدیمی همین کار را می‌کند).
  • hermes portal open صفحهٔ اشتراک را در مرورگر باز می‌کند؛ روشن/خاموش‌کردن تک‌تک ابزارها و انتخاب ارائه‌دهندهٔ هر کدام با hermes setup tools است — مثلاً می‌توانید وب و تولید تصویر را به Portal وصل کنید ولی TTS را روی حالت محلی رایگان نگه دارید.
پوشش ابزارهای مدیریت‌شده به اشتراک Portal شما بستگی دارد؛ اگر دسته‌ای در طرح شما نباشد، جادوگر به‌جای خطا، راهنمای ارتقا در صفحهٔ صورت‌حساب Portal نشان می‌دهد. اگر قبلاً وارد شده باشید، این فرمان فقط انتخاب مدل و فعال‌سازی دروازه را می‌پرسد و ورود را تکرار نمی‌کند.
اگر در طول راه‌اندازی به خطا خوردید، بخش «عیب‌یابی» در انتهای همین راهنما و بخش «اجرای برنامه در حالت توسعه» را ببینید — رایج‌ترین خطاها و راه‌حل آن‌ها آنجا فهرست شده است.

۱۷ راه‌اندازی سریع در ۶ گام

برای کسانی که فقط می‌خواهند استک محلی بالا بیاید: هر گام یک فرمان است. در صورت بروز خطا، جدول عیب‌یابی (بخش ۱۹) را ببینید.

  1. نصب وابستگی‌ها — از ریشهٔ مخزن: npm install (تک‌قفل‌نامه: هرگز از زیرپوشه‌ها مثل ui-tui نصب نکنید) و برای بک‌اند pip install -e ".[web,dev]". آزمون سلامت: hermes doctor.
  2. راه‌اندازی یک‌مرحله‌ای — hermes setup --portal: وارد حساب Nous Portal شوید، مدل را انتخاب کنید و دروازه ابزارها (وب، تصویر، TTS، مرورگر) همان‌جا وصل می‌شود. برای انتخاب تک‌تک ابزارها: hermes setup tools.
  3. اجرای دروازه — hermes gateway run. بازرسی: hermes gateway status باید «در حال اجرا» را نشان دهد.
  4. اجرای داشبورد — hermes dashboard --port 9119؛ پس از چند ده ثانیه http://127.0.0.1:9119/ باز می‌شود (پرچم --no-open هم هست).
  5. انتخاب زبان فارسی — دکمهٔ «تغییر زبان» در پایین نوار کناری داشبورد؛ در ترمینال هم hermes config set display.language fa. فونت Vazirmatn و چیدمان راست‌به‌چپ خودکار فعال می‌شود.
  6. بررسی نهایی — hermes doctor باید بدون هشدار وابستگی تمام شود و نوار وضعیت داشبورد «وضعیت دروازه: در حال اجرا» را نشان دهد. برای شروع خودکار پس از هر ری‌استارت ویندوز، یک‌بار start-hermes-stack.cmd را اجرا کنید.

۱۸ وابستگی‌های اختیاری برای اجرای تست‌ها (توسعه‌دهندگان)

بخش بزرگی از تست‌ها به ارائه‌دهنده‌های اختیاری وابسته‌اند که پیش‌فرض نصب نمی‌شوند؛ بدون آن‌ها pytest به‌جای پاس، skip می‌زند یا خطای جمع‌آوری می‌دهد. همه در pyproject.toml تحت [project.optional-dependencies] پین شده‌اند.

بستهٔ اضافیدستور نصبچه چیزی را باز می‌کند
devpip install -e ".[dev]"خود pytest و pytest-asyncio، mcp، httpx، ruff و ty — پیش‌نیاز هر اجرای تستی
messagingpip install -e ".[messaging]"تست‌های تلگرام، Discord، Slack و کانال‌های پیام‌رسانی (tests/gateway، tests/tools)
anthropicpip install -e ".[anthropic]"تست‌های آداپتور Anthropic در tests/agent (سایر ارائه‌دهنده‌ها از طریق کلید API قلابی stub می‌شوند)
webpip install -e ".[web]"سرور داشبورد/دروازه که تست‌های یکپارچگی به آن وصل می‌شوند
افزونه‌های pytestpip install pytest-timeout pytest-xdistاجرای قطعه‌قطعهٔ suite دروازه روی ویندوز با تایم‌اوت در هر تست (هر دو فقط برای توسعه؛ پین نشده‌اند)
روی ویندوز suite کامل دروازه را قطعه‌قطعه با تایم‌اوت اجرا کنید (دستور در سند run مخزن آمده) — اجرای یک‌جا زیر بار ماشین به‌راحتی گیر می‌کند. اگر پکیجی نبود، pytest خودش نام ماژول گم‌شده را می‌گوید؛ همان extra جدول بالا را نصب کنید و دوباره جمع‌آوری کنید.

۳ چیدمان کلی پنجره

پنجره برنامه از چند ناحیه تشکیل شده که هر کدام وظیفه مشخصی دارند:

ناحیهشرح
نوار عنوانجستجوی سراسری نشست‌ها، نماها و اقدامات؛ دکمه‌های نمایش/پنهان نوار کناری چپ و راست، باز کردن تنظیمات، گراف حافظه و ورود به حالت HUD. در حالت RTL جای دکمه‌ها خودکار برعکس می‌شود.
نوار کناری چپ (نشست‌ها)فهرست گفتگوهای اخیر با جستجو، سنجاق، بایگانی و تراکم نمایش (فشرده / راحت / مفصل). با Ctrl/⌘ کلیک روی یک گفتگو آن را بایگانی کنید.
ناحیه کار (Workspace)قلب برنامه: گفتگوی فعال، مرورگر فایل، مرورگر داخلی، ترمینال‌ها و زبانه‌ها اینجا باز می‌شوند.
نوار کناری راستمرورگر فایل درخت‌واره‌ای؛ می‌توانید آن را پنهان کنید یا با view.flipPanes طرفش را عوض کنید.
نوشتار (Composer)جعبه پیام پایین صفحه. شناور می‌شود، تاریخچه دارد و با @ به فایل‌ها و آدرس‌ها ارجاع می‌دهید.
نوار وضعیتوضعیت دروازه، مدل فعال، مصرف توکن و پیام‌های کوتاه برنامه.
حالت HUDچیدمان شناور و فشرده روی صفحه — با view.toggleHud روشن/خاموش می‌شود و اندازه و جای آن قابل بازنشانی است.
همه نوارها را می‌توانید نمایش یا پنهان کنید؛ اگر چیزی گم شد، کلید میان‌بر یا منوی نوار عنوان را امتحان کنید.

۴ گفتگو و نوشتار

ارسال پیام و هدایت عامل

در نوشتار (Composer) تایپ کنید و با Enter بفرستید؛ با Shift+Enter خط جدید بگذارید. وقتی عامل در حال کار است می‌توانید:

  • هدایت نوبت (Steer): در میانه اجرا پیام بفرستید تا مسیر کار عوض شود.
  • صف کردن (Queue): چند پیام در صف بگذارید تا نوبت‌به‌نوبت اجرا شوند.
  • ارجاع (@): به فایل‌ها، پوشه‌ها و URL ها اشاره کنید تا عامل همان را بخواند.
  • پالت اسلش (/): دستورهای عامل مثل /model یا /usage را همین‌جا صدا بزنید.

حالت صوتی

با voice.recordKey (میان‌بر قابل تنظیم) ضبط صدا را شروع کنید؛ گفتار به متن تبدیل و پاسخ عامل در صورت فعال‌بودن «خواندن خودکار پاسخ‌ها» با TTS خوانده می‌شود. ارائه‌دهنده‌های STT/TTS در بخش صوت تنظیمات پیکربندی می‌شوند.

نمایش فعالیت ابزار

در تنظیمات ← ظاهر می‌توانید انتخاب کنید فراخوانی ابزارها چطور نمایش داده شوند:

  • محصول: فعالیت ابزار به زبان انسان با خلاصه‌های موجز.
  • فنی: شامل آرگومان‌ها و نتایج خام ابزار و جزئیات سطح پایین.

واکنش‌ها و ظرافت‌ها

به پیام‌ها واکنش ایموجی بدهید (تپ‌بک‌های سبک iMessage)، با «قلب‌های Vibe» از عامل تشکر کنید، و پیش‌نمایش‌های غنی لینک‌ها (YouTube و X) را با یکی از حالت‌های «پرسیدن / همیشه / خاموش» فعال کنید.

۵ نشست‌ها و نوار کناری

هر گفتگو یک «نشست» است. نشست‌ها در نوار کناری با تاریخ، پوشه پروژه و عنوان خودشان دیده می‌شوند.

  • نشست جدید: Ctrl/⌘+N — یا زبانه یا پنجره جدید باز کنید.
  • سنجاق: نشست‌های سنجاق‌شده بالای فهرست می‌مانند و هرگز بایگانی خودکار نمی‌شوند.
  • بایگانی: با Ctrl/⌘ کلیک؛ گفتگوهای بایگانی‌شده از نوار کناری پنهان می‌شوند اما پیام‌هایشان حفظ می‌شود (بخش «گفتگوهای بایگانی‌شده» در تنظیمات).
  • بایگانی خودکار: گفتگوهایی که مدتی به آن‌ها سر نزده‌اید پس از N روز بی‌فعالیتی خودکار بایگانی می‌شوند.
  • سوئیچ سریع: کلیدهای session.slot.1…9 به ۹ نشست اخیر می‌پرند؛ session.next و session.prev میان نشست‌ها می‌چرخند.
عنوان نشست‌ها با مدل کمکی «تولید عنوان» خودکار ساخته می‌شود — در تنظیمات مدل می‌توانید برای هر وظیفه کمکی مدل جداگانه بدهید.

۶ ساخته‌ها Artifacts

هر فایلی که عامل در طول کار می‌سازد — کد، سند، تصویر، گزارش — در صفحه ساخته‌ها جمع می‌شود تا بدون گشتن در گفتگو پیدا و بازشود.

  • فایل‌ها را پیش‌نمایش بگیرید، دانلود یا در مدیر فایل سیستم‌عامل نمایش دهید.
  • منوی فایل شامل کپی مسیر، تغییر نام و حذف (انتقال به سطل بازیافت) است.
  • با view.showFiles مرورگر فایل و با view.showBrowser مرورگر داخلی باز می‌شود.

۷ مهارت‌ها Skills

مهارت‌ها حافظه رویه‌ای عامل‌اند: دستورالعمل‌های قابل استفاده مجدد که Hermes آن‌ها را می‌سازد، ذخیره و در طول استفاده بهبود می‌دهد.

  • عامل پس از انجام وظایف پیچیده خودش مهارت جدید می‌سازد.
  • مهارت‌ها با استاندارد باز agentskills.io سازگارند و در ~/.hermes/skills/ زندگی می‌کنند.
  • صفحه مهارت‌ها در دسکتاپ، مدیریت و مرور (Skills Hub) را یک‌جا می‌دهد؛ مدل جستجوی مهارت در تنظیمات مدل قابل تعویض است.
  • مدل کمکی «امان» (Curator) استفاده از مهارت‌ها را بازبینی می‌کند.

۸ پیام‌رسانی Messaging

با دروازه (Gateway)، Hermes از Telegram، Discord، Slack، WhatsApp، Signal و ایمیل در دسترس است — همان عامل، همان حافظه، همان مهارت‌ها.

  • در ترمینال: hermes gateway setup و سپس hermes gateway start.
  • صفحه پیام‌رسانی در دسکتاپ وضعیت پلتفرم‌ها و پیوستن/جدا شدن کانال‌ها را نشان می‌دهد.
  • گفتگو بین پلتفرم‌ها ادامه‌دار است: از ترمینال شروع کنید، در Telegram ادامه دهید.
  • دستورهای اسلش در پیام‌رسان‌ها هم از کاتالوگ زبان رابط پیروی می‌کنند (فارسی با display.language: fa).
دروازه به کلیدهای API پلتفرم‌ها نیاز دارد؛ آن‌ها را در تنظیمات ← کلیدهای API وارد کنید.

۹ وب‌هوک‌ها Webhooks

وب‌هوک‌ها اجازه می‌دهند سرویس‌های بیرونی (CI، فرم‌ها، مانیتورینگ) با یک درخواست HTTP رویدادی را به عامل بدهند و پاسخ بگیرند.

  • هر وب‌هوک یک آدرس اختصاصی و اختیاراً یک توکن امنیتی دارد.
  • بار درخواست به‌صورت پرامپت به عامل می‌رسد و خروجی برگردانده می‌شود.
  • برای اتصال از اینترنت، دروازه را پشت پروکسی معکوس با TLS قرار دهید.

۱۰ مرکز فرمان

یک صفحه یک‌نگاهی برای کنترل کل سیستم: وضعیت دروازه و نشست‌ها، کارهای در جریان، وظایف پس‌زمینه و میان‌برهای سریع به همه بخش‌ها.

اگر فقط یک جا برای «چه خبر؟» می‌خواهید، همین است. از پالت فرمان (nav.commandPalette) هم می‌توانید مستقیم به هر بخش بپرید.

۱۱ وظایف زمان‌بندی‌شده Cron

وظایف تکرارشونده را به زبان طبیعی تعریف کنید؛ Hermes خودش برنامه زمانی می‌سازد و نتیجه را به پلتفرم دلخواه تحویل می‌دهد.

# نمونه از ترمینال
hermes cron add --schedule "0 9 * * *" --prompt "خلاصه اخبار دیروز را بده"
hermes cron list
  • در دسکتاپ، تب وظایف زمان‌بندی‌شده همین کار را بدون ترمینال انجام می‌دهد: تعریف، ویرایش و حذف وظیفه با چند کلیک.
  • تحویل خروجی به: محلی، Telegram، Discord، Slack یا ایمیل.
  • وظایف cron همراه با پروفایل خودشان ذخیره می‌شوند.

۱۲ پروفایل‌ها

پروفایل‌ها چند «هویت» جدا برای عامل‌اند: هر پروفایل مدل، کلیدها، حافظه، پوسته و حتی دروازه مستقل خودش را دارد.

  • نمونه: پروفایل coder با مدل کدنویسی و پوشه پروژه متفاوت؛ پروفایل writer با مدل متنی.
  • با کلیدهای profile.switch.1…18 بین پروفایل‌ها می‌پرید؛ profile.default به پیش‌فرض برمی‌گردد.
  • بسیاری از تنظیمات یک نشان «اعمال به» دارند که می‌گوید تغییرات روی کدام پروفایل ذخیره می‌شود.
  • پوسته هر پروفایل جداگانه ذخیره می‌شود («برای پروفایل X ذخیره شد»).

۱۳ عامل‌ها

صفحه عامل‌ها نمای کلی از عامل‌های در دسترس (محلی و ابری) و وضعیت اجرای آن‌هاست.

  • اگر وارد Hermes Cloud شوید، عامل‌های حساب شما خودکار کشف می‌شوند.
  • برای هر عامل می‌توانید نشست تازه باز کنید و مستقیم داخل همان کار کنید.

۱۴ گراف حافظه Starmap

یک نشه بصری از حافظه عامل: مفهوم‌ها و خاطرات به‌شکل گره‌های ستاره‌ای که با گفتگوهای بیشتر پرتر می‌شوند.

از نوار عنوان با «باز کردن گراف حافظه» باز می‌شود. برای دیدن اینکه عامل واقعاً چه چیزهایی از شما یاد گرفته، بهترین جاست.

۱۵ تنظیمات — همه بخش‌ها

تنظیمات یک پوشش تمام‌صفحه با نوار ناوبری اختصاصی است و جستجوی سراسری دارد. بالای صفحه یک نشان «اعمال به» می‌گوید تغییرات روی کدام پروفایل ذخیره می‌شوند.

🌐 زبان

زبان رابط دسکتاپ را انتخاب کنید. با انتخاب فارسی، کل رابط RTL می‌شود. تنظیم در ~/.hermes/config.yaml هم ذخیره می‌گردد.

🧩 ارائه‌دهندگان

حساب‌ها (ورود مرورگری بدون کپی کلید)، کلیدهای API، و نقاط پایانی سفارشی سازگار با OpenAI (Ollama، vLLM، llama.cpp…).

🎛 مدل

مدل پیش‌فرض، پنجره زمینه، مدل‌های جایگزین، استدلال و مدل‌های کمکی هر وظیفه (بینایی، فشرده‌سازی، تولید عنوان، بازبینی، تأیید و…).

🔌 دروازه‌ها

ثبت و مدیریت اتصال‌ها: محلی، راه دور (HTTP/S)، SSH یا Hermes Cloud. سوئیچ بین دروازه‌ها از صفحه نشست‌ها انجام می‌شود و کار دروازه‌های دیگر ادامه پیدا می‌کند.

🔑 ابزارها و کلیدها

کلیدهای API ابزارها و اعتبارنامه‌ها در .env. مجموعه‌های ابزار فعال (حافظه، ترمینال، جستجوی وب، تفویض و…) را همین‌جا روشن/خاموش کنید.

🔗 MCP

سرورهای Model Context Protocol را اضافه، فعال/غیرفعال و آزمایش کنید. ورود سریع از قطعه‌های mcp.json، فرمان npx/docker یا لینک Cursor پشتیبانی می‌کند.

💬 گفتگو

سبک دستیار، نمایش استدلال، حداکثر نوبت‌های عامل، پیوست‌های تصویر و پوشه پیش‌فرض پروژه برای نشست‌های جدید.

🎨 ظاهر

حالت روشن/تاریک/سیستم، پوسته‌ها (نصب از VS Code Marketplace)، مقیاس رابط، فونت ترمینال، شفافیت پنجره، پس‌زمینه گفتگو و موجود زنده (Pet).

🛡 ایمنی

حالت تأییدها، مهلت تأیید، فهرست سفید فرمان‌ها، سانسور اسرار و نقاط بازگشت فایل (Checkpoints) پیش از ویرایش.

🧠 حافظه و زمینه

حافظه ماندگار، پروفایل کاربر، سهمیه‌های کاراکتر، موتور زمینه و فشرده‌سازی خودکار گفتگوهای طولانی با آستانه و نسبت هدف.

🎙 صوت

تبدیل گفتار به متن (محلی یا OpenAI، Groq، ElevenLabs و…) و متن به گفتار (Edge، OpenAI، ElevenLabs، Piper و…) با صدای قابل انتخاب.

🖥 فضای کار

باک‌اند اجرای ترمینال (محلی، Docker، SSH، Singularity، Modal، Daytona)، پوشه کاری، مهلت فرمان‌ها و متغیرهای محیطی قابل عبور.

🔔 اعلان‌ها

اعلان‌های سیستم‌عامل به‌تفکیک نوع: تأیید لازم است، ورودی لازم است، پاسخ آماده، وظیفه پس‌زمینه تمام شد، هشدار اعتبار و افزونه‌ها — به‌علاوه صدای پایان کار.

🧩 افزونه‌ها

افزونه‌های دسکتاپ (رابط) و افزونه‌های عامل (ابزار، مهارت، سرور MCP، هوک و فرمان اسلش). نصب از مخزن Git با بازبینی پیش از نصب.

📦 نشست‌ها

گفتگوهای بایگانی‌شده، بایگانی خودکار گفتگوهای کهنه و پوشه پیش‌فرض پروژه.

⚙️ پیشرفته

محدودهای خواندن فایل و خروجی ابزار، مدل زیرعامل و تفویض، بیدار نگه داشتن کامپیوتر و ورود سریع (Quick Entry) با میان‌بر سراسری.

💳 صورت‌حساب

اعتبار Nous Portal و وضعیت اشتراک ارائه‌دهنده‌ها؛ هشدار «اعتبار تمام شد» همین‌جا اتصال دارد.

ℹ️ درباره

نسخه برنامه، شاخه و کامیت، به‌روزرسانی‌های خودکار یا دستی و یادداشت‌های انتشار.

۱۹ عیب‌یابی و پرسش‌های رایج

خطای «پل IPC دسکتاپ در دسترس نیست» (Desktop IPC bridge is unavailable) تقریباً همیشه یعنی نشانی 127.0.0.1:5174 را در یک مرورگر معمولی باز کرده‌اید — نه اینکه برنامه خراب باشد. پنجره برنامه دسکتاپ Hermes را باز کنید؛ توضیح کامل در «تفاوت مرورگر و برنامه دسکتاپ» پایین همین بخش.

تفاوت مرورگر و برنامه دسکتاپ

در حالت توسعه، برنامه از دو نیمه تشکیل شده که هر دو باید اجرا شوند:

نیمهچه چیزی استچطور بالا می‌آید
رابط کاربری (Vite)صفحه‌ای که در 127.0.0.1:5174 سرو می‌شود؛ فقط رندرر است.خودکار همراه npm run dev
پوسته دسکتاپ (Electron)پنجره واقعی برنامه؛ پل window.hermesDesktop فقط همین‌جا تزریق می‌شود.خودکار همراه npm run dev

پل IPC توسط اسکریپت preload الکترون به صفحه تزریق می‌شود، پس در فایرفاکس، کروم یا هر تب پیش‌نمایشِ مرورگری هرگز وجود ندارد. نتیجه: صفحه بالا می‌آید و فارسی هم دیده می‌شود، اما بوت با همین خطا متوقف می‌شود. برنامه عمداً نیست — کلاینت الکترون غایب است.

  • راه درست: پنجره دسکتاپ با عنوان «Hermes» را از نوار وظیفه باز کنید.
  • نشانی 127.0.0.1:5174 فقط برای اتصال داخلی الکترون به رندرر است؛ باز کردن مستقیم آن در مرورگر خطای بالا را می‌دهد.
  • از این نسخه، اگر رابط کاربری بیرون از الکترون باز شود، به‌جای صفحه خطای قدیمی کارتی فارسی نشان می‌دهد که همین توضیح را می‌دهد («در مرورگر باز شده، نه در برنامه دسکتاپ»).

اجرای برنامه در حالت توسعه (npm run dev)

cd apps/desktop
npm run dev
  • npm run dev هر دو نیمه را با هم بالا می‌آورد: سرور Vite روی پورت 5174 و سپس پنجره الکترون که خودش به آن وصل می‌شود.
  • اولین اجرا ممکن است چند دقیقه طول بکشد (ساخت باندل‌ها و راه‌اندازی باک‌اند)؛ پنجره با صفحه پیشرفت «راه‌اندازی Hermes Desktop…» نشان می‌دهد.
  • اگر فقط سرور Vite بالا باشد و پنجره الکترون باز نشود، دوباره npm run dev را اجرا کنید — یا در ترمینال دیگری npm run dev:electron تا فقط پوسته دسکتاپ به سرور در حال اجرا وصل شود.
  • تغییر کد رندرر با HSL/HMR فوراً در پنجره اعمال می‌شود؛ اگر تغییری اعمال نشد، پنجره را با Ctrl+R بازخوانی کنید.
  • برای تست بدون کلید API واقعی: npm run dev:mock یک سرور ساختگی پاسخ‌های آماده می‌سازد.
مشکلراه‌حل
«پل IPC دسکتاپ در دسترس نیست»نشانی سرور توسعه را در مرورگر باز کرده‌اید. پنجره برنامه دسکتاپ Hermes را باز کنید (بخش «تفاوت مرورگر و برنامه دسکتاپ» بالا).
راه‌اندازی دسکتاپ ناموفق بوداز صفحه خطا «تلاش دوباره»، «تعمیر نصب» یا «استفاده از دروازه محلی» را امتحان کنید؛ هیچ‌کدام گفتگوها یا تنظیمات را حذف نمی‌کنند. لاگ‌ها از دکمه «باز کردن لاگ‌ها» در دسترس‌اند.
«Hermes couldn't start the desktop UI» با کد (-6) و مسیر apps\desktop\dist\index.htmlیعنی برنامه بدون متغیر محیطیِ سرور توسعه اجرا شده: الکترون به‌جای اتصال به سرور Vite به‌دنبال باندل نسخه ساخته‌شده (dist) می‌گردد که در مخزن توسعه وجود ندارد (-6 = فایل پیدا نشد). برنامه را با cd apps/desktop و سپس npm run dev اجرا کنید؛ اجرای مستقیم electron . دقیقاً همین خطا را می‌دهد. گزینه hermes desktop --force-build فقط برای نسخه نصب‌شده کاربرد دارد، نه مخزن توسعه.
«Backend exited before it became ready» همراه با خطای «rejected the session token»پیامِ توکن گمراه‌کننده است — علت واقعی تقریباً همیشه ناهم‌خوانی وابستگی‌های پایتون است: هنگام بررسی WebSocket، باک‌اند زنجیره import مسیر ws را بارگیری می‌کند و می‌شکند (رایج‌ها: uvicorn قدیمی‌تر از 0.31 بدون capture_signals، نسخه اصلی ناسازگار websockets، یا نبودن ماژول concurrent_log_handler). در desktop.log دنبال Traceback واقعی بگردید، روی همان مفسر پایتونِ باک‌اند pip install -e ".[web]" (یا uv sync --extra web) را اجرا کنید و برنامه را دوباره باز کنید؛ hermes doctor نیز وضعیت محیط را می‌سنجد.
چک‌لیست ناهم‌خوانی محیط پایتون (خطاهای import یا نسخه هنگام بوت باک‌اند)چهار گام به‌ترتیب: ۱) pip check — باید «No broken requirements found» بدهد؛ هر خطی که «requires X, but you have Y» گفت یعنی آن بسته را با نسخه خواسته‌شده نصب کنید. ۲) نسخه‌های نصی را با پین‌های پروژه بسنجید: نسخه دقیق هر وابستگی در pyproject.toml (بخش [project.optional-dependencies] برای وب: uvicorn، fastapi، starlette، websockets، python-multipart) و [project.dependencies] برای بقیه؛ هم‌ترازی کامل با pip install -e ".[web]" روی همان مفسرِ باک‌اند. ۳) اگر pip هشدار «Ignoring invalid distribution ~xyz» داد، پوشه باقی‌ماندهٔ نصب نیمه‌کاره را حذف کنید — در Lib/site-packages هر پوشه‌ای که با ~ شروع می‌شود (مثل ~vicorn یا ~qlalchemy) خرده‌نصبِ خراب است و باید پاک شود. ۴) سلامت زنجیره ورود ماژول‌ها را مستقیم بیازمایید: python -c "import uvicorn, fastapi, websockets; from tui_gateway.ws import handle_ws" — اگر این بدون خطا گذشت، محیط سالم است.
چک‌لیست ناهم‌خوانی محیط npm/Node (خطاهای نصب، EENGINE)چهار گام به‌ترتیب: ۱) نصب‌های تکراری را با npm ci انجام دهید — این دستور درخت node_modules را حذف و دقیقاً مطابق package-lock.json بازسازی می‌کند؛ npm install برای نصب روزمره است و ممکن است lockfile را جابه‌جا کند. ۲) بهداشت lockfile: این مخزن تک‌قفل‌نامه است — همه کارهای نصب از ریشه مخزن انجام شود و package-lock.json را همراه هر تغییر وابستگی کامیت کنید؛ پراکندگیِ npm install در زیرپوشه‌ها (مثل ui-tui) رزولوشن پکیج‌های داخلی را می‌شکند. ۳) خطای EENGINE یعنی npm نصب‌شده در بازه مجاز engines پروژه نیست (<11.10.0 || >=11.17.0) — نسخه سازگار نصب کنید (مثل npm i -g npm@12) و از دورزدن با --engine-strict=false جز در مواقع ضروری خودداری کنید، چون .npmrc پروژه این را عمداً سخت‌گیرانه کرده است.
خطای EALLOWSCRIPTS یا اجرا نشدن اسکریپت‌های postinstallاین خطا یعنی postinstallهای بسته‌ها (مثل دانلود باینری الکترون) اجرا نشده‌اند. علت رایج: خط allow-scripts در ~/.npmrc کاربر — آن خط را حذف کنید تا پیکربندی پروژه حاکم شود. اگر ممنوعیت اسکریپت عمدی است (سیاست امنیتی)، به‌جای غیرفعال‌سازی سراسری از npm ci --ignore-scripts آگاهانه استفاده کنید. آزمون سلامت: باینری الکترون باید در node_modules/electron/dist باشد؛ نبودش یعنی postinstall اجرا نشده است.
اولین اجرا طول می‌کشددر اولین اجرا، برنامه باک‌اند را از صفر راه می‌اندازد (نصب وابستگی‌ها)؛ صفحه پیشرفت را باز بگذارید. اجراهای بعدی سریع‌اند.
اتصال با دروازه قطع شدبرنامه خودش در پس‌زمینه تلاش مجدد می‌کند؛ اگر باقی ماند، تنظیمات دروازه را باز کنید و برای دروازه راه دور دوباره وارد شوید.
«باک‌اند قدیمی است»زمان اجرای Hermes از برنامه دسکتاپ عقب است — از اعلان «به‌روزرسانی Hermes» استفاده کنید.
متن فارسی به‌هم‌ریخته در ترمینالفونت ترمینال را در تنظیمات ← ظاهر به یک فونت پشتیبان RTL (مثل Vazirmatn یا JetBrains Mono) تغییر دهید.
فارسی اعمال نشددر ترمینال: hermes config get display.language — مقدار باید fa باشد. متغیر HERMES_LANGUAGE بر پیکربندی اولویت دارد.
خطای کلیاز ترمینال hermes doctor را اجرا کنید؛ برای ارسال گزارش به Nous از «ارسال عیب‌یابی» استفاده کنید (اسرار سانسور و بسته پس از ۱۴ روز حذف می‌شود).
اعتبار تمام شداز هشدار «افزودن اعتبار» یا بخش صورت‌حساب در Portal ادامه دهید؛ مدل‌های جایگزین در تنظیمات مدل توقف‌گاه میانی می‌سازند.
سرویس MCP در دسترس نیستاز تنظیمات ← MCP حالت سرور را ببینید؛ اگر «نیازمند احراز هویت» است دوباره وارد شوید و «بارگذاری مجدد MCP» را بزنید.
