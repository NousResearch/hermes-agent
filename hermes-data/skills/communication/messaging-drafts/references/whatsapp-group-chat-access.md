# WhatsApp Group Chat Access — Honest-Answer Pattern

## Trigger

User asks "do you have access to the entire conversation I've been having with the landowners on the [project] group?" before dictating a group update (or similar "do you have the full chat" questions).

## Fact

Hermes has NO read access to WhatsApp group chats. WhatsApp is not connected — the group's messages (including landowner replies) are invisible. What you DO have is only:

- Messages YOU drafted through Hermes in past sessions (delivered as tap-to-send deep links — you know what was sent through you, not the replies)
- Email threads via Gmail (e.g. term-sheet emails to individual landowners)
- Drive/JDA records (landowner list, share details, index spreadsheets)

## Correct response shape — don't claim context you don't have

1. Confirm plainly: no, you do not hold the full group chat.
2. Inventory what you actually hold:
   - Past drafts you generated for that group
   - Individual landowner transaction records (e.g. Sunder Padmanabhan ₹20L advance — ₹1L token Jan 2026 + ₹19L ad-hoc Jul 2026, total consideration ₹2Cr, balance ₹1.8Cr at registration)
   - Landowner list from the JDA
   - Recent project emails (architect planning thread, etc.)
3. Offer the ingestion path: user can export the WhatsApp group chat (WhatsApp → group → Export chat) and send the .txt — you'll ingest it. Landowner replies still won't appear unless the user relays the key ones.
4. Then proceed: "Want to dictate the update now — I'll draft it with the verified context baked in."

## Why

Prevents fabricating "I have all context" (which leads to wrong messages to the group) and prevents missing landowner-side facts that never came through email.

Pairs with `references/voice-recall-vs-written-record-accuracy.md` — the written record you drafted/emailed is authoritative over the user's voice recall.

## Caption convention (colleague vs external)

Established convention (Sep 2026): bold WhatsApp caption (`*Caption*`) goes on messages to DRA colleagues (staff asked to pull/scan files — e.g. Bharat). NO caption for external recipients (landowners, outsiders — e.g. Swaminathan). Do not invent captions for external contacts; plain message body only.

## Related pitfall — verify index row numbers against the live sheet

When the user dictates a reference from memory ("row 224"), VERIFY against the live spreadsheet before putting the number in any external message. In one session the user said row 224 but the live Allalsandra index sheet had the death certificate at row 244 — sending the unverified number to Bharat would have sent him hunting in the wrong physical file. Always re-read the sheet, confirm the row, and state the corrected source (sheet tab name + row number) in the draft.
