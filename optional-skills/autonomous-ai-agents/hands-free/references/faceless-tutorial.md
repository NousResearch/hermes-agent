# Example: A First Faceless Software Tutorial

This is a portable production example, not a report that a video was made. It demonstrates proof before scale, an authentic evidence chain, multi-artifact QA, and delivery gates. Choose subject, languages, duration, and publishing destination from the current user's request; do not inherit another user's preferences or files.

## Brief and acceptance

Agree on the audience, one learning outcome, real-screen-footage requirement, narration and caption languages, target aspect ratio/resolution, duration range, and required deliverables. For a first video, keep the demonstration small enough to verify completely. If the request is only production, public uploading is out of scope.

| Deliverable | Acceptance evidence |
|---|---|
| Finished video | Correct container/streams/duration; full decode; playback review; readable UI and captions |
| Demonstrated result | Real before/action/after recording; result independently read back |
| Narration and script | Accurate to the demonstrated behavior; intelligible audio and appropriate rights/consent |
| Captions | Correct language, text, timing, rendering, and placement |
| Thumbnail/title/description if requested | Accurate claims, legibility, no unintended private information |
| Editable production kit if requested | Source footage, script, caption files, project/edit notes, asset provenance, final-output manifest |
| Publication only if requested | Exact channel/account, approved payload, processed media, actual object readback |

## Production milestones

1. **Discover and isolate.** Inventory existing footage/assets and approved installed tools. Preserve originals and previous exports. Use a clearly labeled demo copy for edits; do not modify a live application installation or the active agent conversation to manufacture a scene. Exit: an isolated working area and protected source inventory exist.
2. **Prove the demonstration.** Record a short real interaction and verify its resulting state before writing the full narration. A visible menu alone does not prove an edit worked. If a crucial action cannot be verified, stop or negotiate a changed tutorial; do not replace real footage with a fabricated interface. Exit: an authentic demonstrable outcome exists.
3. **Write to the evidence.** Explain what the viewer can actually observe. Mark a reenactment or existing-code walkthrough accurately rather than implying original from-scratch development. Synthetic narration is acceptable when authorized and represented honestly; never impersonate a real person without the required consent. Exit: script claims map to footage or separately sourced facts.
4. **Capture and edit.** Record only the task surface, excluding credentials, notifications, private tabs, and personal account details. Save raw footage and edit copies separately. Use close-ups where needed; avoid visual effects that conceal failures. Use owned/licensed media and check whether any rendering/narration provider will receive private material before sending it. Exit: an assembled draft uses authentic footage with known provenance.
5. **Export a versioned candidate.** Keep prior cuts and editable inputs. Record export settings, asset list, caption version, and output identity. Do not download codecs, fonts, engines, or model weights without the installation review gate. Exit: the actual exported artifact exists without overwriting the source kit.
6. **QA the exact final file.** Perform the checks below, fix defects, and repeat affected checks on the new candidate. Exit: every agreed criterion passes or is explicitly unresolved.
7. **Deliver, then separately gate publication.** Provide the requested files. For public release, follow the main skill's account, payload, consent, single-submit, processing, and exact-object readback procedure. Exit: local delivery or the explicitly authorized external state is verified.

## Media QA, not just a successful render

- Inspect metadata: intended codecs/container, dimensions, duration, frame rate, video/audio stream presence, and required caption track or sidecar. Compare against the brief and current destination requirements rather than fixed guessed limits.
- Decode the entire export with an already approved tool, not merely its header or first frame. Save the real result; if no decoder is available, mark this check untested instead of claiming a pass.
- Play back the video and listen to its narration. Inspect the opening, every important state transition, and ending, plus caption boundaries. Full playback is the target for a short first tutorial; document any sampling limits.
- Check that every essential UI action and result is visible, in focus, and readable at the intended viewing size. Cropping must not remove the proof of success.
- Check audio for intelligibility, unintended silence, clipping, abrupt cuts, music masking, and synchronization; inspect measured levels where tooling permits.
- Parse subtitle cue ordering and start/end times, check text completeness and timing, and inspect the rendered result. For Arabic or other complex scripts, explicitly check shaping, bidirectional order, punctuation, fonts, and line breaks; valid subtitle syntax does not establish correct display.
- Check private-data leakage across frames, audio, subtitles, metadata, and source attachments. Review a redacted derivative without silently replacing or publicly exposing restricted originals.
- Compute the final file hash after all edits, and record it in the local output manifest. If the uploaded platform transcodes, verify its playback/content and account separately; a local hash alone cannot prove the published media.

If rendering/capture is blocked, deliver the authentic partial kit and precise blocker. A storyboard is not a finished video, an illustrative UI is not a screen recording, and an upload preview is not a published tutorial.
