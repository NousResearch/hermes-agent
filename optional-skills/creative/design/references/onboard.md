# Onboard

Onboarding's job is to get users to the moment that proves the product is worth their time. It is not a product tour.

## Principles

- **Show, don't tell.** Use working examples and real actions, not descriptions.
- **Time to value first.** Teach the 20% that delivers 80% of value.
- **Make it optional.** Let experienced users skip.
- **Context over ceremony.** Teach when the feature appears, not upfront.
- **Respect the user.** Don't patronize or over-explain standard patterns.

## Empty states are onboarding

Every empty state needs:
1. **What will be here:** "Your recent projects will appear here."
2. **Why it matters:** "Projects help you organize work and collaborate."
3. **How to start:** `[Create project]` or `[Start from template]`.
4. **Visual interest:** illustration or icon, not a blank page.
5. **Help link:** "Need help? [Watch a 2-min tutorial]."

## First-run experience

- Clear value proposition and honest time estimate.
- Minimal required information; collect more later.
- One to three core concepts, not everything.
- Pre-populated data or templates so the first success is real.
- Clear next step after completion.

## Contextual discovery

- Tooltips appear when the user first reaches a feature.
- Badges on new or unused features.
- Empty states guide the next action.
- Inline help and keyboard shortcut hints (`⌘K`).

## Verify

- Users reach value quickly.
- They understand what to do next.
- Skip rate and completion rate are healthy.
- Returning users are not shown the same onboarding twice.

When the first-run path is clear, hand off to `polish`.
