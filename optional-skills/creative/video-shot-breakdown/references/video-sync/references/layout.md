# 版式与几何

## 一条规则：只看宽高比

```
宽 ≥ 高（横版、方版） → vstack：画面在上，面板在下
宽 <  高（竖版）      → hstack：画面在左，面板在右
```

不看分辨率、不看帧率、不看内容。方版（1:1）走横版那一支——1:1 的片子把面板放右边会挤成一条。

## 尺寸怎么算

| | 横版 / 方版 | 竖版 |
| --- | --- | --- |
| 画面区 | 宽 = min(原片宽 × `--scale`, `maxVideoWidth` 1920)，高按原比例 | 高 = min(原片高 × `--scale`, `maxVideoHeight` 1080)，宽按原比例 |
| 面板区 | 与画面**同宽**，高 = 画面高 × `panelRatioWide`（0.8） | 与画面**同高**，宽 = 画面宽 × `panelRatioTall`（1.6） |
| 输出 | 宽 = 画面宽，高 = 画面高 + 面板高 | 宽 = 画面宽 + 面板宽，高 = 画面高 |

三条硬约束：

1. **画面只缩不裁不拉**——原片的宽高比一分不动。面板负责补齐剩下的画布
2. **所有边长取偶数**（h264 的要求）。1281×721 这种奇数尺寸的原片最容易在这里炸，
   自测里专门有一条
3. **面板最短边不低于 `minPanelPx`（260）**——再小字就放不下了，
   320×240 的老素材也得给面板留够地方

**默认只缩不放。** 但面板是跟着画面区算的，原片太小面板也跟着小：640×360 的片子面板只有
640×288，四列挤在一起谁也读不了。这种时候用 `--scale 2` 把画面区放到 1280×720，
面板跟着变成 1280×576——**放大的是像素，不是构图**，宽高比一分不动，上限照样夹。
画面会糊一点，但「糊一点的画面 + 读得清的表」比「清楚的画面 + 读不了的表」有用。

## 几个实际的数

| 原片 | 版式 | 画面 | 面板 | 输出 |
| --- | --- | --- | --- | --- |
| 1280×720（16:9） | 上下 | 1280×720 | 1280×576 | 1280×1296 |
| 1680×720（21:9） | 上下 | 1680×720 | 1680×576 | 1680×1296 |
| 1080×1080（1:1） | 上下 | 1080×1080 | 1080×864 | 1080×1944 |
| 1080×1920（9:16） | 左右 | 608×1080 | 972×1080 | 1580×1080 |

竖版那一行是重点：**输出是 1580×1080 的近似 3:2**，不是把竖片硬塞进 16:9 再两边填黑。

## 旋钮

命令行给，或者写进 shots.json 的 `syncParams`：

| 参数 | 默认 | 作用 |
| --- | --- | --- |
| `--panel <比例>` | 横 0.8 / 竖 1.6 | 面板相对画面的大小。**信息多就调大**（0.9 / 2.0），要突出画面就调小 |
| `--scale <倍数>` | 1 | 画面区相对原片的倍数。默认只缩不放；**原片太小面板排不下四列就调它** |
| `--width` | 1920 | 画面区宽上限（横版按它缩） |
| `--height` | 1080 | 画面区高上限（竖版按它缩） |
| `--crf` | 20 | x264 质量，越小越清晰越大 |
| `--ease <秒>` | 0.45 | 切点处滚动与高亮的缓动时长 |
| `--anchor <行号>` | 1 | 当前镜头钉在第几行（0 = 第一行） |
| `syncParams.fps` | 30 | 输出帧率 |

调之前先跑 `plan`——它只算不合成，几秒出结果。

## 动画：只截三张图，动的部分交给 ffmpeg

面板上会变的只有两样：**滚到哪**、**哪一行亮**。所以既不逐帧截图，也不一个镜头截一张：

```
量一次   #measure  → 每行的 top/height、列表视窗的位置、整张表的高
截三张   #static   → 表头 + 进度条的底板（面板尺寸）
         #tall     → 整张镜头表铺开、全部压暗的长图
         #tall-lit → 同一张表，但每行都按「当前镜头」的样子渲
合成     暗底长图裁一个视窗 → 盖到列表位置（这是滚动）
         亮条长图裁一行高   → 盖到当前行此刻的位置（这是高亮）
```

53 镜的片子截图从 53 次降到 3 次（12 秒），换来的是**真正的连续动画**。

### 当前镜头钉在第二行

```
第 1 镜   列表在顶，它就是第一行            不滚
第 2 镜   还在顶，高亮往下挪到第二行         不滚
第 3 镜起 每切一次往上滚**一行**，当前镜头始终停在第二行
```

锚点取的是**第二行的行首**（`rows[1].top`），不是「视窗高的百分之多少」——
按百分比算滚完会卡在两行中间，整张表看着是歪的（踩过）。`--anchor 0` 可以改成钉第一行。

### 动在切点，静在镜头里

切点处滚 `--ease`（默认 0.45）秒到位，**滚完就停住**。
长镜头里让列表一直慢慢爬会一直晃眼睛——16 秒的长镜头，观众要盯着它 16 秒。

高亮条和视窗用同一段缓动，所以是「一起滑过去」，不是一个跳一个滑。

### 行高由内容决定

画面描述和节奏分析不截断，写得长行就高——行高是**浏览器量出来的**，脚本不猜。

代价在高亮条上：**`crop` 的高度是配置期定死的，运行时只认 x/y 命令**（`h` 命令无效，试过）。
所以按行高分层：出现过几种行高就建几层高亮条，当前镜头用哪种高度就点亮哪一层，
其余各层挪到画面外「停车」。上一镜那层晚一个缓动才停——让它陪着滑完这一程，
不在切点上凭空消失。绝大多数片子只有一两种行高，也就一两层。

### 四个踩过的坑

1. **`drawbox` 的表达式只在初始化时算一次**，用它画高亮框会得到一张永远不动的框。
   只有 `crop` 和 `overlay` 的 x/y 是逐帧求值的——动画只能落在这两个上。
2. **别把整片拼成一条大表达式。** ffmpeg 的表达式解析器在一百来项上直接
   「Failed to configure input pad」——53 镜 × 2 段 = 106 项，正好踩线。
   改成 **sendcmd**：每个镜头在切点处下发一条只管自己那一段的小表达式（50 字符以内）。
3. **裁的 x 要和盖的 x 是同一个值。** 长图是整块面板那么宽的，列表在里面是缩进的
   （`view.x`，1280 的面板缩 27px）。从 `x=0` 裁一个 `view.width` 宽的窗口再盖回 `view.x`，
   整张表会往右挪 27px，右边同样宽度的字被切掉——看上去像「最后一个词被啃了一口」。
4. **停车位要在整块面板之外，不只是视窗之外。** 视窗底下还留着进度条那一条，
   停在「视窗底 + 10」的话，没轮到的那层高亮条会有一截露在进度条上面。

浏览器预览（`panels/panel.html`、调参台）里用 CSS `transition` 做同样 0.45 秒的补间，
所以**预览里看到的动效和导出的一致**；`#tall` / `#static` 这两个截图模式里 transition 被关掉，
否则会截到动画中间的某一帧。
