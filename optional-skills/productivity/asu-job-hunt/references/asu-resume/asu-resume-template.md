# ASu 同款单栏高密度技术简历模板

## 适用场景

用于 `/asu-resume` 复刻参考图中的中文技术简历，适合应届生、实习生和 AI/Agent/LLM/前端工程方向候选人。模板强调“身份定位 → 公开背书 → 项目全景 → 个人职责 → 技术证据”，不把经历写成无法追问的宣传文案。

## 页面结构

1. **顶部信息区**：姓名、电话、邮箱、微信/主页、年龄或身份、目标岗位、GitHub/开源身份、学校和毕业时间；最右侧预留证件照位置。
2. **经历分区**：用蓝色粗体标题和细蓝线分隔，默认顺序为“实习经历 → 项目经历 → 校园经历 → 技能与其他”；内容不足时不强行分页留白。
3. **公司条**：浅灰圆角背景，左侧放公司或平台 Logo，中间写团队/业务/岗位，右侧写时间与公开链接。
4. **项目标题**：蓝色加粗，必要时加中英文项目名、仓库链接或产品链接。
5. **项目要点**：按“背景/目标 → 我的职责 → 关键技术动作 → 结果证据”排列；每个项目 2—5 条，技术细节用缩进子弹点展开。
6. **分页**：内容能在正常字号下形成完整信息闭环时优先单页；双页时第一面优先放最强实习/核心项目并先填实，再由第二面承接补充项目、开源、论文、技能和奖项。长项目在自然段落处分页，不截断标题和子弹点。

## 视觉参数

- 纸张：A4，建议页边距 10—13 mm；正文 9.5—10.5 pt，行距 1.25—1.4。
- 姓名：20—24 pt，黑色加粗；顶部定位和联系信息紧凑排列。
- 分区标题：16—18 pt，使用蓝色 `#2458B8`，下方 1—2 px 蓝线。
- 项目标题：11—13 pt，蓝色加粗；正文黑色，关键词可加粗但不要整段加粗。
- 公司条：背景 `#F3F4F6`，圆角 6 px；Logo 建议 22—28 px，保持等比，不拉伸。
- 链接：蓝色，并在可见文字中保留规范化 URL、DOI 或可识别的“域名/关键路径”；打印后不能只剩“网站”“PAPER”“CODE”等标签。长地址去掉无关追踪参数后允许换行，不能把无法公开验证的内容写成背书。
- 字体：中文统一优先使用 `SimHei`、`黑体`、`Microsoft YaHei` 等黑体字体；英文使用 `Times New Roman` 风格，并准备通用回退字体。
- 个人信息图标：电话、邮箱、微信、身份、教育和 Star 图标统一使用 `../../assets/icons/` 中的 SVG，不使用 Emoji；品牌 Logo 继续使用 `../../assets/logos/`。
- 页面模式：HTML 工具栏提供 `A4 分页` 和 `A4 长页（不限高度）` 两种模式；分页模式显示 A4 纸张边界，长页模式保持 A4 宽度并连续向下编辑。
- 编辑工具：选中文字后可在同一工具栏修改字体、字号、文字颜色和加粗，使用撤回/前进修正编辑，并由浏览器本地自动保存；同时可使用打印按钮导出 PDF。
- 证件照：右上角预留框支持点击选择本地图片，已有照片时再次点击即可替换。
- 页面密度：按 [`/resume` 页面平衡规则](../resume/page-balance-qa.md) 测量每张 `.sheet`；优先通过内容重排和结构合并消除大面积空白，不靠缩小到难读或添加装饰填充。

## Logo 资源库

Logo 文件统一放在 `../../assets/logos/`，文件名使用小写英文或品牌英文名，和简历内容解耦。获取 AI、模型、平台或公司 Logo 时，优先遵循 [LobeHub Icons 技能说明](https://lobehub.com/icons/skill.md)，使用 `@lobehub/icons` 或 `@lobehub/icons-static-svg` 的 SVG/CDN 资源。

| 简历名称        | 文件                                       | 匹配别名                          |
| --------------- | ------------------------------------------ | --------------------------------- |
| OpenAI          | `../../assets/logos/openai.svg`           | OpenAI、GPT、OpenAI API           |
| Claude          | `../../assets/logos/claude.svg`           | Claude、Anthropic、Claude API     |
| 抖音 / 字节跳动 | `../../assets/logos/bytedance-color.svg` | 抖音、字节跳动、ByteDance、TikTok |
| 哔哩哔哩        | `../../assets/logos/bilibili-color.svg`  | 哔哩哔哩、B站、Bilibili           |
| GitHub          | `../../assets/logos/github.svg`          | GitHub、Github、开源仓库          |

生成用户专属简历时，每段能够确认品牌的公司或平台经历都应显示 Logo：先复用上表中的共享资源；缺少对应品牌时，从 `@lobehub/icons` 或 `@lobehub/icons-static-svg` 获取官方 SVG，并复制到用户 HTML 同级的 `logos/<brand>.svg`，由 HTML 通过相对路径引用。这样用户移动、预览或导出简历时不依赖仓库目录和网络。只有品牌无法确认或 LobeHub 没有可用资源时才显示纯文字公司条，不要用相似公司的 Logo 代替。

只有需要把新 Logo 沉淀为仓库共享资源时，才将文件命名为 `../../assets/logos/<brand>.svg` 并在本表登记别名；用户专属 Logo 不回写只读母版或共享资源目录。

## 内容规则

- 保留正式职位、公司、时间和教育背景，不用模板制造更高职级。
- 每个“Owner、主导、架构、0→1、核心作者”都要能由职责、提交、上线或评审证据支撑。
- 项目总调用量、用户数、Star/Fork 等指标要标明口径；项目数据不能自动算成个人数据。
- 先写个人贡献，再写技术栈；技术名词后面必须有动作或结果。
- 不确定的信息用 `【待补：指标/职责/链接】` 标记，成稿前集中让用户核对。

## 输出与校验

默认生成真正可编辑的 HTML，而不是整页截图。生成后检查：

- A4打印预览是否为预期页数；
- 联系方式、链接和中文字体是否可复制；
- Logo 是否清晰、等比、没有挤压；
- 公司条、项目标题和子弹点是否被分页拆开；
- 页尾是否有空白过大、文字溢出或下一页孤立标题。
- 单页是否形成完整闭环；双页的第一页是否先填实、末页空白是否能通过重排消除，并在交付说明中记录各页占用比例。
