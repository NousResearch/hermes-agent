# 主张—证据账本

主张—证据账本用于让 `/contributor`、`/asu`、`/resume` 和 `/asu-resume` 共享同一份事实基线。它解决的是跨 Skill 交接时证据来源、个人边界和确认状态容易丢失的问题，不是新的数据库或评分系统。

可复制 [../../../assets/career-claim-ledger-template.json](../../assets/career-claim-ledger-template.json) 作为起点。账本应保存在用户指定的求职材料目录，不回写插件模板。

## 何时使用

满足任一情况时建议创建或更新账本：

- 用户准备组合使用两个或更多 ASu skills；
- 同一经历需要生成多个岗位版本；
- 材料中存在 GPA、时间、论文状态、作者顺序、指标或职责冲突；
- 简历中出现“主导、负责人、Owner、0→1、核心作者”等强主张；
- 需要把 PR、项目链接、截图、证明或推荐人信息交给后续 Skill；
- 用户希望后续准备面试追问或复盘投递结果。

只生成一句 HR 开场白、且材料简单明确时，不强制创建账本。

## 最小字段

每条 `claims` 记录包含：

| 字段 | 用途 |
| --- | --- |
| `id` | 稳定引用这条主张，例如 `claim-project-001` |
| `source_fact` | 用户原始事实，不做包装 |
| `candidate_wording` | 可用于简历或沟通的候选表述 |
| `sources` | 证据类型、位置和公开状态 |
| `responsibility_level` | `参与`、`负责模块`、`主导方案或交付`、`项目负责人` |
| `verification_status` | `已确认`、`待确认`、`已过期`、`不采用` |
| `allowed_uses` | 可用于哪些岗位版本或求职材料 |
| `interview_details` | 能够在追问中展开的决策、难点、验证和结果 |
| `boundary` | 团队成果与个人贡献的明确分界 |
| `risk_notes` | 冲突、缺口或成稿前必须处理的问题 |
| `last_verified` | 最近一次由用户或证据确认的日期；未知时为 `null` |

`sources` 只保存定位证据所需的信息，例如公开 URL、文件名或“导师证明可提供”。不要复制密码、验证码、邮件全文、内部代码、客户数据或其他敏感内容。

## 状态规则

### 已确认

用户已明确确认，或有用户提供的可靠材料支持。可以进入正式简历，但仍必须保留 `boundary`。

### 待确认

来源之间存在冲突、证据不完整，或用户尚未确认。只可出现在审计稿和待补清单中；进入简历草稿时必须保留 `【待补】`，不能进入最终 PDF。

### 已过期

内容曾经正确，但会随时间变化，例如在读年级、论文在投状态、Star 数或当前岗位。更新前不能继续作为最新事实使用。

### 不采用

已确认不准确、与目标岗位无关，或用户决定不公开。保留原因便于复盘，但不进入对外材料。

## 各 Skill 的读写责任

### `/contributor`

PR 提交或合并后新增事实记录，保存仓库、PR 链接、状态、实际修改和验证方式。未合并 PR 的候选表述必须写“协作中”，不能写“被采用”。

### `/asu`

读取 `source_fact`、证据和边界，生成 `candidate_wording`。发现来源冲突时将状态设为 `待确认`，不能选择更有利的版本。强主张必须填入能够回答追问的 `interview_details`。

### `/resume`

正式成稿只消费 `已确认` 且适用于当前目标岗位的主张。`待确认` 可以进入带明显占位符的内部草稿，导出最终 PDF 前必须删除或确认。

### `/asu-resume`

除遵循 `/resume` 的规则外，还要确保模板中的醒目标题、指标和 Logo 不会放大未经确认的主张。模板母版保持只读，账本保存在用户副本旁边。

## 冲突处理

同一事实出现多个版本时，不新增两个互相矛盾的“已确认”主张。保留一个主张记录，把不同来源写进 `sources`，状态设为 `待确认`，并在 `risk_notes` 中列出冲突。例如：

```json
{
  "source_fact": "GPA 在两份材料中分别为 3.70 和 3.73",
  "candidate_wording": "【待补：以最新成绩单确认 GPA】",
  "verification_status": "待确认",
  "risk_notes": ["正式简历、领英和申请表必须使用同一数值"]
}
```

## 交付检查

- 对外材料中的每个强主张都能回指一条账本记录；
- 最终 PDF 不包含 `待确认`、`已过期` 或 `不采用` 的主张；
- 团队成果没有自动变成个人成果；
- 指标注明口径和时间，不把项目总量当成个人数据；
- 账本没有密码、验证码、邮件全文或内部敏感材料；
- 修改简历措辞时更新候选表述，不篡改原始事实。
