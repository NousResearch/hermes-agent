# `/contributor` 每日 routine 示例

这个示例用于支持定时任务的宿主环境。宿主负责按计划调用，`/contributor` 负责一次运行内的检查、候选准备、验证和汇报。

## 示例 prompt

```text
使用 $contributor 为 GitHub 用户【用户名】执行每日开源贡献 routine。

目标岗位：【岗位】
技术方向：【技术栈或领域】
候选赛道：【目标组织、项目或技术生态】

每次运行先只读检查已有 PR 的 CI、review、评论和合并状态，再轮换搜索近期活跃、贡献规则清楚、容易客观验证的文档、测试、示例、前端或小型代码问题。已有 PR 未合并不阻塞探索新机会。

默认准备最多【数量】个彼此独立的候选和本地 diff，但不得为凑数量降低标准。必须检查 CONTRIBUTING、AGENTS.md、AI_POLICY.md、相关 issue、认领状态、open/closed PR 和近期主分支，避免重复或处理已失效问题。

任何 fork、push、PR、评论或 review 修复都属于外部写操作。逐个展示目标仓库、账号、分支、文件、完整 diff、验证结果、PR 标题和正文，等待我明确确认后再执行。

运行结束时汇报：已有 PR 状态、检查过的仓库与候选、准备或提交的 PR、验证结果、未继续的原因，以及可选的时间或上下文消耗估算。未合并只记录为“已提交/协作中”，合并后才记录为“被项目采用”。
```

## 调度边界

- skill 不创建后台进程，也不保证定时唤醒；运行时间和失败重试由宿主配置。
- 宿主可以保存目标仓库和上次运行结果，但每次仍要重新检查上游状态。
- 不把一次确认扩展成后续运行的永久写入授权；每个 PR 和每次更新都要重新确认。
- 没有安全候选是正常结果，日报应说明筛选依据，而不是制造无意义改动。
