# PDR 管理端

管理端按登录者的角色权限显示菜单、数据与按钮，与用户端（问答）是两个独立工程，页面之间没有任何互相跳转的入口。

## 运行

推荐从仓库根目录一键启动（管理端与用户端一起拉起）：

```bash
python start_run.py
```

只看管理端界面时，也可以在仓库根目录（pnpm 工作区）单独运行：

```bash
pnpm install
pnpm dev:admin
```

打开 http://127.0.0.1:5173 。

## 示例数据模式

后端管理接口完成前，管理端默认使用内置示例数据（`src/api/mock/`），所有页面与操作都能完整体验；示例数据保存在浏览器本地，清除站点数据即可还原。

登录页列出演示账号，任意密码均可登录，不同角色看到的菜单、数据范围与按钮不同：

| 账号 | 角色 | 能看到的 |
|---|---|---|
| `zhanglei` | 租户管理员 | 本租户全部功能（不含租户管理、系统配置） |
| `wangmin` | 内容审核员 | 工作台、任务列表、内容看板、文档 / 音视频核对、分类确认、知识库；只看上海市的数据 |
| `lihang` | 标注员 | 工作台、任务列表、标注工作台；只看分配给自己的任务 |
| `admin` | 平台超级管理员 | 全部功能，含租户管理、系统配置与平台级（写入 config.yaml）的智能体配置 |

用户端（问答）账号（如 `chenxiao`）不能登录管理端。

切换到真实接口：把 `pdr/config.yaml` 的 `admin_web.mock_api` 改为 `false`（单独运行时设置环境变量 `VITE_ADMIN_MOCK=false`），请求会发往 `/api/admin/v1`，开发服务器把它代理到 `app.host:app.port`。

## 权限

- 菜单定义在 `src/lib/nav.ts`：模块 → 页面，每个页面挂一个功能权限编码（如 `content:review`、`agent:config`）。
- 菜单、路由守卫、工作台的待办页签与各页按钮都按登录者的权限过滤；直接输入没有权限的地址只会看到“没有权限”页。
- 接口同样校验（示例数据实现里也一样）：无权限的调用返回 403，并记入审计日志。

## 配置页的数据

「智能体配置」「系统配置」两页的表单由 `pdr/config.yaml` 每个配置项上方的 `#:` 元数据行生成（中文名、说明、取值范围、生效方式）。修改 config.yaml 的配置项或元数据后重新生成：

```bash
uv run python pdr/scripts/gen_admin_config_schema.py
```

## 目录

```
src/
├── api/          types.ts 接口约定 · http.ts 真实接口 · mock/ 示例数据（按权限与数据范围过滤）
├── stores/       auth（登录态与权限判断）
├── lib/          nav 菜单与权限 · format 阶段 / 状态 / 模态 · icons 图标 · toast 提示
├── components/   外壳布局、配置编辑器、图表、日历、上传、阶段条
├── views/        登录、工作台、内容任务、人工核对、知识库、智能体、权限管理、系统设置
├── data/         config-schema.json（由 config.yaml 生成，勿手改）
└── styles/       全局变量与通用样式
```
