# Strict Generation Prompt — Built LMS LinkedIn Drafting

## Four Output Gates

### Gate 1: Buyer-Relevance
Does this post address a problem an L&D Director, CS Lead, or Enablement Manager would recognize from their own work? If the answer isn't immediately obvious, discard the topic.

### Gate 2: Specificity
Is the claim grounded in a real workflow, tradeoff, or discovery insight? Generic observations ("most platforms lack X") are not specific. Name the pattern, the tool, or the specific frustration.

### Gate 3: Anti-Slop
- No "not X, but Y" / "not just X, but Y"
- No one-sentence paragraph stacking
- No SCORM as a topic
- No generic openers
- No engagement-bait endings
- No product-internal plumbing

### Gate 4: Claim-Safety
- No paying customers, revenue, named case studies, proven percentages
- No SOC 2, enterprise readiness, marketplace listings, integrations not live
- Aspirational examples must be framed as illustrative

## Hard-Failure Modes
HF-1: Binary reversal formulas ("not X, but Y")
HF-2: One-sentence paragraph stacking
HF-3: SCORM as content topic
HF-4: Generic openers
HF-5: Engagement-bait endings
HF-6: Product-internal engineering as content
HF-7: Unsupported customer claims

## Source-First Drafting
Build every post from vault research, discovery conversations, or specific product observations. Do not invent scenarios.

## Per-Batch Quality Checklist
- [ ] No HF-1 through HF-7 violations in any draft
- [ ] Each draft addresses a problem a buyer persona would recognize
- [ ] Each draft uses concrete details (workflow, tradeoff, observation)
- [ ] Each draft has a clear target persona and desired reaction
- [ ] Posts are under 1,300 chars (500-900 preferred)
- [ ] 0-2 hashtags max
