# 制限付きコーディング用の試行環境

この設定は、既存の実行制御を有効にしてコーディング作業を評価するための開始点です。
通常のユーザー設定は変更しません。CLI を対象にしています。

## 起動

1. Docker を起動し、作業用イメージに必要な依存関係を事前導入してください。
   `terminal.docker_image` にそのイメージを指定します。再現性が必要な運用では digest を固定します。
   実行中のコンテナはネットワークを使用できません。
2. 編集対象のリポジトリ直下で、新しい状態ディレクトリを使って起動します。

   ```sh
   HERMES_DEV_SANDBOX_DIR=.hermes-harness scripts/dev-sandbox.sh \
     --persistent --from scripts/sandbox-coding .venv/bin/hermes
   ```

3. 初回にモデルと認証を設定します。起動元のリポジトリだけがコンテナの `/workspace` に
   マウントされ、そこで編集できます。ホームディレクトリ・Docker socket・ネットワークは
   コンテナから見えません。成果物は起動元リポジトリの作業ツリーに残るため、レビュー後に
   `git diff` を確認してcommitしてください。

既存の `.hermes-harness` がある場合、`--from` は設定を上書きしません。
変更先は起動時に表示される `HERMES_HOME/config.yaml` です。
元の起動方法に戻せば、この試行設定は使われません。作業成果がある状態ディレクトリを削除しないでください。

## 制御と範囲

- 親は40回、各子は12回の反復上限。子は1ターン最大4件、同時2件、再委譲なし。
- 親の実行予算は600秒、子のタイムアウトは120秒。実行予算はプロセス全体の強制終了保証ではありません。
- 同一失敗・停滞を停止し、コード編集後は検証を促します。検証催促は有限で、品質の自動保証ではありません。
- 手動承認を使用し、無人実行では承認が必要な操作を拒否します。Docker内のコマンドはコンテナを隔離境界として扱うため、通常の危険コマンド承認を省略する実装です。
- CLI のツールを terminal / file / todo / delegation に絞り、ブラウザ・送信・cron・外部コネクタ・ホスト側コード実行を無効にします。
- Docker の隔離対象はターミナルと対応するファイル操作です。Hermes本体、モデルAPI通信、ホスト側プラグインを隔離する設定ではありません。未知のプラグインを追加しないでください。
- `/workspace` は意図的に編集対象として公開した唯一のホストディレクトリです。コード実行から
  作業ツリーを守る設定ではないので、共有・本番リポジトリではなくレビュー用のcheckoutを使ってください。

## 評価

同じモデル・同じ入力・同じ初期作業コピーで、実際に使いたい代表タスクを比較します。
タスクごとに受け入れ条件と実行するテストを決め、成功率、所要時間、モデル呼び出し数、
トークン数、意図しない変更、停止理由を確認してください。上限に達した結果を完成扱いしないでください。

この変更の回帰テストは、リポジトリ直下で次のように実行できます。

```sh
scripts/run_tests.sh \
  tests/agent/test_tool_guardrails.py \
  tests/agent/test_tool_call_guardrail_runtime.py \
  tests/agent/test_verification_evidence.py \
  tests/tools/test_file_tools_ssh_approval_cwd.py \
  tests/tools/test_typescript_lint_offline.py
```

SSH承認テストは一時ホームと実ファイル、lintテストはローカルnpm、
検証証拠テストは一時SQLite台帳を使用します。モデル応答の品質や実Docker隔離の証明とは別です。
