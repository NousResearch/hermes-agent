# Anti-AI Patterns

Use this when a page or screen feels generic, synthetic, or untrustworthy.

## Common Web AI Patterns

- Blue/purple gradient hero with centered headline and two buttons.
- Three equal feature cards with generic icons.
- Repeated "AI-powered", "seamless", "unlock", "empower", "all-in-one" copy.
- Random glowing blobs or glass panels with no product meaning.
- Over-rounded cards everywhere.
- Fake metrics with no explanation.
- Screenshots/mockups that show empty or impossible data.
- Every section has the same rhythm: eyebrow → title → paragraph → cards.
- Pricing/testimonials/logos appear without trust context.
- No error/empty/loading states.

## Common Native Mobile AI Patterns

- Web landing-page layout squeezed into a phone screen.
- Too many cards and gradients instead of native hierarchy.
- Ignoring safe areas/status bars/navigation bars.
- Non-native back behavior.
- Tiny tap targets.
- Static mockups with no keyboard, permissions, empty, loading, or error states.
- Custom controls that fight iOS/Android expectations without a reason.

## Critique Questions

- What is the screen actually trying to accomplish?
- Which parts are generic and could fit any product?
- Where is the strongest proof or product-specific detail?
- What can be removed without hurting the goal?
- Which copy is vague or inflated?
- Which visual effect lacks purpose?
- Which states are missing?

## Repair Moves

- Replace generic claims with concrete user outcomes.
- Replace icon grids with product-specific workflows or proof.
- Use one strong visual metaphor instead of many decorations.
- Add real data and realistic edge cases.
- Reduce repeated section structures.
- Make CTA copy describe an action.
- Strengthen typography and spacing before adding effects.
- For native mobile, return to platform navigation and interaction primitives.
