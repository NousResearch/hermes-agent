# Carousel Architecture

The shape of a carousel and the structures that fit different ideas. A carousel is a sequence —
like a thread, but visual — so the same retention logic applies: every slide must earn the next
swipe.

## The shape

**Cover (hook + promise) → Body slides (the build) → Payoff slide → CTA slide.**

- **Cover** — hooks and promises the swipe; the most important slide; what stops the scroll.
- **Body** — the substance, one idea per slide, maintaining momentum.
- **Payoff** — the summary, the result, the "so what."
- **CTA** — one ask, usually save (carousels win on saves).

## The spine — outline before designing

Outline the **spine** first: the cover's promise, then the ordered slides that deliver it. If you
can't state it in a sentence ("cover promises 5 hooks → one hook per slide → summary → save"), the
carousel isn't ready. The spine is what makes it a cohesive piece instead of unrelated slides.

## One idea per carousel, one idea per slide

- **Per carousel:** one teaching point or one story. Two ideas = two carousels.
- **Per slide:** one headline-sized idea. If a slide needs a paragraph to explain, split it into
  two slides. The constraint *is* the craft — it forces clarity.

## Carousel structures — pick what fits

- **How-to / step-by-step** — "How to X." Cover promises the outcome; each slide = one step; payoff
  shows the result. High save value.
- **Listicle** — "N ways / tips / mistakes." Cover promises the list; one item per slide. The
  easiest to follow and the most save-able.
- **Story / narrative** — a journey with tension. Cover drops in; each slide is a beat; payoff is
  the resolution/lesson.
- **Before → after** — the gap and how to cross it. Cover shows the contrast; slides walk the
  transformation.
- **Myth-bust** — "X things you believe about Y that are wrong." Cover states the provocation; each
  slide flips one myth.
- **Framework / breakdown** — teach a model or deconstruct something. Cover names it; slides are the
  components.

Match structure to idea: a process is a how-to; a journey is a story; a set of tips is a listicle.

## Swipe momentum

Attention leaks at every swipe. Counter it:

- **Progress cues** — "1/7", or visual progress — orient and signal there's more.
- **Forward pulls** — a slide can tee up the next ("but the 3rd one changes everything →").
- **The arrow / swipe cue** on the cover and early slides ("→").

Don't withhold value cheaply; each slide should be useful *and* pull forward.

## Slide count — tight beats padded

Instagram allows up to 20; LinkedIn PDFs more. But the rule is **every slide earns
its place**. A 6-slide carousel that's all signal beats a 10-slide one padded to hit a number. Let
the idea set the count. If you're adding slides to "make it longer," stop.

## Save-optimization

Carousels are saved more than any other format — design for it. Reference-value content (checklists,
frameworks, step-by-steps, swipe-able resources) gets saved and re-opened, which signals quality.
Make the carousel something worth keeping, and the CTA "save this for later" lands honestly.
