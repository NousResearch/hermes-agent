# The TEST framework — evidence, not vibes

Most "testing" on social is vibes: post two things, eyeball the likes, declare a winner, learn nothing.
TEST is the discipline that turns guesses into evidence — and establishes **causation** (the thing
observation alone can't). Setting the target is `goals-and-kpis`; reading the result is
`analytics-and-reporting`; **isolating what moves it is here.**

## T — Target one variable
- Write a clear **hypothesis** ("a question-hook beats a stat-hook on saves"). Change **one element** —
  hook / first-frame / caption / CTA / time / format — and keep **everything else identical.**
- Pick the **one variable with the most leverage** on your KPI (often the hook on short video).

## E — Establish the decision rule first
- **Before publishing**, set the **primary metric + win threshold + guardrail**: *"B wins if reach +15%
  and saves-per-reach not worse."* Anchor the primary metric to the **KPI** (`goals-and-kpis`).
- Pre-committing kills post-hoc rationalizing — you can't move the goalposts to fit the result.

## S — Set controls + sample
- **Control the context:** same platform, format, similar topic/length, similar **posting window.**
- **Run long enough:** ≥7 days (small accounts ~2–4 weeks). Organic can't hit true significance → judge
  on a **~20%+ consistent effect**, not a squeaker. A **tie** means "test elsewhere."

## T — Tally, repeat, scale
- **3–5 paired repetitions** before you call it a "best practice" — one winner is noise.
- **Document** every test (hypothesis/variant/result/learning) in a log. **Scale** proven winners into
  the playbook (`content-recycling`) and feed `social-strategy`; retire what tied/lost.

## The experiment brief a request should fill
```
HYPOTHESIS: changing [variable] will improve [primary metric tied to a KPI]
VARIABLE: the ONE element changing (everything else identical)
CONTROL: same platform/format/topic/length/posting window
PRIMARY METRIC + DECISION RULE: e.g. "B wins if saves/reach +20%" (set before publishing)
GUARDRAIL: the metric that must not get worse
DURATION + REPS: >=7 days (small acct 2-4 wks); 3-5 paired tests
READOUT: native analytics (analytics-and-reporting); log it; scale or drop
```
