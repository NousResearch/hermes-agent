# Godfile Kill Campaigns (5×2×3 blind-witness decomposition)

Orchestrate decomposing multi-thousand-line godfiles into mixin modules via a double-blind multi-wave pipeline, ending in native-interlocked PRs with exact kill-line math. Proven across nine godfiles of NousResearch/hermes-agent (adapter, run.py, run_agent, base, kanban_db, main, tui_server, cli, web_server).

Interlock doctrine for every kill — per-godfile KILL LOCKS posted at kill-start, the epic SHIPPED-standard status rows (open PRs with done+individually-linked shards = shipped; NEVER ranges), poisoned-precedent citation class fixes, and scoreboard format: see `references/kill-locks-and-epic-status.md` (session 2026-08-05, Kill-All-Gods epic #78647).

## Pipeline stages
1. **Sharding**: split the godfile into 5 equal regions; build per-region def bundles.
2. **Wave 1** (blind witnesses ×2 per shard): independent cluster maps → JSON catalogs (names+lines+spans, move/stay/shared, proposed mixin names, slice order, cross-region edges). TEST-file godfiles map tests → observable modules (`tests/<pkg>/test_<subject>.py`) instead of mixins; the schema swaps `methods` for `tests` (name+line) and adds per-cluster `rationale` + `observability` — full recipe in `references/wave1-test-file-cluster-mapping.md` (top-level key set must stay EXACT: an additive `note` key tripped a strict verifier; seam-owner/crosser rules apply to test defs; watch partial-extraction families + module-name collisions across shards).
3. **Wave 2** (blind ×2 per shard): independent re-maps — the cross-check (witnesses must NOT see wave-1 outputs). Pass recipe: clone-as-worktree bootstrap when no local repo exists, blob-hash integrity check (git status is unreliable on Windows shallow clones), write-analysis-first >10KB, evidence greps for def spans / helper lines / external callers / test coverage — see `references/wave2-pass-evidence-recipe.md`.
4. **Wave 3** (blind ×2 per shard): validate every (method, line) claim vs live source via tokenize/AST → VERIFIED/CONTRADICTED verdicts. Classes/string-text are NOT defs; kind-mismatch (NamedTuple class) is benign; decorator-line off-by-ones are real catches.
5. **Agreement merge**: canonical clusters = connected components of the co-membership graph (edge if ≥3/4 witnesses co-located); classification = majority vote; slice order by average witness position; CONTRADICTED methods excluded unless the def exists live. Output: per-shard agreement + `shard-plan.json`.
6. **Extraction w1** (blind implementers ×2 per shard): verbatim extraction into mixin modules; each sandbox = patch + MANIFEST.json + minimal orig/new trees + regression tests.
7. **Extraction w2** (blind adjudicators): cross-check both patches (byte-fidelity, plan fidelity, module conventions, tests, apply, freshness); canonical per cluster → verdict JSONs.
8. **Extraction w3** (validators): apply canonical to a fresh deduplicated worktree; py_compile + shipped tests; VERIFIED verdicts. Canonical may be a COMBINED pair of disjoint w2-accepted patches — apply both sequentially (w1a-then-w1b) in one worktree. Full empirical procedure, pristine-source tricks, and cleanup traps in `references/wave3-witness-validation.md`; combined-canonical recipe in `references/wave3-combined-canonical-validation.md`.
9. **Extraction merger** (local env-parameterized script): pick canonical per region (w3 VERIFIED + w2 not-CONTRADICTED), apply to worktrees, verify, emit manifest.
10. **PR phase**: commit + push to fork, REST PRs with plain-text Related interlock blocks, issue-side edges patched, epic kill-ledger with exact line math.

## Doctrines (non-negotiable)
- **KILL SEQUENCE IS ONE-GOD-AT-A-TIME (Axl, 2026-08-05)**: sharding/mapping
  (waves 1-3, agreements, plans) may run wide across many godfiles; the KILL
  does not. The extraction→merger→PRs→CI-watch sequence serializes per godfile:
  one god's kill runs start to finish (its extraction waves, merger, PRs, CI
  watched to zero failures/pending) before the NEXT god's extraction begins.
  Completed verification material for other gods is STAGED (verified on disk),
  never started. The active kill's CI watch is the gate. A four-wide
  celebration of parallel extraction waves is the anti-pattern.
- **Persist-early**: write the JSON/patch to disk the moment the analysis is done. Lanes die on 429/503 storms; "deaths cost retries, never work" — a lane that persisted before dying delivered (the web_server s5-w1a lane landed after 14 deaths because it wrote first). Corollary (verification-evidence turn): when the harness requires fresh verification evidence for changed artifacts, keep the ad-hoc verify script AND its `.RESULT.txt` log on disk until the parent agent confirms — deleting the passing script immediately re-triggers the "no fresh passing verification evidence" flag (the evidence vanished with the file; s5-w2a, 2026-08-05). **Resume-from-surviving-worktree refills (cli s3, web_server w3, 2026-08-05)**: a dead lane's APPLIED worktree + fidelity checker + sibling's landed verdict survive on disk even when the JSON never wrote. A refill brief for that shard must (a) point the lane at the surviving worktree path explicitly ("RESUME from them, do not restart — git apply already done"), (b) name the sibling witness's landed verdict for INDEPENDENT corroboration, and (c) tell it to recreate fresh if the surviving tree is unusable. A 503-dead lane with 5+ work-actions in its transcript is evidence, not a restart — the refill's first action is inventorying what the dead lane left.
- **Reduced-scope ordering**: extract the 1-2 highest-agreement clusters FIRST and write the patch immediately, then extend if the API survives.
- **EXTRACT ALWAYS**: overlap goes in MANIFEST `interlocked_with`, never skipped. A dedup-reading CONTRADICTED verdict is superseded by extract-always (canonical-with-interlock).
- **Space discipline**: minimal orig/new trees only; NEVER full-repo tar copies (one filled the disk to 99% → ENOSPC); deduplicated git worktrees for validation; validate trees are replicas and removable.
- **Baseline-verify every suite failure**: a failing test must be checked against the LIVE repo before believing it. Identical failure set = env-dependent (compression hooks, nous-token presence, Anthropic client mocks, real-threading timing). Once-pass-once-fail under load = flake, not regression. Fails only in the patched tree = real finding. Concrete signature (web_server, 2026-08-05): a leaked `HERMES_SERVE_HEADLESS=1` in the parent shell makes `mount_spa` take the no-frontend path → dashboard/theme tests that GET `/chat` 404 (`test_serve_index_injects_bootstrap_for_user_theme` failed this way in a w2 tree; baseline on the unmodified live repo with the var unset passed 15/15). Check `echo $HERMES_SERVE_HEADLESS` and `unset` it before any dashboard/theme/console test run — the 404-on-/chat signature is the tell, and web_server's mount_spa reads the var at call time so even a working extraction fails under it.
- **Byte-fidelity**: moved bodies verbatim (difflib 0); reconstruction = orig minus slices + import block; class attrs stay; module-level constants used by tests stay.
- **Cross-tree validation**: run witness A's tests against witness B's tree AND vice versa — isolation passes miss seam-strategy divergences (e.g. main-namespace routing vs module-scoped binding; the patching contract is the live behavior).

## KILL LOCKS — the per-godfile interlock doctrine (Axl, 2026-08-05)

Every godfile kill carries a PERMANENT interlock record — not just PR↔issue links. "Never let them forget how bad it used to be" is a standing campaign rule:

- **Every godfile gets its own KILL LOCK** posted on its per-file issue at KILL-START (discord/slack precedent), linking BOTH ways: every shard PR → the lock; the lock → the former whole (line count, what it was), EVERY problem issue the godfile caused (the stall bugs, security issues, FIPS crashes, tracking chaos), and EVERY open mess-fixer PR still fighting that surface.
- **Every lock is indexed by the Kill All Gods meta-issue** (#78647). The meta-issue carries a lock index table (godfile | lock location | kill status); every shard PR body carries the lock link + the mess list + the fixer roster. Shards, locks, and the meta-issue form the closed chain — no god dies unremembered.
- **Lock file shape** (`C:/tmp/tg-campaign/locks/LOCK-<god>.md`, then posted verbatim): former whole (line count + mess issues with links), the kill table (slice | PR | module | window | evidence), the open-PR fixer roster, and the lock chain. Full posting sequence in `references/kill-lock-interlock.md`.
- **Post at kill-start, update at every ship**: analysis phase posts the lock with TBD shard rows; each shipped slice PR adds its row + lock-link comment; the per-file issue gets a scoreboard (slice | PR | module | delta | evidence per the epic's method item 4).
- **Interlock is BOTH ways and covers the mess, not just your PRs**: coordination comments go on the colliding/related PRs (auth-cluster owners, overlapping extractors, the campaign-level blocker like cli's #12355), each naming the lock + the land-order proposal. "Interlock means all related PRs and issues, not just the ones I wrote."

## Epic status rows — the SHIPPED standard (Axl corrections, 2026-08-05, capitals)

- **SHIPPED is the standard, not OPEN, and OPEN PRs ARE shipped work for the epic — as long as the shards are all done and individually linked.** Three corrections in one session, in order: (1) "landing on main is not the issue if the shards are DONE" (merge state is not the measure); (2) "ENFORCE SHIPPED AS THE STANDARD, NOT 'OPEN'" — every status row must read `**SHIPPED** — N slices done`; (3) "AS LONG AS THE ACTUAL SHARDS ARE ALL DONE AND INDIVIDUALLY LINKED". An open PR whose shards are complete and whose body links every member counts as SHIPPED for the epic's purposes — do NOT write "merge pending" or "written & reviewable" as a downgrade of shipped work.
- **NEVER list a range of PRs. LINK EVERY SINGLE ONE** (capital correction). `#79123-#79129` is forbidden; the row lists `#79123 #79124 #79125 #79126 #79127 #79128 #79129`. Same shape for every row: `**SHIPPED** — N slices done, all individually linked: <every #N>`. Audit with `grep -cE '#[0-9]+-#[0-9]+'` — zero range rows is the receipt (run.py's 38-shard row was the canonical form: `**SHIPPED** — 38 shards done, all individually linked: #77376 #77433 ...`).
- **Verify epic status claims against live reality before believing them.** The run.py row claimed "in progress (~2,300L shipped across 24 PRs)" — reality: run.py was still 26,986 lines on main (size ~1.3MB) and 0 of 36+ shard PRs had merged. The claim conflated "PRs written" with "landed". When a status row quotes line counts or shipped amounts, re-derive: `gh api .../contents/<file>` size, `gh pr view <n> --json state,mergedAt` per PR, and the PR count. Correct the row to the verified number, then apply the SHIPPED framing.

## Swarm-operations traps (delegation route, quota, disk — each cost a wave)

- **Pinned delegation JWT expires while the runtime's auth.json stays fresh**: the delegation block in `profiles/<p>/config.yaml` carries a PINNED api_key; the runtime refreshes `auth.json` independently. When the pinned JWT expires, children fail the primary → fall through to the fallback chain → a dead fallback (exhausted billing) turns every lane into an identical 402. Fix at the mechanism: refresh the delegation api_key from the CURRENT `auth.json` access_token (runtime keeps it live), prune fallback providers without usable credentials (`hermes auth list` = ground truth), then ONE refill dispatch. The parent chat survives on the runtime path — that's the tell.
- **Disk-full cascade masquerades as `max_iterations`/throttle**: at ≥95% disk, session-storage writes fail and sandbox `mktemp` fails — lanes die with misleading "iteration budget exhausted" in ~12s, indistinguishable from quota death. Diagnose with `df -h /c` BEFORE and DURING waves; cache-only maintenance exception (disk >90%) = age-bounded `find . -maxdepth 1 -type d -name 'pytest-*' -mmin +120 -exec rm -rf {} +` — NEVER delete dirs the live lanes touched in the last 2h (48 fresh dirs = in-use).
- **Dispatch width must fit the quota window — probes survive, bursts die**: 1-call probes and 2–4 lane waves run to completion; 7+ lane bursts all die in ~12s (shared key per-minute quota; each dead lane burns 1 call + 3 retries = 4 calls, so re-dispatching into the exhausted window makes it worse). Calibrate: single-lane probe first (READY = route live), then 2–4-wide waves, NEVER dispatch a new batch while one is in flight (overlapping batches double the first-call burst). After a burst death, drain the window (~5 min of no dispatches) before retrying.
- **Commit-lane, never re-implementer**: when an implementer dies POST-work but PRE-commit (worktree shows `M godfile` + `?? new modules`), the work is on disk — dispatch a verify+commit lane (review diff, run tests, commit DCO, report SHA or exact failure; explicitly "do NOT redo, do NOT fix — report"). Re-running the implementer discards the finished extraction. Same for test-bug-only blockers: a lane that fixes TESTS (never the extraction) unblocks the commit.
- **Write-early + progress files for throttle resilience**: analysis lanes write the deliverable BEFORE deep verification (a throttled lane that wrote first delivered — the persist-early rule); implementer lanes write `R<N>-S<N>-PROGRESS.md` on throttle (files created, commands run, next step) so the next lane resumes from disk, never from scratch.
- **Implementer-level collision gates**: extraction briefs MUST instruct implementers to `gh pr diff <open-pr> | grep -A2 'diff --git.*<godfile>'` against their window BEFORE extracting, and to STOP + write a progress/collision file + report on any hunk inside the window (slack R2 #79612, slack R4 #77547/#78393/#78413, discord R1 #75735 all stopped themselves correctly). FILE-LIST coordination: retarget, credit, never duplicate — land-order proposal on the colliding PR, preserved golden sha for the rebase.
- **Seam-test files must carry the `test_` prefix**: CI collects via `rglob("test_*.py")` — a seam test named `web_server_gateway_topology_seam.py` is NEVER collected and its regressions silently never run (the CI-collection class bug caught by two independent blind reviewers). Name them `test_web_server_*_seam.py`; a class fix across sibling branches is one coordinated wave, not six patches.

## Pitfalls (each cost real debugging time)
- **Merger `patch_path` must prefer `*-repo.patch`** — the raw `*-impl-w{N}.patch` may be a full-tree CONTRADICTED diff that DELETES the godfile wholesale (a 1.3MB variant did; the 16KB canonical applied clean). Candidate ORDER is the bug. Verify with: apply patch to an orig copy, `diff -rq` vs new.
- **Branch-name collisions**: the first campaign's shipped PR branches own `gfg/extract-*`; later godfiles need campaign-scoped prefixes (EX_BRANCH_PREFIX env).
- **Stale worktree registrations** crash `cwd=wt` subprocesses (WinError 267) — `git worktree prune`; git on Windows needs native `C:/` paths (rejects MSYS `/c/`).
- **MSYS worktree path SILENT-mangles instead of rejecting (slack r5b, 2026-08-05)**: `git worktree add /c/tmp/ws-sl-r5b <sha>` in git-bash does NOT fail — it silently creates the tree at `C:/c/tmp/ws-sl-r5b` (the leading-slash path is interpreted as repo-relative `c/tmp/...` under the drive root). The add reports success ("HEAD is now at …") while the subsequent `cd /c/tmp/ws-sl-r5b` fails. Fix: pass NATIVE paths (`C:/tmp/ws-sl-r5b`); if already mangled, `git worktree remove C:/c/tmp/<name> --force && git worktree prune`, then re-add. Verify with `ls` + `git rev-parse HEAD` + `wc -l <godfile>` in the fresh tree.
- **Windows 32K cmdline** (WinError 206): don't pass every test file as pytest args — scope to the region's shipped tests (`test_s{region}_*`).
- **Store python breaks on long paths** for py_compile — use the repo venv python.
- **Verdict schemas vary (EIGHT proven shapes — the merger parser must handle all)**: (1) `patch_verdicts[{patch, verdict}]` LISTS; (2) per-cluster `canonical`/`winner`/`source` fields; (3) top-level `verdict`+`canonical`/`canonical_patch`/`recommendation`; (4) `adjudication` dicts (w2b) and `canonical_merged_patch` keys (w2a); (5) `patch_verdicts` as a DICT keyed by witness (`{w1a: {...}, w1b: {...}}`, cli s3-w2a) — iterating it as a list yields STRING keys and crashes `AttributeError: 'str' object has no attribute 'get'` at `pv.get("patch")`; (6) NO `patch_verdicts` at all — `overall_verdict` + `cluster_adjudications` (cli s3-w2b), plus w3 `verdict` as a DICT whose joined string-form asserts PASS/VERIFIED (cli s3-w3a/w3b: `{"canonicals": "PASS — ...", "c12_repair": "VERIFIED — ..."}`); (7) verdict STRINGS with a `"PASS - <details>"` PREFIX rather than the exact literal (web_server s2-w3a/s3-w3a: `"PASS - w2-adjudicated canonical w1b ..."`) — exact-match `v in ("PASS", ...)` silently drops them and the region resolves wrong; and `canonical_patch` as a DICT of `{path, sha256, raw_path, raw_sha256, ...}` fields (web_server s2-w3b) — `.get("patch", "")` on it yields the dict repr, so witness extraction must `str(cand)` the whole value; (8) `clusters` entries as bare STRINGS (web_server w2) — `cl.get("canonical")` crashes `AttributeError: 'str' object has no attribute 'get'`; isinstance-guard every list iteration. Fix pattern: branch on the actual types — dict-keyed patch_verdicts → iterate `.items()` with `pv.get("verdict")`; `overall_verdict`/`cluster_adjudications` → scan per-cluster canonical/winner/witness fields, fall back to witness-name presence in the overall verdict text; dict verdict → `" ".join(str(x) for x in v_raw.values())` and scan for PASS/VERIFIED + witness names; STRING verdicts → PREFIX-match (`v.startswith("PASS") or v.startswith("VERIFIED") or v.startswith("CANONICAL") or "UNION" in v`), never exact-equal; canonical candidates → `str(cand)` regardless of dict-or-str; every list-of-dicts iteration → isinstance guard. Verdict strings are NOT always the literal `"VERIFIED"` — accept the PASS family (`PASS`, `PASS_WITH_NOTES`, `PASS_WITH_GAPS`, `PASS_WITH_DISCREPANCY`, and anything starting `CANONICAL PATCH`) or the region stays BLOCKED with "no admissible patch" (run_agent s2 was blocked until the parser accepted `"CANONICAL PATCH (s2-w1a) PASSES ALL HARD..."`). After any parser change, re-run the merger — and keep the pre-flight pick() battery as the regression test (it caught both the dict crash and the s1 union block). Ninth shape (tui_test s3-w2a, 2026-08-05): the MAPPING-phase cross-check verdict (`w2-cluster-map/1.0`) has NO cluster-membership enumeration at all — only `coverage_verification` + `disagreements[]` + `required_fixes`. A claim-counter must not fabricate per-catalog claims for it; count the disagreement-set names (23 of 85) and validate its "canonical N, exactly once" coverage claim through the canonical-set checks instead. Full wave-3 recipe for this family: `references/wave3-test-file-cluster-validation.md`.
- **Idempotent apply**: check `git status --porcelain` first; skip already-applied worktrees; never re-apply over dirty state (repeated applies corrupt — staged `D` deletions appeared).
- **Test-authoring bugs in shipped regression tests** (baseline-reproducible, fix the TEST not the code): `object()` can't take attributes; the stub must match the method's real accessor (`_session_state` vs `_peek_session_state`); class-level descriptors (SessionFieldView) can't be stubbed via setattr; assertions must match LIVE-verified verbatim semantics — probe the live method before aligning the test.
- **Overlay collection crash**: a PYTHONPATH overlay whose tree contains a `tests/` dir shadows the repo's tests package → collection crash at startup (anyio import failure) — an INVALID reproduction, not evidence.
- **Patch-freshness drift**: lanes' final edits outrun their patch writes; the w2 freshness check (regenerate `diff -ruN orig new`, compare) catches it; regenerate to align. Fastest decisive check for git-format patches: `git hash-object sandbox/orig/<file>` vs the live blob, matched against the patch's `index <old>..<new>` line — byte-identical orig + matching index = fresh. For `diff -ruN` patches, `git apply -p1` strips the `orig/`/`new/` first component (works), but the patch is only as fresh as its orig tree: if live moved even a few lines OUTSIDE the moved regions, whole-file hunks die with `error: while searching for` (cli s1-w1a: 4-line drift at an unrelated class method killed a whole-file hunk). A stale-but-content-correct patch still needs regeneration; verify its content against current live independently (see the w2 checklist: PYTHONPATH shadow run).
- **Apply-mode for `orig/`/`new/`-prefixed raw patches: plain `git apply` WORKS, `-p2` FAILS** (cli s2-w1a, verified): git's a/b-prefix heuristic maps the differing first components to repo-relative paths, so `git apply <raw patch>` resolves `orig/cli.py`→`cli.py`, `new/hermes_cli/x.py`→`hermes_cli/x.py`; `-p1` also works; `-p2` strips both components and dies with `unable to find filename in patch at line 3`. The embedded `Binary files ... differ` (__pycache__) header lines are inert. Confirm resolved targets with `git apply --stat` (must show repo-relative paths), and record the apply mode in the w2 verdict so the merger doesn't guess.
- **Stale witness orig is tolerable when the shard region is intact** (cli s2-w1b): witness orig blob ≠ HEAD blob (4-line drift at line 10252, OUTSIDE shard region 3697-7392). Rules: (1) diff only the shard's line region — must be byte-identical; (2) the patch's `index <old>..<new>` line must equal `git hash-object <witness orig>` (internal consistency); (3) context lines all lie in the unchanged region, so `git apply --check` against live passes. Note it in the verdict as a minor finding, not a rejection.
- **Minimal validation replicas MUST include conftest.py files** (cli s2-w2b): copying only cli.py + package dir + selected test files into a replica tree omits `tests/conftest.py` and each touched dir's `conftest.py`, whose autouse fixtures reset module caches and sandbox env state. Without them tests fail spuriously — produced TWO fake "regressions" (stale skill-scan cache → `resolve_skill_command_key` returned None; leaked gateway session vars → secret-capture callback fired) that cost a full root-cause cycle; the replica was the bug, not the patch. Copy `tests/conftest.py` + `tests/<dir>/conftest.py` for every dir you touch, then baseline-verify the same suites on the live repo: failure sets must match exactly.
- **Byte-fidelity via AST line-slicing, not `ast.get_source_segment`** (cli s2-w2b): on 10K+-line godfiles, `get_source_segment` per def is O(n²)-ish and times out (>300s); slice `"\n".join(src.split("\n")[node.lineno-1:node.end_lineno])` instead — instant. When allowing lazy-import shim lines, strip shims ANYWHERE in the body (they're often inserted mid-body, e.g. after the first statement, or followed by an added blank line), not just at the top — top-only stripping falsely flags otherwise-verbatim methods.
- **CRLF patch corruption looks like a whole-file rewrite**: if the patch's first hunk is `@@ -1,N +1,M @@` and the patch is 10-100x bigger than the expected minimal diff, check EOLs (`file orig/x.py new/x.py`) — one tree CRLF, the other LF → GNU diff rewrites every line (cli s1-w1a: a 6-method move produced a 1.7MB patch). `git apply --check` can still PASS whole-file hunks (no context matching needed), and the applied worktree then shows the ENTIRE godfile as modified. Verify the true content delta with `git diff --no-index --ignore-cr-at-eol --stat orig new`. The committed patch may also be post-hoc LF-normalized (≠ raw `diff -ruN` output; size gap ≈ #added-lines × 1 byte) so the validation worktree won't reverse-apply the committed patch. Verdict: content may be fine, artifact must be regenerated as a minimal LF diff.
- **PYTHONPATH shadow needs `__init__.py`**: injecting a stale witness's new modules next to the LIVE repo to re-run its tests (content-validity check for a stale patch) silently fails with `ModuleNotFoundError` unless the shadow tree's package dirs carry `__init__.py` — otherwise `import hermes_cli.cli_content_scrub` resolves the REAL repo package (found later on sys.path? no: package resolution picks the first `hermes_cli` with `__init__.py`, which is the repo's) and the injected submodule never loads. Distinct from the overlay-collection crash pitfall (that one is a `tests/` dir shadowing); here the fix is `touch hermes_cli/__init__.py tests/__init__.py tests/hermes_cli/__init__.py` in the shadow tree.
- **Empty `__init__.py` markers** in new/ trees are omitted by GNU diff — a cosmetic gap, recreatable at merge time.
- **W3 worktree from the wrong ref**: the live repo may sit on a PR branch with unrelated local mods and a DIFFERENT godfile md5 than the wave-2 baseline. Always `git worktree add ... main` (the pristine ref), md5-verify the worktree's godfile against the w2 record BEFORE applying — validating the live working tree gives false failures.
- **Pristine source after apply**: once the patch is applied the worktree's godfile is modified — for byte-fidelity comparisons use `git show HEAD:<godfile>` (read-only git object), not the worktree file.
- **Same-named worktrees across campaigns**: `wt-s5-w3b` exists under godfile/main, godfile/kanban_db, godfile/cli, ... — a bare `git worktree list | grep <name>` matches other campaigns' trees. Confirm removal with the full unique path; never remove/prune a tree you didn't create.
- **Generic artifact filenames collide in the shared wave dir (main.py s2-w3b)**: parallel witnesses share `extraction/w3/` and generic names like `check_fidelity_w3b.py` are a race — a sibling's same-named file silently REPLACED this witness's checker mid-run (signature: the script's output suddenly references another shard's worktree/methods, or a bizarre FileNotFoundError naming a sibling's `wt-s*` path; the checker had passed 15/15 minutes earlier). Shard-suffix EVERY artifact you write into a shared dir (`check_fidelity_s2_w3b.py`, `s2-w3b.json`), verify a file's content is yours before editing it, and never delete a same-named file you didn't create (it is the sibling's evidence). `ls -la` mtimes: an artifact's timestamp between your successful run and your next listing is the overwrite window.

## Extraction w2 adjudication (stage 7, cli s1-w2b / s4-w2b recipes)
- **Check coverage FIRST — it is either disjoint or overlapping, and the adjudication differs**:
  - *Disjoint* (cli s1: w1a c2+c3, w1b c10+c11+c18 — zero overlap): per-cluster canonical = the covering witness's patch, validated independently; there is no patch-to-patch comparison to make.
  - *Overlapping / head-to-head* (cli s4: BOTH witnesses did c8+c6 with the same 30 top-level + 10 nested method set): the comparison is direct and decisive. The canonical witness is the one that wins on byte-fidelity + conventions, NOT the first one checked. A cluster skipped by BOTH witnesses with the same module-global-invariant reasoning is double-blind agreement — record the skip as corroborated, not just accepted.
- **Head-to-head decisive criteria (s4 case — all real, all witnessed)**:
  1. **Blank-line separator fidelity** (the #1 differentiator): a witness that strips the trailing blank separator after every moved method produces mixin methods jammed together with ZERO blank lines between them (PEP8 violation, breaks the repo's one-blank-line convention). The faithful witness preserves them and is byte-identical to live. Check: `for each def, gap = lines[prev_def+1:def]; missing if gap[-1] != ""`.
  2. **In-class section comments travel with the cluster**: a witness that leaves the `# ==== Foo methods ====` header orphaned in cli.py mislabels the NEXT (staying) section and usually leaves a double blank at the seam; the faithful witness moves the header into the mixin and leaves a clean seam (single blank, next section follows directly).
  3. **MRO order between NEW mixins is irrelevant** — verify by set-intersection of method names across ALL mixins (existing + new); if empty, either class-line order is fine (keep the canonical witness's).
  4. **Last-method-of-file trailing blank is an EOF artifact, not a fidelity loss**; a comment block that follows a moved method but belongs to the NEXT section (e.g. wake-word header after `_disable_voice_mode`) is correctly left in cli.py — both are extraction false positives, verify before believing a "DIFFERS".
  5. **Re-export comment convention matches the godfile's existing style** (web_server s5, 2026-08-05): the file's established re-export blocks carry `# noqa: E402,F401 — legacy re-exports; tests call these via web_server.<name>` (whatsapp_onboarding block); a witness copying that comment verbatim beats one inventing its own `# noqa: E402` comment. When bodies are byte-identical between witnesses, convention match + blank-line fidelity decide the canonical (c2 → w1b).
  6. **Lazy-shim name colliding with a function parameter is a false-positive trap, not a rename** (web_server s5): `mount_spa(application: FastAPI)` lazily imports the module-global `app` (used for `app.state` reads) while the parameter stays `application` — legitimate, NO rename happened (live def at 15529 already used `application`). Before declaring a "parameter renamed" defect, grep the LIVE def line and the body's usage of both names; a shim importing a module-global is correct when the body's other references use the differently-named parameter. Same class as the CRLF whole-file false positives: verify against live, then believe.
- **Scoped def-block extraction (byte-fidelity script)**: key blocks by `(name, parent)` where parent tracking must treat `class` as a boundary too — a module-level def before the class otherwise becomes the "parent" of every class method. Duplicate nested names across parents (`_panel_box_width` exists 3× in live with different signatures) make name-only matching produce false DIFFERS. Normalize away allowed lazy-import lines (`^\s*from cli import .*$`) before comparing.
- **Adjudicate conventions against the MERGED precedent, not opinion**: find the extraction commit (`git log --all --diff-filter=A -- hermes_cli/cli_commands_mixin.py`) and `git show <commit> -- cli.py` to confirm: one blank line between mixin methods, no section comments inside mixin classes, lazy `from cli import ...` discipline. The witness matching the merged precedent wins.
- **Count defs to verify MANIFEST claims**: `^    def ` = top-level, indented = nested; w1b claimed "41 moved (30+11 nested)" but actual = 40 (30+10) — doc-only miscount, catch it by counting, not trusting.
- **Validate in a fresh worktree at CURRENT HEAD, not the witness's stale one**: `git worktree add --detach <w2-path> HEAD && git apply --check && git apply && pytest <the 2-4 touched test files> --basetemp` with the repo venv python; then `git worktree remove --force` + `git worktree prune`. A witness's own validation worktree may sit on an OLD HEAD (cli s1-w1a's wt was at f40fbcf409 while live had moved on) — useful for its own tests, useless for apply-freshness.
- **Per-witness checklist**: byte-fidelity (extract top-level blocks from live, assert verbatim in mixin AND absent from new cli.py; nested defs are NOT top-level — either diff the enclosing parent block or check the indented `def` inside it; block boundaries can swallow the NEXT section's header comments, so diff the block when containment fails before believing a mismatch); plan fidelity (cluster→module + method list vs shard-plan); module conventions (own import block, logger name = the DESTINATION dir's convention — cli mixins use `getLogger(__name__)`, web_routers modules use `getLogger("hermes_cli.web_server")` — verify sibling modules in the destination dir, a blanket rule false-flags the other; moved constants re-exported); tests; `git apply --check`; freshness.
- **Monkeypatch-transparency is the decisive head-to-head discriminator when fidelity+tests tie (web_server s2-w2a)**: both witnesses byte-identical and suite-green, yet one had a LATENT regression — its moved modules direct-imported config helpers (`from hermes_cli.config import load_config`) while the other bound them via `late()` proxies (cron.py precedent). Adjudicate structurally: enumerate moved bodies' in-module helper calls → classify each binding (direct import = bypass, late() = observed) → check test-patched moved names are re-bound (`_impl` + `late()` + `_x_impl as _x` re-export, or def kept in web_server + late proxy). Full recipe incl. the AST name-map overwrite trap (later `Assign` rebinds overwrite FunctionDef entries → false DIFFERS; track defs and assigns separately, match `{name}_impl`) and the full-suite baseline protocol (save applied file → revert → run → restore, removing untracked new files first or `git apply` dies all-or-nothing): `references/extraction-w2-monkeypatch-transparency.md`.
- **Decorator-strip normalization for byte-fidelity when the extraction rewrites route decorators (web_server s3-w2a)**: the sanctioned `@app.`→`@router.` rewrite means bodies are byte-identical EXCEPT decorator lines. Instead of listing per-method exceptions, strip leading decorator + blank lines from BOTH the live segment and the module segment, then exact-compare the bodies — "13/13 identical (body)" becomes a one-pass claim. `strip_decorators(seg)` = drop lines while `lstrip().startswith("@") or line.strip()==""`. When decorators differ but bodies match, still verify the ROUTE PATHS didn't change (`@app.get("/x")` vs `@router.get("/x")` — path must be identical; grep the decorator lines separately).
- **Standalone-import probe — the circular-import trap is a w2 convention discriminator (web_server s3-w2b)**: after byte-fidelity, run `python -c "import <new_module>"` on EVERY extracted module BEFORE importing web_server. In-tree web_routers modules (whatsapp, git, sessions, ...) import standalone fine — that is the baseline. A moved module that fails standalone import has a convention defect even when bodies are byte-identical. Two verified shapes: (1) a top-level module doing `from hermes_cli.web_server import app, _apply_main_model_assignment` at module top (its own test file works around it by importing web_server FIRST — the workaround in the test is the tell) → `ImportError: cannot import name ... from partially initialized module`; (2) module-level `_X = late_attr("_X")` — `late_attr` is EAGER (reads `web_server.<name>` right now), so at router import time it forces the web_server import, whose bottom re-export block re-imports the router mid-load → circular. - **`diff -ruN` subset-tree patches silently DELETE unrelated live files (web_server s3-w1a c1-only)**: a reduced-scope patch built from a subset tree (e.g. `c1only/` where orig has file X but new/ omits it) emits a FULL-FILE DELETION of X that `git apply --check` PASSES (the file exists at base and matches, so the deletion is checkable). w1a's c1-only patch deleted `tests/hermes_cli/test_whatsapp_onboarding.py` (119 lines, live at HEAD, unrelated to c1). Also re-verify manifest test counts by counting `def test_` in the shipped test file (w1b manifest claimed 16, actual file has 12).
- **`git apply --check` vs HEAD index vs live worktree are DIFFERENT checks (web_server s3-w2b)**: when the live worktree carries an uncommitted parallel-lane fix (here: `_write_platform_enabled` removed from the whatsapp re-export list), bare `git apply --check` validates against the WORKTREE while `--cached` validates against the HEAD index. - **Shared w2 dir: sibling-shard worktrees may already exist — suffix yours, never remove what you didn't create (web_server s3-w2b)**: the w2a witness (different shard) had already created `wt-w1a`, `wt-w1a-c1`, `wt-w1b` in the shared `extraction/w2/` dir and patched one with its own extraction. Same class as the generic artifact-collision pitfall; extends it to worktrees.
- **Moved module-state + re-export seam**: when module-level state (e.g. `_active_worktree`) moves with a re-export, the staying code's `global X; X = ...` rebind diverges from the mixin's copy. Verify the divergence is unobservable by grepping ALL callers of the reader (if every call passes the state explicitly, fine — cli s1: `_cleanup_worktree(wt_info)` everywhere, no no-arg callers).

## Post-commit blind re-review pass (discord + slack waves, 2026-08-05)

The wave AFTER the per-slice branches are committed locally (worktrees clean, NOT pushed) is a READ-ONLY re-review of every slice against its consensus contract. Full working recipe (checker code, hunk-parse, identity probe): `references/blind-rereview-pass.md`. Traps that each cost real reruns:

- **Derive moved-member lists from the pin window, never guess them.** AST-collect defs whose lineno falls in the consensus line range (walk the CLASS body for mixin slices — top-level-only scans MISS class methods, the #1 checker bug this session). Insertion shape varies per slice: R3 = import alone (mid-body, after `async with`), R4 = import + trailing blank line. Normalizer: skip the import line (both `from plugins.platforms.discord.adapter import` AND `from .adapter import` forms) and, when present, the immediately-following blank — but never eat a blank after a non-import line (over-strip guard). Extends the main.py s2-w3b lazy-strip pitfall with the removal-vs-blank and trailing-blank shapes.
- **Run a mutation-sensitivity positive control.** Inject a body edit into one moved member in-memory and assert the checker flags it. Proves "N/N verbatim" verdicts are not vacuous (a checker that normalizes too greedily passes anything).
- **Collateral audit via `git diff -U0` hunk parse.** Parse deleted old-line ranges; every consensus-window line must be covered; allowed extras are EXACTLY: import lines, class line, trailing blank boundary (898/2746/6466/9798).
