# Feature specifications

All new behavior-changing work after the brownfield cutover belongs in numbered feature directories.

Minimum full-project flow:

`DRAFT product spec.md -> ACCEPTED product -> Ponytail architecture plan.md -> ACCEPTED architecture -> Ponytail tasks.md -> ACCEPTED complete map -> implementation -> release -> product readback`

Hermes `todo` mirrors the active canonical task. New decisions open a patch/minor/major version instead of being rejected to preserve stale documents.

Historical artifacts are not rewritten as if this process had existed earlier.
