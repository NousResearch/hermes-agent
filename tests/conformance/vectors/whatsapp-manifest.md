# WhatsApp conformance vector manifest

Campaign: **WhatsApp Feature Parity** (#79890), Phase 1 — Quick win.

`tests/conformance/vectors/whatsapp.json` is generated by
`scripts/generate_conformance_vectors.py`. The file is committed and is
the executable spec the connector conformance runner asserts against.

This manifest documents what each vector locks (what behavior it pins),
so reviewers can see what a divergence in a vector actually means for
WhatsApp users.

> Don't hand-edit the vector JSON. To add/change a vector, edit the
> shared corpus in `scripts/generate_conformance_vectors.py` (GRID /
> SCAR / ADVERSARIAL) and run the generator, then commit the regenerated
> files together with the script change (see
> `test_committed_vectors_match_regeneration`). The same corpus feeds
> all four platforms; each oracle renders the corpus independently, so
> a single text input may have different `native_output` per platform.

## Oracle

`gateway/platforms.whatsapp_common.WhatsAppBehaviorMixin.format_message`
(invoked `self`-free — asserted by
`tests/conformance/test_vector_generator.py::test_oracles_importable_and_self_free`).

The renderer:
1. `_sanitize_outbound_text` strips zero-width format chars
   (U+200B, U+2060, U+2063, U+FEFF) and normalizes odd unicode spaces
   (U+00A0, U+1680, U+180E, U+2000–U+200A, U+202F, U+205F, U+3000) to
   ASCII space.
2. Protects fenced code blocks (` ```…``` `) by placeholder.
3. Protects inline code (`` `…` ``) by placeholder.
4. Converts markdown italic `*text*` → WhatsApp `_text_` (lookaround
   guarded so list bullets and `**bold**` are not matched).
5. Converts markdown bold `**text**` and `__text__` → WhatsApp `*text*`.
6. Converts markdown strikethrough `~~text~~` → WhatsApp `~text~`.
7. `_text_` is already WhatsApp italic — left as-is.
8. Converts markdown headers `# Title` → WhatsApp `*Title*`, stripping
   redundant `*…*` wrapping from step 5.
9. Converts markdown links `[text](url)` → `text (url)`.
10. Restores protected code.

## Expect semantics (per vector `expect` field)

| expect     | runner behavior                                                                 |
|------------|--------------------------------------------------------------------------------|
| `parity`   | connector render must byte-equal `native_output` (WhatsApp is a same-dialect port) |
| `divergent`| connector and native intentionally differ; assertions check the documented behavior named in `note` |

The default for all WhatsApp vectors is `parity`.
Telegram vectors default to `semantic` (HTML vs MarkdownV2); WhatsApp does not use that lane.

### ADVERSARIAL (9) — pathological and renderer-internal inputs

| id                       | locks                                                                                            |
|--------------------------|--------------------------------------------------------------------------------------------------|
| `media-tag`             | `MEDIA:` paths must pass through unchanged.                                                    |
| `unclosed-fence`        | Unterminated ```` ```python\n… ```` — divergent: WhatsApp degrades without dropping content, but the rendering is unspecified (never a 400-equivalent). |

| `whitespace-only`       | Whitespace-only input survives sanitize (no formatting catastrophe).                          |

| `triple-markers-alt` (new) | `***bold italic***` (closed-form triple-marker) — WhatsApp renders as literal `**bold italic**` (the bold step 5 leaves the wrapping `**` on each side because italic step 4 consumed the middle `*`). ## What changed in this phase (Phase 1 — Quick win)

Added 9 vectors to the shared corpus in `scripts/generate_conformance_vectors.py`,
lifting every platform from 44 → 53 vectors. The 9 new WhatsApp-relevant
vectors (all marked `(new)` above):

- `underscore-bold` (grid)
- `bold-inside-word` (grid)
- `link-with-bold-text` (grid)
- `code-with-bold-markers` (grid)
- `italic-header` (scar)
- `two-inline-codes` (scar)
- `sanitize-zwj` (scar)
- `sanitize-nbsp-var` (scar)
- `triple-markers-alt` (adversarial)

They lock:

- **Alternative bold syntax** (`__bold__` → `*bold*`), previously untested.
- **Mid-word bold markers** — `*` placement around a word rather than at word boundaries.
- **Bold inside link display text** — format steps must run before the link de-references.
- **Inline code containing `*`/`**`** — code protection must happen before the bold/italic substitution.
- **Italic inside a header** — the header-to-bold step wrapping the italic-converted `_…_`.
- **Multiple inline codes per line** — placeholder substitution ordering under several placeholders.
- **Zero-width-character sanitization** — `_sanitize_outbound_text` selectively strips U+200B / U+FEFF.
- **Narrow-space normalization** — odd unicode spaces (U+202F, U+200A) normalized to ASCII space.
- **Closed-form triple markers** (`***b***`) — pairs with existing `triple-markers` to lock both open and closed variants.

These close gaps surfaced in the Phase 0 parity matrix:
`docs/whatsapp-parity-matrix.md` (Lane S1 — Core messaging, "Text send /
markdown / code blocks").

## Regenerating

```
python scripts/generate_conformance_vectors.py
# or
python scripts/generate_conformance_vectors.py --out /tmp/vectors/
```

Committed vector files must reproduce from the generator (locked by
`tests/conformance/test_vector_generator.py::test_committed_vectors_match_regeneration`).
Drift means a renderer changed without regenerating the vector file —
the test fails loudly.
