# ADR 0005 — Tracked runtime state discovered in repo-reorg audit

**Date:** 2026-07-24
**Status:** Proposed
**Deciders:** Kensei (recommendation), Sahil (final)

## Context

The repo-reorg audit (Step 1 of the 2026-07-23 handoff) found 33 files in git that
violate the spec's hard rule **"No runtime state in git. Memory, sessions, logs,
caches — gitignore, never commit."** They were committed in error from running
agents in-tree during earlier development.

## What was found

All 33 files are listed below. They are categorized, with a recommended action
for each. None of them are required for the repo to function — they are
caches/backups/state that should be regenerated on demand.

## Recommendation

All 33 files are safe to `git rm --cached` (untrack without deleting the
working tree file). They will continue to exist on disk and on the VPS at
`~/.hermes/`, but will not be part of the repo.

A separate commit (proposed: commit 1.5, between the .gitignore update and
the plugins reorg) should do the untrack. This ADR is filed first so the
decision is captured before the bulk operation.

## Alternatives considered

- **Delete from disk** — rejected. Some files (image_cache mp3s, agent caches)
  may be useful for debugging if an agent session is still active.
- **Keep tracked, don't move** — rejected. Violates the spec's hard rule.
- **Flag only, no untrack** — accepted as the default until Sahil confirms.
  This is the current state: .gitignore is updated (so future state does not
  get committed) but the 33 already-tracked files remain in the index.
