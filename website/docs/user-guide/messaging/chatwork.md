# Chatwork Setup

Run Hermes Agent from Chatwork using the official **Chatwork Webhook** and **Chatwork API v2**. The bundled platform plugin receives signed message events and posts Hermes replies back to the same room.

> Run `hermes gateway setup` and choose **Chatwork** for guided credential entry.

## Requirements

- A Chatwork account that can access the target rooms
- A Chatwork API token for that account
- Permission to create a webhook in Chatwork
- A public HTTPS URL that can forward to the Hermes host

## 1. Create the API token

Open Chatwork's API token page and issue/copy the token:

- https://www.chatwork.com/service/packages/chatwork/subpackages/api/token.php

Hermes uses this token to authenticate `GET /me`, fetch room metadata, and post messages.

## 2. Expose the webhook endpoint

The adapter listens on `0.0.0.0:8647` by default. Expose it through a fixed HTTPS URL, for example with Cloudflare Tunnel or your reverse proxy:

```bash
cloudflared tunnel --url http://localhost:8647
```

The webhook URL is:

```text
https://<your-public-host>/chatwork/webhook
```

Health check:

```text
https://<your-public-host>/chatwork/webhook/health
```

## 3. Create the Chatwork webhook

In Chatwork's integrations/webhook settings:

1. Create a webhook whose endpoint is `https://<your-public-host>/chatwork/webhook`.
2. Select either **messages addressed to this account** (`mention_to_me`) or room message creation (`message_created`).
3. Copy the displayed **Webhook token**. This is different from the API token.
4. For a room-wide webhook, set `CHATWORK_ALLOWED_ROOMS` so unrelated rooms are ignored.

Hermes rejects requests whose `x-chatworkwebhooksignature` does not match the raw request body.

## 4. Configure Hermes

Add credentials and authorization to `~/.hermes/.env`:

```env
CHATWORK_API_TOKEN=YOUR_API_TOKEN
CHATWORK_WEBHOOK_TOKEN=YOUR_WEBHOOK_TOKEN

# Recommended: authorize only known Chatwork account IDs.
CHATWORK_ALLOWED_USERS=1234567,2345678

# Optional defense in depth for room-wide webhooks.
CHATWORK_ALLOWED_ROOMS=987654321

# Optional default room for cron/proactive delivery.
CHATWORK_HOME_CHANNEL=987654321
```

Then enable the platform in `~/.hermes/config.yaml`:

```yaml
gateway:
  platforms:
    chatwork:
      enabled: true
```

The environment variables also auto-enable the bundled plugin when both required tokens are present.

## 5. Start and verify

```bash
hermes gateway run
```

Expected log shape:

```text
Chatwork: authenticated as account 1234567; webhook listening on 0.0.0.0:8647/chatwork/webhook
```

Send a message that matches the webhook rule. Hermes replies in the same room. When the triggering sender is known, the response uses Chatwork's `[rp ...]` reply syntax.

## Behavior and limitations

- Text messages are supported inbound and outbound.
- Hermes ignores webhook events sent by its own Chatwork account.
- Chatwork does not provide a typing indicator through API v2.
- Chatwork has rooms rather than Slack-style threads. Hermes uses Chatwork reply tags for immediate replies, but proactive/cron messages are posted flat.
- Files generated by detached cron runs are listed as paths; binary upload is not yet implemented.

## Environment variables

| Variable | Description |
|---|---|
| `CHATWORK_API_TOKEN` | Required API v2 token. |
| `CHATWORK_WEBHOOK_TOKEN` | Required webhook-signature token. |
| `CHATWORK_ALLOWED_USERS` | Comma-separated account IDs allowed to use Hermes. |
| `CHATWORK_ALLOW_ALL_USERS` | Development-only bypass for user authorization. |
| `CHATWORK_ALLOWED_ROOMS` | Optional comma-separated accepted room IDs. |
| `CHATWORK_HOME_CHANNEL` | Default room ID for cron/proactive delivery. |
| `CHATWORK_HOST` | Bind host; default `0.0.0.0`. |
| `CHATWORK_PORT` | Bind port; default `8647`. |
| `CHATWORK_WEBHOOK_PATH` | Endpoint path; default `/chatwork/webhook`. |
| `CHATWORK_API_BASE` | API base override for testing/private proxies. |
