# 팁 및 모범 사례

Hermes Agent를 즉시 더 효과적으로 사용할 수 있게 해 주는 실용적인 팁을 빠르게 모았습니다. 각 섹션은 서로 다른 측면을 다루므로, 제목을 훑어보고 필요한 부분으로 이동하세요.

:::tip 어떤 모델을 선택해야 할지 모르겠나요?
`hermes setup --portal`을 실행하세요 — Claude, GPT-5, Gemini를 포함한 300개 이상의 모델을 하나의 구독으로 이용할 수 있습니다. [Nous Portal](/integrations/nous-portal)을 참조하세요.
:::

---

## 최상의 결과 얻기

### 원하는 것을 구체적으로 말하기

모호한 프롬프트는 모호한 결과를 만듭니다. "코드를 고쳐 줘"라고 하는 대신 "47번째 줄 `api/handlers.py`의 TypeError를 고쳐 줘 — `process_request()` 함수가 `parse_body()`에서 `None`을 받습니다"라고 말하세요. 더 많은 컨텍스트를 제공할수록 필요한 반복 작업이 줄어듭니다.

### 처음부터 컨텍스트 제공하기

관련 세부 정보인 파일 경로, 오류 메시지, 예상 동작을 요청 앞부분에 넣으세요. 잘 작성한 메시지 하나가 세 번의 확인 과정보다 낫습니다. 오류 트레이스백은 그대로 붙여 넣으세요 — 에이전트가 이를 분석할 수 있습니다.

### 반복되는 지침에는 컨텍스트 파일 사용하기

같은 지침("공백 대신 탭 사용", "pytest를 사용", "API는 `/api/v2`에 있음")을 계속 반복하고 있다면 `AGENTS.md` 파일에 넣으세요. 에이전트가 매 세션 자동으로 읽으므로, 설정 후에는 전혀 수고할 필요가 없습니다.

### 에이전트가 도구를 사용하게 하기

모든 단계를 일일이 통제하려 하지 마세요. "`tests/test_foo.py`를 열고 42번째 줄을 본 다음..."이라고 하기보다 "실패하는 테스트를 찾아서 고쳐 줘"라고 하세요. 에이전트에는 파일 검색, 터미널 액세스 및 코드 실행 기능이 있으므로, 스스로 탐색하고 반복하게 하세요.

### 복잡한 워크플로에는 스킬 사용하기

무언가를 하는 방법을 설명하는 긴 프롬프트를 작성하기 전에, 이미 해당 작업을 위한 스킬이 있는지 확인하세요. `/skills`를 입력해 사용 가능한 스킬을 찾아보거나 `/axolotl`, `/github-pr-workflow`처럼 직접 호출하세요.

## CLI 파워 유저 팁

### 여러 줄 입력

**Alt+Enter**, **Ctrl+J** 또는 **Shift+Enter**를 눌러 전송하지 않고 줄바꿈을 삽입하세요. **Shift+Enter**는 터미널이 이를 별도의 키 입력으로 전송할 때만 작동합니다(기본적으로 Kitty / foot / WezTerm / Ghostty, Kitty 키보드 프로토콜을 활성화한 iTerm2 / Alacritty / VS Code 터미널). 나머지 두 가지는 모든 터미널에서 작동합니다.

### 붙여넣기 감지

CLI는 여러 줄 붙여넣기를 자동으로 감지합니다. 코드 블록이나 오류 트레이스백을 그대로 붙여 넣으세요 — 각 줄이 별도의 메시지로 전송되지 않습니다. 붙여넣은 내용은 버퍼에 저장되어 하나의 메시지로 전송됩니다.

### 중단 및 방향 전환

응답 중 **Ctrl+C**를 한 번 눌러 에이전트를 중단하세요. 그런 다음 새 메시지를 입력해 방향을 바꿀 수 있습니다. 2초 안에 **Ctrl+C**를 두 번 누르면 강제 종료됩니다. 에이전트가 잘못된 방향으로 가기 시작했을 때 매우 유용합니다.

### `-c`로 세션 재개

지난 세션에서 뭔가 잊은 것이 있나요? `hermes -c`를 실행하면 전체 대화 기록을 복원하여 정확히 이어서 작업할 수 있습니다. 제목으로 재개할 수도 있습니다: `hermes -r "my research project"`.

### 클립보드 이미지 붙여넣기

채팅에 클립보드의 이미지를 직접 붙여 넣으려면 **Ctrl+V**를 누르세요. 에이전트는 이미지를 사용해 스크린샷, 다이어그램, 오류 팝업 또는 UI 목업을 분석합니다 — 저장할 필요가 없습니다.

### 슬래시 명령 자동 완성

`/`를 입력하고 **Tab**을 눌러 사용 가능한 모든 명령을 확인하세요. 여기에는 기본 제공 명령(`/compress`, `/model`, `/title`)과 설치된 모든 스킬이 포함됩니다. 아무것도 외울 필요 없이 Tab 완성을 이용하면 됩니다.

:::tip
도구 출력 표시 모드를 순환하려면 `/verbose`를 사용하세요: **off → new → all → verbose**. 에이전트가 하는 일을 지켜보고 싶을 때는 "all"이 좋고, 간단한 질의응답에는 "off"가 가장 깔끔합니다.
:::

## 컨텍스트 파일

### AGENTS.md: 프로젝트의 두뇌

프로젝트 루트에 아키텍처 결정, 코딩 규칙 및 프로젝트별 지침이 담긴 `AGENTS.md`를 만드세요. 이 파일은 모든 세션에 자동으로 주입되므로 에이전트가 항상 프로젝트 규칙을 알고 있습니다.

```markdown
# Project Context
- This is a FastAPI backend with SQLAlchemy ORM
- Always use async/await for database operations
- Tests go in tests/ and use pytest-asyncio
- Never commit .env files
```

### SOUL.md: 성격 사용자 지정

Hermes의 기본 목소리를 안정적으로 유지하고 싶나요? `~/.hermes/SOUL.md`를 편집하세요(또는 사용자 지정 Hermes 홈을 사용하는 경우 `$HERMES_HOME/SOUL.md`). 이제 Hermes가 시작용 SOUL을 자동으로 만들며, 해당 전역 파일을 인스턴스 전체의 성격 정보로 사용합니다.

전체 안내는 [Hermes에서 SOUL.md 사용하기](/guides/use-soul-with-hermes)를 참조하세요.

```markdown
# Soul
You are a senior backend engineer. Be terse and direct.
Skip explanations unless asked. Prefer one-liners over verbose solutions.
Always consider error handling and edge cases.
```

지속적인 성격 설정에는 `SOUL.md`를 사용하세요. 프로젝트별 지침에는 `AGENTS.md`를 사용하세요.

### .cursorrules 호환성

이미 `.cursorrules` 또는 `.cursor/rules/*.mdc` 파일이 있나요? Hermes도 이를 읽습니다. 코딩 규칙을 복제할 필요가 없습니다 — 작업 디렉터리에서 자동으로 로드됩니다.

### 탐색

Hermes는 세션 시작 시 현재 작업 디렉터리의 최상위 `AGENTS.md`를 로드합니다. 하위 디렉터리의 `AGENTS.md` 파일은 도구 호출 중에(`subdirectory_hints.py`를 통해) 필요할 때 탐색되어 도구 결과에 주입되며, 시스템 프롬프트에 처음부터 로드되지는 않습니다.

:::tip
컨텍스트 파일은 집중적이고 간결하게 유지하세요. 모든 메시지에 주입되므로 글자 하나하나가 토큰 예산에 반영됩니다.
:::

## 메모리 및 스킬

### 메모리와 스킬: 어디에 무엇을 둘 것인가

**메모리**는 환경, 선호 사항, 프로젝트 위치 및 에이전트가 사용자에 대해 학습한 내용 같은 사실을 위한 것입니다. **스킬**은 다단계 워크플로, 도구별 지침 및 재사용 가능한 레시피 같은 절차를 위한 것입니다. 메모리는 "무엇"에, 스킬은 "어떻게"에 사용하세요.

### 스킬을 만들어야 할 때

5단계 이상이 필요하고 다시 하게 될 작업을 찾았다면 에이전트에게 스킬을 만들어 달라고 하세요. "방금 한 작업을 `deploy-staging`이라는 스킬로 저장해 줘"라고 말하면 됩니다. 다음에는 `/deploy-staging`만 입력하면 전체 절차가 로드됩니다.

### 메모리 용량 관리

메모리에는 의도적으로 용량 제한이 있습니다(`MEMORY.md` 약 2,200자, `USER.md` 약 1,375자). 가득 차면 에이전트가 항목을 통합합니다. "메모리를 정리해 줘"라고 하거나 "예전 Python 3.9 메모를 지우고 3.12로 바꿔 줘 — 우리는 3.12를 사용해"처럼 말할 수 있습니다.

### 에이전트가 기억하게 하기

생산적인 세션이 끝나면 "다음에 사용할 수 있도록 기억해 줘"라고 말해 핵심 내용을 저장할 수 있습니다. 더 구체적으로 "우리 CI가 `deploy.yml` 워크플로를 사용하는 GitHub Actions라는 것을 메모리에 저장해 줘"라고 요청할 수도 있습니다.

:::warning
메모리는 고정된 스냅샷입니다 — 세션 중 변경한 내용은 다음 세션이 시작될 때까지 시스템 프롬프트에 나타나지 않습니다. 에이전트는 디스크에 즉시 기록하지만, 세션 중 프롬프트 캐시가 무효화되지는 않습니다.
:::

## 성능 및 비용

### 프롬프트 캐시를 깨뜨리지 않기

대부분의 LLM 제공업체는 대화 접두부(시스템 프롬프트 + 기록)를 캐시합니다. 세션에서 시스템 프롬프트를 안정적으로 유지하면(같은 컨텍스트 파일, 같은 메모리) 이후 메시지에서 **캐시 적중**이 발생해 입력 비용을 크게 줄일 수 있습니다. 캐시는 모델과 계정을 기준으로 하므로, 명시적인 `/model` 전환, [자동 제공업체 대체](../user-guide/features/fallback-providers.md) 또는 [자격 증명 풀 순환](../user-guide/features/credential-pools.md)은 다음 턴에 전체 대화를 다시 읽게 하여 입력 비용을 모두 발생시킵니다. 가끔 전환하는 것은 괜찮지만, 긴 세션에서 자주 전환하면 비용이 배로 늘어납니다.

### 한도에 도달하기 전에 /compress 사용하기

긴 세션에는 토큰이 누적됩니다. 응답이 느려지거나 잘리는 것을 발견하면 `/compress`를 실행하세요. 핵심 컨텍스트를 보존하면서 대화 기록을 요약해 토큰 수를 크게 줄입니다. 현재 상태를 확인하려면 `/usage`를 사용하세요.

### 병렬 작업 위임하기

세 가지 주제를 한 번에 조사해야 하나요? 에이전트에게 병렬 하위 작업과 함께 `delegate_task`를 사용하도록 요청하세요. 각 하위 에이전트는 자체 컨텍스트로 독립 실행되고 최종 요약만 돌아오므로, 주 대화의 토큰 사용량을 크게 줄일 수 있습니다.

### 일괄 작업에 execute_code 사용하기

터미널 명령을 한 번에 하나씩 실행하는 대신, 에이전트에게 모든 작업을 한 번에 처리하는 스크립트를 작성하게 하세요. "모든 `.jpeg` 파일의 이름을 `.jpg`로 바꾸는 Python 스크립트를 작성하고 실행해 줘"라고 요청하는 편이 파일을 하나씩 이름 변경하는 것보다 저렴하고 빠릅니다.

### 적절한 모델 선택하기

세션 중 모델을 전환하려면 `/model`을 사용하세요. 복잡한 추론과 아키텍처 결정에는 프런티어 모델(Claude Sonnet/Opus, GPT-4o)을 사용하세요. 형식 지정, 이름 변경 또는 보일러플레이트 생성 같은 간단한 작업에는 더 빠른 모델로 전환하세요. 단, 전환할 때마다 프롬프트 캐시가 재설정되므로(위 참조), 긴 세션에서는 모델을 오가느니 다른 모델로 새 세션을 시작하는 편이 더 저렴한 경우가 많습니다.

:::tip
토큰 사용량을 확인하려면 주기적으로 `/usage`를 실행하세요. 지난 30일의 사용 패턴을 폭넓게 보려면 `/insights`를 실행하세요. 대화 전 *고정된* 메시지당 비용(시스템 프롬프트, 스킬 색인, 메모리, 도구 스키마)을 미리 확인하려면 [`hermes prompt-size`](/reference/cli-commands#hermes-prompt-size)를 실행하세요(오프라인에서 작동).
:::

## 메시징 팁

### 홈 채널 설정하기

선호하는 Telegram 또는 Discord 채팅에서 `/sethome`을 사용해 홈 채널로 지정하세요. Cron 작업 결과와 예약된 작업 출력이 이곳으로 전달됩니다. 설정하지 않으면 에이전트가 능동적으로 메시지를 보낼 곳이 없습니다.

### /title로 세션 정리하기

`/title auth-refactor` 또는 `/title research-llm-quantization`으로 세션 이름을 지정하세요. 이름을 지정한 세션은 `hermes sessions list`로 쉽게 찾고 `hermes -r "auth-refactor"`로 재개할 수 있습니다. 이름 없는 세션은 쌓여서 구분하기 어려워집니다.

### 팀 액세스를 위한 DM 페어링

허용 목록에 사용자 ID를 수동으로 수집하는 대신 DM 페어링을 활성화하세요. 팀원이 봇에 DM을 보내면 일회성 페어링 코드를 받습니다. `hermes pairing approve telegram XKGH5N7P`로 승인하면 됩니다 — 간단하고 안전합니다.

### 도구 진행 상황 표시 모드

도구 활동을 얼마나 표시할지 제어하려면 `/verbose`를 사용하세요. 메시징 플랫폼에서는 보통 적게 표시하는 편이 좋으므로 새 도구 호출만 보려면 "new"로 설정하세요. CLI에서는 에이전트의 모든 활동을 실시간으로 보고 싶을 때 "all"을 사용하면 됩니다.

:::tip
기본적으로 메시징 세션은 자동으로 재설정되지 않습니다 — `/reset`을 실행하거나 압축이 시작될 때까지 컨텍스트가 유지됩니다. 유휴 시간 이후 또는 매일 특정 시각에 세션을 자동 재설정하려면 `~/.hermes/config.yaml`의 `session_reset` 섹션에서 선택하세요.
:::

## 보안

### 신뢰할 수 없는 코드에는 Docker 사용하기

신뢰할 수 없는 저장소로 작업하거나 익숙하지 않은 코드를 실행할 때는 Docker 또는 Daytona를 터미널 백엔드로 사용하세요. `.env`에서 `TERMINAL_ENV=docker`를 설정하세요. 컨테이너 내부의 파괴적인 명령은 호스트 시스템에 피해를 줄 수 없습니다.

```bash
# In your .env:
TERMINAL_ENV=docker
TERMINAL_DOCKER_IMAGE=hermes-sandbox:latest
```

### Windows 인코딩 문제 피하기

Windows에서는 일부 기본 인코딩(예: `cp125x`)이 모든 유니코드 문자를 표현하지 못해 테스트나 스크립트에서 `UnicodeEncodeError`가 발생할 수 있습니다.

- 파일을 열 때 명시적인 UTF-8 인코딩을 우선 사용하세요:

```python
with open("results.txt", "w", encoding="utf-8") as f:
    f.write("✓ All good\n")
```

- PowerShell에서는 현재 세션을 UTF-8로 전환할 수도 있습니다:

```powershell
$OutputEncoding = [Console]::OutputEncoding = [Text.UTF8Encoding]::new($false)
```

이렇게 하면 PowerShell과 하위 프로세스가 UTF-8을 사용하므로 Windows에서만 발생하는 오류를 방지할 수 있습니다.

### "항상"을 선택하기 전에 검토하기

에이전트가 위험한 명령(`rm -rf`, `DROP TABLE` 등)의 승인을 요청하면 네 가지 옵션이 있습니다: **once**, **session**, **always**, **deny**. "always"를 선택하기 전에 신중히 생각하세요 — 해당 패턴을 영구적으로 허용 목록에 추가합니다. 확신이 들 때까지는 "session"으로 시작하세요.

### 명령 승인이라는 안전망

Hermes는 엄선된 위험 패턴 목록을 기준으로 모든 명령을 검사합니다. 여기에는 재귀 삭제, SQL 삭제, 셸로 curl 연결, 재귀적인 삭제 등이 포함됩니다. 프로덕션에서는 이 기능을 비활성화하지 마세요 — 좋은 이유로 존재합니다.

:::warning
컨테이너 백엔드(Docker, Singularity, Modal, Daytona)를 사용할 때는 컨테이너가 보안 경계이므로 위험한 명령 검사를 건너뜁니다. 컨테이너 이미지가 적절히 잠겨 있는지 확인하세요.
:::

### 메시징 봇에 허용 목록 사용하기

터미널 액세스 권한이 있는 봇에서 `GATEWAY_ALLOW_ALL_USERS=true`를 설정하지 마세요. 플랫폼별 허용 목록(`TELEGRAM_ALLOWED_USERS`, `DISCORD_ALLOWED_USERS`) 또는 DM 페어링을 사용해 에이전트와 상호작용할 수 있는 사람을 항상 제한하세요.

```bash
# Recommended: explicit allowlists per platform
TELEGRAM_ALLOWED_USERS=123456789,987654321
DISCORD_ALLOWED_USERS=123456789012345678

# Or use cross-platform allowlist
GATEWAY_ALLOWED_USERS=123456789,987654321
```
