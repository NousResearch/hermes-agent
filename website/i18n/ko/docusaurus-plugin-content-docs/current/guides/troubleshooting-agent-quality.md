# 문제 해결: "내 에이전트가 더 멍청해진 것 같아요"

때때로 Hermes가 어제보다 덜 똑똑해 보이거나, 20분 전에 알려준 내용을 잊어버리는 것처럼 느껴질 수 있습니다. 이는 거의 미스터리한 일이 아닙니다. 대개 구체적으로 확인할 수 있는 원인이 하나 있습니다. 이 체크리스트를 순서대로 따라가 보세요. 각 단계는 실제 원인으로 밝혀지는 빈도가 높은 순서로 정렬되어 있습니다.

## 1. 세션이 실제로 어떤 모델을 사용하는지 확인

**증상:** 전반적으로 답변이 피상적이고, 코드 품질이 떨어졌으며, 추론이 이상하게 느껴집니다.

**확인:** 인수 없이 `/model`을 실행하면 현재 모델을 표시하고, `/status`를 실행하면 한 화면에서 세션의 모델, 제공자, 프로필을 확인할 수 있습니다.

**의미:** 모델 전환은 기능의 변화이며, 자신이 생각한 것과 다른 모델을 사용하게 되기 쉽습니다.

- 인수 없이 실행하는 일반적인 `/model <name>` 전환은 기본적으로 **세션에만 적용됩니다**(`model.persist_switch_by_default: true`가 설정된 경우 제외). 따라서 현재 사용 중인 모델이 `config.yaml`의 내용과 다를 수 있습니다.
- 대시보드의 Models 페이지에서 기본 모델을 변경하면 **새 세션에만** 적용됩니다. 이미 열려 있는 채팅은 시작할 때 사용한 모델로 계속 실행됩니다.
- 간단한 작업을 위해 더 빠른 모델로 전환했다면([Tips & Best Practices](/guides/tips#choose-the-right-model)에서 권장하는 방식), 복잡한 추론 작업을 할 때는 원래 모델로 다시 전환해야 합니다.

모델이 잘못되었다면 `/model <name>`으로 이 세션에서 수정할 수 있고, `config.yaml`에 변경 사항을 저장하려면 `--global`을 추가하세요. 세션 중간에 모델을 전환하면 프롬프트 캐시가 초기화된다는 점에 유의하세요. 다음 턴에서 대화를 입력 전체 가격으로 다시 읽으며, 긴 세션에서는 올바른 모델로 새로 시작하는 편이 더 저렴할 수 있습니다.

## 2. 컨텍스트 사용량 확인

**증상:** 세션은 처음에는 잘 작동했지만 응답이 느려지고, 잘리거나, 앞서 나온 세부 사항을 놓치기 시작합니다.

**확인:** `/usage`를 실행해 토큰 사용량과 컨텍스트 창 상태를 확인하거나, `/context`를 실행해 컨텍스트 창을 차지하는 항목(시스템 프롬프트, 도구 정의, 스킬, 메모리, 대화)과 남은 공간을 시각적으로 확인하세요.

**의미:** 대화가 길어지면 메시지와 도구 출력이 누적되어 컨텍스트 한도에 가까워집니다. 긴 세션에서 성능 저하가 느껴지면 다음을 실행하세요.

```bash
# Compress the conversation (summarizes history, preserves key context)
/compress

# Or start a fresh session
/new
```

`/compress`는 핵심 컨텍스트를 유지하면서 대화 기록을 요약해 토큰 수를 크게 줄입니다. `/compress here [N]`은 최근 N개의 교환을 원문 그대로 유지하고 나머지를 요약하며, 집중 주제(`/compress focus <topic>`)를 지정하면 전체 요약에서 보존할 내용을 해당 주제로 좁힙니다.

:::tip
문제가 생길 때까지 기다리기보다 긴 세션 중에 `/compress`를 정기적으로 사용하고, `/usage`를 주기적으로 확인해 현재 상태를 파악하세요.
:::

## 3. 감지된 컨텍스트 길이 확인

**증상:** 컨텍스트 문제가 예상보다 일찍 나타납니다. 첫 번째 긴 대화에서 이미 한도에 도달하거나, 모델이 광고하는 창보다 훨씬 빨리 압축이 실행됩니다.

**확인:** CLI 시작 줄을 확인하세요. 감지된 컨텍스트 길이가 표시됩니다(예: `📊 Context limit: 128000 tokens`). 세션 중 `/usage`로도 확인할 수 있습니다.

**의미:** Hermes가 모델의 컨텍스트 길이를 잘못 자동 감지했을 수 있습니다. 명시적으로 설정하세요.

```yaml
# In ~/.hermes/config.yaml
model:
  default: your-model-name
  context_length: 131072  # your model's actual context window
```

사용자 지정 엔드포인트의 경우 제공자 항목에서 모델별로 설정할 수 있습니다.

```yaml
providers:
  my-server:
    api: "http://localhost:11434/v1"
    models:
      qwen3.5:27b:
        context_length: 64000
```

Ollama 사용자: 사용자 지정 `num_ctx`를 설정했다면 Hermes에도 일치하는 컨텍스트 길이를 설정하세요. Ollama의 `/api/show`는 설정한 유효 `num_ctx`가 아니라 모델의 *최대* 컨텍스트를 보고합니다. 실행 중인 게이트웨이에서는 `model.context_length` 또는 `compression.*` 키를 수정하면 다음 메시지부터 적용되며 재시작할 필요가 없습니다.

자동 감지 작동 방식과 모든 재정의 옵션은 [컨텍스트 길이 감지](/integrations/providers#context-length-detection)를 참조하세요.

## 4. "말해줬는데 잊어버렸어요" — 고정된 메모리 스냅샷

**증상:** 이 세션 중 Hermes에게 무언가를 기억해 달라고 요청했고 저장을 확인받았지만, *같은* 세션에서 나중에 그 내용을 모르는 것처럼 보입니다.

**확인:** 아무것도 고장 난 것이 아닙니다. 타이밍을 확인하세요. 세션 중간에 저장된 메모리는 즉시 디스크에 기록되지만 시스템 프롬프트에는 다음 세션까지 반영되지 않습니다.

**의미:** 이는 문서화된 의도적 동작입니다. 메모리는 **세션 시작 시 고정된 스냅샷**으로 시스템 프롬프트에 삽입되며, LLM의 접두사 캐시를 성능을 위해 보존하기 위해 세션 중간에는 이 삽입 내용이 변경되지 않습니다. 세션 중 에이전트가 메모리 항목을 추가하거나 삭제하면 변경 사항은 즉시 디스크에 저장되지만, 시스템 프롬프트에는 다음 세션이 시작될 때만 나타납니다. 도구 응답에는 항상 실시간 상태가 표시되므로 저장 자체는 확인되며 실제로 완료된 것입니다.

:::info
실제 고정 스냅샷: 세션 중 "X를 기억해"라고 말하면 X는 **다음** 세션에서 사용할 수 있도록 보장됩니다. 현재 세션 안에서는 해당 사실이 대화 기록 자체에 여전히 존재합니다. 다만 대화의 해당 부분이 이후 압축으로 사라진 경우에는 에이전트가 이를 잊어버릴 수 있습니다(7단계 참조).
:::

전체 작동 방식은 [영구 메모리](/user-guide/features/memory#how-memory-appears-in-the-system-prompt)를 참조하세요.

## 5. 메모리는 대화 기록이 아니라 제한되고 선별된 정보입니다

**증상:** 지난주 세션에서 세부 사항을 길게 이야기했는데도 Hermes가 이를 기억하지 못합니다.

**확인:** 메모리 용량과 내용을 확인하세요. 시스템 프롬프트의 메모리 헤더에 사용량(예: `[67% — 1,474/2,200 chars]`)이 표시되며, `hermes journey list`는 저장된 모든 메모리 항목과 스킬을 보여줍니다.

**의미:** 영구 메모리는 의도적으로 제한되어 있습니다. MEMORY.md에는 2,200자(~800토큰), USER.md에는 1,375자(~500토큰)만 저장됩니다. 대화 기록이 아니라 선별된 핵심 사실을 담습니다. 저장할 가치가 있는 내용은 선호 사항, 환경 정보, 관례, 수정 사항이며, 원시적인 대화 세부 내용은 설계상 저장되지 않습니다.

"지난주에 X에 대해 이야기했나?"와 같은 내용을 기억하기 위해 에이전트에는 별도의 메커니즘이 있습니다. `session_search`는 모든 과거 세션을 쿼리하고(전체 텍스트 검색을 지원하는 SQLite에 저장됨), 현재 메모리에 없어도 몇 주 전에 나눈 대화를 찾을 수 있습니다. "배포 논의가 있었던 과거 세션을 검색해 줘"라고 요청하면 됩니다.

직접 도움을 줄 수도 있습니다. 생산적인 세션 뒤에 "다음에 기억할 수 있도록 저장해 줘"라고 말하거나, 용량이 거의 찼을 때 "메모리를 정리해 줘"라고 말하면 에이전트가 항목을 통합합니다. [메모리 및 스킬 팁](/guides/tips#memory--skills)과 [용량 관리](/user-guide/features/memory#capacity-management)를 참조하세요.

## 6. 스킬과 도구가 로드되었는지 확인

**증상:** Hermes가 예전에는 특정 워크플로를 능숙하게 처리했는데 이제는 순진하게 접근하거나, 예전에 할 수 있었던 일을 할 수 없다고 말합니다.

**확인:**

- `/skills` — 설치된 스킬을 살펴봅니다(에이전트가 의존하던 스킬이 제거되었을 수 있습니다).
- `/reload-skills` — 새로 설치되었거나 제거된 스킬을 찾기 위해 `~/.hermes/skills/`를 다시 검색합니다.
- `/tools list` — 사용 가능한 도구를 확인합니다. 이전에 `/tools disable`로 비활성화한 도구는 해당 세션에서 에이전트 도구 모음에 계속 포함되지 않습니다.
- `/context all` — 실제로 로드된 항목의 목록 역할도 하는, 스킬별·도구 모음별 비용 목록을 표시합니다.

**의미:** 스킬은 에이전트의 절차적 지식, 즉 다단계 워크플로와 도구별 지침입니다. 스킬이 없거나 도구 모음이 축소되었다면(예: 프롬프트 부담을 줄이기 위해 `hermes chat -t "terminal"`로 시작한 세션), 해당 세션에서 에이전트가 활용할 수 있는 것이 실제로 줄어든 것입니다. `/tools enable`로 도구를 다시 활성화하거나, 스킬 이름(`/github-pr-workflow`)을 명시적으로 호출해 로드되는지 확인하세요.

## 7. 압축의 부작용

**증상:** 긴 세션 후(또는 `/compress`를 실행한 직후) Hermes가 큰 줄기는 기억하지만 대화 초반의 세부 사항을 잃었습니다.

**확인:** 압축이 실행되었는지 확인하세요. 메시징 플랫폼에서는 `/usage`와 `/context`에 압축 통계와 컨텍스트 상태가 표시되며, 수동으로 `/compress`를 실행하면 항상 결과가 보고됩니다.

**의미:** 압축은 이전 대화 기록을 요약으로 대체합니다. 이것이 압축의 목적이며, 여유 공간을 확보하는 대신 세부 사항을 필연적으로 줄입니다. 다음과 같은 구조를 이해해 두세요.

- 최근 메시지는 보호됩니다. 기본적으로 마지막 20개 메시지는 압축되지 않은 상태로 유지되고(`protect_last_n`), 시작 교환은 고정됩니다(`protect_first_n: 3`). 따라서 원래 목표가 계속 표시됩니다.
- 압축은 비파괴적입니다. 기본값인 `compression.in_place: true`에서는 세션이 하나의 영구 ID를 유지하고, 압축 전 턴은 소프트 아카이브됩니다. 삭제되는 것이 아니므로 `session_search`로 계속 검색하고 복구할 수 있습니다.
- `in_place: false`(기존 동작)에서는 압축할 때마다 이전 세션과 연결된 **새 세션**으로 전환됩니다. 제목이 있는 세션은 `"my project" → "my project #2" → "my project #3"`처럼 이어집니다. 제목으로 재개하면 `hermes -c "my project"`가 가장 최근 변형을 자동으로 선택합니다.
- 집중 주제는 전체 요약에서 보존할 내용을 좁힙니다. `/compress focus auth-refactor`는 다른 내용의 세부 사항을 줄이는 대신 해당 스레드의 세부 사항을 유지합니다.

압축으로 사라진 세부 사항이 중요하다면 에이전트에게 검색을 요청하세요(`session_search`는 아카이브된 턴까지 검색합니다). 또는 핵심 사실을 대화에 다시 붙여 넣으세요.

[컨텍스트 압축](/user-guide/configuration#context-compression)에서 전체 설정 참조를, [압축 시 자동 계보](/user-guide/sessions#auto-lineage-on-compression)에서 제목이 있는 세션이 연결되는 방식을 확인할 수 있습니다.

|---------|--------------|--------------|
| 모든 기능이 떨어진 것처럼 느껴짐 | `/model` | 세션이 생각한 것과 다른 모델을 사용 중 |
| 긴 세션에서 성능 저하 | `/usage` | 컨텍스트 압박 — 압축하거나 새로 시작 |
| 한도에 예상보다 일찍 도달 | CLI 시작 줄 / `/usage` | 컨텍스트 길이를 잘못 자동 감지함 |
| 이 세션에서 내가 말한 내용을 잊음 | — (의도된 동작) | 고정된 메모리 스냅샷 — 다음 세션에 표시됨 |
| 지난주 논의를 잊음 | `session_search`로 검색 요청 | 메모리는 제한된 선별 정보만 저장 |
| 특정 기능을 잃음 | `/skills`, `/tools list` | 이 세션에 스킬 또는 도구 모음이 로드되지 않음 |
| 긴 세션 후 예전 세부 사항을 잃음 | `/usage`, `/context` | 압축이 이전 기록을 요약함 |
