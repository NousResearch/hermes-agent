# 결과물 모드

Hermes Agent가 메시징 게이트웨이(Slack, Discord, Telegram,
WhatsApp, Signal 등) 안에서 실행되면 생성된 파일을 채팅에 직접 전송할 수 있습니다.
사용자가 복사해야 하는 경로가 아니라 네이티브 첨부 파일로 전송됩니다.

차트는 인라인 이미지로 표시됩니다. PDF 보고서는 파일 다운로드로 표시됩니다. 스프레드시트는 `.xlsx`로 업로드됩니다. 에이전트는 `MEDIA:` 태그를 작성하거나 특별한 작업을 할 필요가 없습니다. 파일을 생성하고 응답에 절대 경로를 언급하기만 하면 됩니다. 게이트웨이는 텍스트에서 경로를 찾아 눈에 보이는 메시지에서는 제거한 다음 파일을 네이티브 방식으로 업로드합니다.

## 작동 방식

세 가지 요소가 맞물려 작동합니다.

1. **에이전트에는 파일을 생성하는 도구가 있습니다.** 차트에는 `execute_code`와 matplotlib, Word 문서에는 `docx` 스킬, 스프레드시트에는 `xlsx` 스킬, PDF에는 `pdf` 및 `latex-pdf-report` 스킬, 프레젠테이션에는 `powerpoint` 스킬, 이미지에는 `image_generate`, 오디오에는 `text_to_speech` 등을 사용합니다.

2. **게이트웨이는 에이전트 응답에서 파일 경로를 검색합니다.** 지원되는 확장자로 끝나는 절대 경로(`/tmp/...`) 또는 홈 기준 상대 경로(`~/...`)를 추출합니다. 코드 블록과 인라인 코드 안의 경로는 무시되므로 코드 샘플이 손상되지 않습니다.

3. **게이트웨이는 파일 형식에 따라 전송합니다.** 플랫폼이 지원하는 경우 이미지는 인라인으로 삽입되고, 동영상도 인라인으로 삽입됩니다. 오디오는 음성/오디오 첨부 파일로 전송되고, 나머지는 모두 파일 첨부로 업로드됩니다.

## 지원되는 파일 확장자

| 분류 | 확장자 | 전송 방식 |
|---|---|---|
| 이미지 | `.png .jpg .jpeg .gif .webp .bmp .tiff .svg` | 인라인 삽입 |
| 동영상 | `.mp4 .mov .avi .mkv .webm .3gp` | 인라인 삽입(지원되는 경우) |
| 오디오 | `.mp3 .m2a .wav .ogg .opus .m4a .flac` | 음성/오디오 첨부 |
| 문서 | `.pdf .docx .doc .odt .rtf .txt .md .epub` | 파일 업로드 |
| 데이터 | `.xlsx .xls .ods .csv .tsv .json .xml .yaml .yml` | 파일 업로드 |
| 지리 공간 | `.kmz .kml .geojson .gpx` | 파일 업로드 |
| 프레젠테이션 | `.pptx .ppt .odp .key` | 파일 업로드 |
| 아카이브 | `.zip .tar .gz .tgz .bz2 .xz .7z .rar .apk .ipa` | 파일 업로드 |
| 웹 | `.html .htm` | 파일 업로드 |

`.py`, `.log` 및 기타 소스 파일 확장자는 의도적으로 제외됩니다. 에이전트가 임의의 소스 파일을 자동으로 전송하지 않도록 하기 위해서입니다. 사용자에게 코드를 보내려면 코드 블록을 사용하세요.

## 에이전트가 아티팩트를 생성하도록 유도하기

에이전트는 기본적으로 아티팩트를 찾지 않으므로 아티팩트가 필요하다는 것을 알아야 합니다.
이를 유도하는 방법은 두 가지입니다.

**세션별:** 명시적으로 요청하거나(“비교 결과를 차트로 보내 줘”, “데이터를 CSV로 반환해 줘”) 메시징 플랫폼에서 아티팩트 형식의 답변을 선호하도록 사용자 지정 지침/페르소나 항목을 직접 작성합니다.

**프로젝트 수준:** 작업 중인 프로젝트의 `AGENTS.md` / `CLAUDE.md` /
`.cursorrules`, 전역 페르소나인 `~/.hermes/SOUL.md`, 또는
`~/.hermes/config.yaml`의 `agent.personalities` 아래에 이름이 지정된 프리셋에 해당 선호를 추가합니다(세션마다 `/personality`로 전환 가능).

에이전트가 사용해야 하는 방식은 간단합니다. 파일을 절대 경로(예: `/tmp/q3-revenue.png`)로 렌더링하고 답변에 해당 경로를 일반 텍스트로 언급합니다. 게이트웨이가 나머지를 처리합니다. 펜스로 묶은 코드 블록이나 백틱 안의 경로는 무시되므로 코드 샘플이 손상되지 않습니다.

## Kanban: 아티팩트는 완료 알림을 따라갑니다

Hermes의 kanban 멀티 에이전트 워크플로를 사용하는 경우 작업자는 `kanban_complete` 호출에 결과물 파일을 첨부할 수 있습니다.

```python
kanban_complete(
    summary="rendered Q3 revenue chart and report",
    artifacts=[
        "/tmp/q3-revenue.png",
        "/tmp/q3-report.pdf",
    ],
)
```

게이트웨이 알림자가 Slack/Telegram 등의 작업 구독자에게 “작업 완료” 메시지를 전송할 때 각 아티팩트도 해당 채팅에 네이티브 첨부 파일로 업로드합니다. 알림자가 실행될 때 디스크에 존재하지 않는 파일은 조용히 건너뜁니다.

## MCP로 더 많은 서비스 연결하기

아티팩트 전송 파이프라인 외에도 에이전트는 MCP(Model Context Protocol)를 통해 다른 서비스에 접근할 수 있습니다. 대부분의 인기 도구에는 MCP 생태계의 커뮤니티 서버가 있으므로 필요한 것만 설치하면 됩니다.

| 서비스 | 제공 기능 |
|---|---|
| **Notion** | Notion 페이지와 데이터베이스 읽기/쓰기, 워크스페이스 쿼리 |
| **GitHub** | 이슈, PR, 댓글, `gh` CLI 이상의 저장소 검색 |
| **Linear** | 티켓, 프로젝트, 사이클 |
| **Slack** | 워크스페이스 전체 검색, 다른 채널 읽기 |
| **Gmail** | 받은편지함 분류, 메일 전송, 라벨 관리 |
| **Salesforce** | 리드, 영업 기회, 계정 데이터 |
| **Snowflake / BigQuery** | 데이터 웨어하우스에 대한 SQL |
| **Google Drive** | 파일 검색, 콘텐츠, 공유 관리 |

`mcp_servers` 섹션 아래의 `~/.hermes/config.yaml`을 통해 MCP 서버를 설치합니다. 전체 설정 가이드는 [MCP 통합](./mcp.md)을 참조하세요.

## Slack의 Perplexity Computer와 비교

Perplexity Computer의 Slack 통합도 동일한 아이디어를 중심으로 합니다. 에이전트가 결과물(차트, PDF, 슬라이드 덱)을 생성하고 네이티브 첨부 파일로 스레드에 다시 게시합니다. Hermes Agent의 결과물 모드는 동일한 사용자 경험을 로컬에서 제공합니다.

- 생성은 사용자의 자체 venv / 샌드박스에서 이루어집니다(원격 테넌트 없음).
- 파일은 동일한 Slack `files.uploadV2` API를 통해 채팅에 도착합니다.
- 커넥터의 폭넓은 범위는 400개의 호스팅 통합을 엄선한 카탈로그가 아니라 MCP를 통해 제공됩니다. 실제로 사용하는 것만 설치하면 됩니다.

OAuth 토큰은 사용자의 컴퓨터에 `auth.json` / `.env`로 저장됩니다. 호스팅된 토큰 저장소는 없습니다. 멀티 테넌트 microVM도 없습니다. 결과는 동일합니다.
