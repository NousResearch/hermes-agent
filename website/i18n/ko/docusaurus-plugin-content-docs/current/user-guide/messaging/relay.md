# Hermes Relay (커넥터)

:::warning 실험적 기능
Relay는 **실험적 기능**입니다. 시스템을 검증하는 동안에는 유예 기간 없이 와이어 계약, 인증 방식 및 구성이 변경될 수 있습니다.
:::

Hermes Relay는 그 자체로 채팅 플랫폼이 아니라, 게이트웨이가 실제 메시징 플랫폼(Discord,
Telegram, Slack, WhatsApp 등) 하나 이상을 **어떤 플랫폼 자격 증명도 보유하지 않고** 앞단에서
제공할 수 있게 하는 **커넥터 시스템**입니다. 별도의 서비스인 *커넥터*가 플랫폼 봇 토큰과
소켓을 보유합니다. 게이트웨이는 단일 인증 WebSocket을 통해 커넥터로 **아웃바운드 연결**을
열고, 핸드셰이크에서 기능 설명자를 받은 다음, 정규화된 메시지 이벤트(인바운드)와 작업
(아웃바운드)을 해당 소켓으로 주고받습니다.

주요 특성:

- **아웃바운드 전용 네트워킹.** 게이트웨이는 인바운드 포트를 열지 않습니다.
  인바운드 메시지는 게이트웨이가 연결한 동일한 WebSocket을 통해 다시 전달되므로, 릴레이는
  NAT 뒤나 공인 IP가 없는 호스트에서도 작동합니다.
- **게이트웨이에 플랫폼 비밀 정보가 없습니다.** 봇 토큰은 커넥터에 보관됩니다.
  인증이 필요한 플랫폼 미디어 URL은 커넥터 측에서 다시 호스팅하므로 플랫폼 자격 증명이
  와이어를 통과하지 않습니다.
- **플랫폼에 종속되지 않습니다.** 게이트웨이는 하드코딩된 플랫폼 로직이 아니라 핸드셰이크
  설명자로부터 연결된 플랫폼이 할 수 있는 작업(메시지 길이 제한, 마크다운 방언, 편집/스레드/
  스트리밍 지원 및 정확한 지원 작업 집합)을 파악합니다.

공식 게이트웨이 ⇄ 커넥터 인터페이스는 저장소의
`docs/relay-connector-contract.md`에 있습니다.

## Relay를 사용해야 하는 경우

Relay는 호스팅 또는 공유 커넥터 서비스가 플랫폼 측을 관리하는 배포에 적합합니다. 예를 들어
하나의 공유 봇이 여러 사용자의 에이전트를 연결하는 멀티 테넌트 호스팅이나, 게이트웨이
머신에 봇 토큰을 두고 싶지 않은 환경이 이에 해당합니다. 봇을 직접 실행한다면 대신 기본
플랫폼 어댑터([Telegram](/user-guide/messaging/telegram),
[Discord](/user-guide/messaging/discord) 등)를 사용하세요.

## 등록

자체 호스팅 게이트웨이는 게이트웨이별 비밀 정보로 커넥터에 인증합니다.
`hermes gateway enroll`은 **한 번만 사용할 수 있는 등록 토큰**(테넌트의 경로가 프로비저닝될
때 커넥터가 발급하고 게이트웨이 구성과 함께 전달함)을 해당 비밀 정보로 교환합니다.

```bash
hermes gateway enroll \
  --token <enrollment-token> \
  --connector-url wss://connector.example.com/relay
```

수행하는 작업:

1. 기존 로그인(`~/.hermes/auth.json`)에서 최신 Nous Portal 액세스 토큰을 확인합니다. 이는
   사용자가 소유한 Nous 조직(테넌트)을 증명합니다. `gateway.idp.token_url`이 구성되어 있으면
   대신 자체 IdP를 사용합니다(에어갭/자체 호스팅 IdP 경로이며 Nous Portal은 관여하지 않음).
   `client_id`/`client_secret`이 구성되어 있으면 일반적인 OAuth2 클라이언트 자격 증명 부여를
   수행하고, 둘 다 구성되어 있지 않으면 URL을 주변 토큰 엔드포인트로 취급합니다(응답 본문이
   토큰인 일반 GET — 예: Domino의 `$DOMINO_API_PROXY/access-token` 메타데이터 서버 패턴).
   두 자격 증명 중 하나만 구성하면 오류입니다.
2. TLS를 통해 등록 토큰과 게이트웨이 ID를 커넥터의 `/relay/enroll` 엔드포인트로 POST합니다.
3. 커넥터가 토큰(서명, 일회성 사용, 테넌트 일치)을 검증하고, 게이트웨이별 비밀 정보와
   테넌트별 전달 키를 발급한 다음 한 번 반환합니다.
4. 자격 증명을 `~/.hermes/.env`에 저장합니다:
   `GATEWAY_RELAY_ID`, `GATEWAY_RELAY_SECRET`, `GATEWAY_RELAY_DELIVERY_KEY`
   (제공되는 경우 `GATEWAY_RELAY_URL` / `GATEWAY_RELAY_WAKE_URL`도 포함).

그 다음 게이트웨이를 다시 시작하여 새 환경 변수를 읽게 하세요.

플래그:

| 플래그 | 설명 |
|------|-------------|
| `--token` | 한 번만 사용할 수 있는 등록 토큰입니다. `GATEWAY_RELAY_ENROLL_TOKEN`으로도 설정할 수 있습니다. |
| `--connector-url` | 커넥터 기본 URL 또는 릴레이 URL(`wss://…/relay` 또는 `https://…`)입니다. `GATEWAY_RELAY_URL` 또는 `config.yaml`의 `gateway.relay_url`로도 설정할 수 있습니다. |
| `--gateway-id` | 이 게이트웨이 인스턴스의 안정적인 ID입니다(킬 스위치 세분화에 사용). 기본값은 `gw-<hostname>`입니다. |
| `--wake-url` | 게이트웨이가 유휴 상태일 때 버퍼링된 작업이 도착하면 커넥터가 깨우도록 호출하는, 연결 가능한 선택적 URL(페이로드 없는 GET)입니다. `GATEWAY_RELAY_WAKE_URL`로 저장됩니다. 이 값이 없어도 게이트웨이는 다음에 다시 연결할 때 버퍼링된 메시지를 모두 처리합니다. |

:::note 관리형 설치
`hermes gateway enroll`은 관리형/호스팅 설치에서 실행되지 않습니다. 해당 환경에서는 호스팅
플랫폼이 릴레이 비밀 정보를 컨테이너 환경에 직접 프로비저닝합니다.
:::

## 구성

커넥터 릴레이 URL이 구성되면 Relay가 활성화되며, 별도의 기능 플래그는 없습니다. 해당 URL을
설정하지 않는 배포에는 영향이 없습니다.

| 설정 | 위치 | 의미 |
|---------|-------|---------|
| `GATEWAY_RELAY_URL` | env (`~/.hermes/.env`) | 커넥터 릴레이 WebSocket URL입니다. 존재하면 릴레이 플랫폼이 활성화됩니다. |
| `gateway.relay_url` | `config.yaml` | 위와 동일하며 구성 파일 형식입니다(env가 우선함). |
| `GATEWAY_RELAY_ID` | env | 이 게이트웨이 인스턴스의 ID입니다(`enroll`이 기록함). |
| `GATEWAY_RELAY_SECRET` | env | WebSocket 업그레이드를 인증하는 게이트웨이별 비밀 정보입니다(`enroll`이 기록함). |
| `GATEWAY_RELAY_DELIVERY_KEY` | env | 테넌트별 전달 키입니다(`enroll`이 기록하며 향후 호환성을 위해 유지됨). |
| `GATEWAY_RELAY_WAKE_URL` / `gateway.relay_wake_url` | env / `config.yaml` | 유휴/일시 중지된 게이트웨이를 위한 선택적 깨우기 호출 대상입니다. |
| `GATEWAY_RELAY_PLATFORMS` | env | 하나의 연결을 통해 이 게이트웨이가 앞단에서 제공하는 플랫폼의 쉼표로 구분된 목록입니다(예: `discord,telegram`). 일반적으로 배포/오케스트레이터가 기록합니다. |
| `GATEWAY_RELAY_BOT_IDS` | env | 플랫폼별 봇 ID의 JSON 매핑입니다(예: `{"discord": {"botId": "…"}}`). `GATEWAY_RELAY_PLATFORMS`와 함께 사용합니다. |
| `gateway.idp.token_url` | `config.yaml` | 설정하면 등록/프로비저닝 시 Nous Portal 대신 자체 IdP에 인증합니다. `gateway.idp.client_id`/`client_secret`도 설정되어 있으면 OAuth2 클라이언트 자격 증명을 사용하고, 그렇지 않으면 주변 토큰 엔드포인트(토큰을 원문 또는 `{"access_token": …}`으로 반환하는 일반 GET)를 사용합니다. |

## 지원되는 기능

릴레이 연결에서 실제로 작동하는 기능은 핸드셰이크 시 협상됩니다. 커넥터는
`supported_ops` 목록을 알리고, 게이트웨이는 커넥터가 명시적으로 알린 작업만 사용합니다
(이전 커넥터는 기존 `send`/`edit`/`typing`/`follow_up` 집합으로 대체됩니다). 플랫폼별 기능
플래그(편집 기반 스트리밍, 스레드, 초안 스트리밍, 마크다운 방언, 메시지 길이 제한)도
핸드셰이크 설명자에서 가져옵니다. 이 협상에 따라 릴레이는 다음을 지원합니다.

- **텍스트 메시지 및 스트리밍** — 전송, 답장, 그리고 연결된 플랫폼이 메시지 편집을 지원할
  때의 점진적 편집 기반 스트리밍을 지원합니다. 그렇지 않으면 출력이 세그먼트당 한 메시지로
  저하됩니다.
- **양방향 미디어** — 아웃바운드 이미지, 음성, 오디오, 비디오 및 문서는 커넥터에 업로드되거나
  공개 URL로 참조되어 각 플랫폼의 기본 업로드 경로를 통해 캡션과 함께 전달됩니다.
  인바운드 첨부 파일은 에이전트가 사용할 수 있도록 파일로 로컬화됩니다. 인증이 필요한
  플랫폼 URL은 커넥터 측에서 다시 호스팅되므로 플랫폼 자격 증명이 게이트웨이에 도달하지
  않습니다. 미디어 재호스팅은 25MB로 제한되며 약 1시간 후 만료됩니다.
- **기본 인터랙티브 프롬프트** — exec 승인, 확인 및 명확화 질문이 번호가 매겨진 텍스트
  대체 UI가 아니라 **플랫폼 기본 컨트롤**(Discord 버튼, Telegram 인라인 키보드, Slack
  Block Kit 작업, WhatsApp 버튼/목록 메시지)로 표시됩니다. 버튼 누르기는 실제로 클릭한
  사용자가 보낸 인증된 프롬프트 응답으로 돌아오므로 게이트웨이의 인증 게이트가 입력된
  답장과 정확히 동일하게 적용됩니다. 프롬프트 만료는 게이트웨이 측에서 적용됩니다.
- **반응 확인 수명 주기** — 봇의 처리 상태 반응(처리 중 👀, 완료 시 ✅/❌)이 릴레이를 통해
  작동합니다. 반응은 최선 노력 방식이므로 반응 실패가 턴 전체를 실패시키지는 않습니다.
- **스레드 수명 주기** — 플랫폼 추상화된 `thread_create` / `thread_rename` 작업을 통해
  핸드오프 스레드를 만들고 스레드 이름을 변경합니다(LLM이 지정한 의미 기반 이름 변경 포함).
  사람이 수동으로 이름을 변경한 경우 우선하도록 덮어쓰기 방지 가드가 있습니다. 사용 가능
  여부는 플랫폼에 따라 다릅니다(예: Slack 스레드는 이름을 변경할 수 없고 WhatsApp에는
  스레드가 없음).
- **입력 중 표시기** — 처리 중 게이트웨이는 입력 중 상태(및 입력 중지 상태)를 커넥터를
  통해 송신합니다.
- **채팅 메타데이터** — 커넥터가 알린 경우 `get_chat_info` 조회가 커넥터로 프록시됩니다.
- **버퍼링된 전달 및 깨우기** — 게이트웨이가 유휴 상태가 되거나 연결이 끊기면 커넥터가
  인바운드 메시지를 내구성 있게 버퍼링하고 재연결 시 순서대로 재생합니다(확인 응답에 의해
  제어되며 손실이나 중복이 없음). 깨우기 URL이 등록되어 있으면 잠자고 있는 게이트웨이에
  버퍼링된 작업이 도착할 때 커넥터가 해당 URL을 호출합니다.

멀티플랫폼 연결도 지원됩니다. 하나의 게이트웨이가 단일 릴레이 연결을 통해 여러 플랫폼(예:
Discord와 Telegram)을 앞단에서 제공할 수 있으며, 각 아웃바운드 메시지에는 대상 플랫폼이
태그됩니다.

## 문제 해결

**등록이 401로 실패함** — 커넥터가 신원 토큰을 확인하지 못했습니다.
`hermes auth add nous`(또는 `hermes setup`)로 다시 로그인한 뒤 재시도하세요.

**등록이 403으로 실패함** — 등록 토큰이 유효하지 않거나, 만료되었거나, 이미 사용되었거나,
다른 테넌트에 속해 있습니다. 등록 토큰은 한 번만 사용할 수 있으므로 테넌트 경로를
프로비저닝한 담당자에게 새 토큰을 요청하세요.

**"커넥터에 연결할 수 없음"** — 커넥터 URL을 확인하세요. `wss://…/relay` 다이얼 URL이나
`https://…` 기본 URL을 붙여넣을 수 있으며, CLI가 둘 사이를 자동으로 변환합니다.

**`enroll` 실행이 거부됨** — 릴레이 비밀 정보가 호스팅 플랫폼에 의해 프로비저닝되는
관리형/호스팅 설치 환경입니다. 자체 등록은 자체 호스팅 게이트웨이에서만 사용할 수 있습니다.

**이전에 작동하던 Relay 플랫폼이 비활성화된 것으로 표시됨** — 성공적인 핸드셰이크 *후* 코드
4401로 WebSocket이 닫혔다는 것은 게이트웨이의 비밀 정보가 취소되었다는 뜻입니다(예: 인스턴스가
프로비저닝 해제됨). 게이트웨이는 의도적으로 재연결을 중단하고 재시도하는 대신 릴레이를
비활성화된 것으로 보고합니다. 성공적인 핸드셰이크 *전*의 4401은 아직 프로비저닝되지 않은
일시적 경쟁 상태로 처리되며 정상적으로 재시도합니다.

**등록 후 아무것도 바뀌지 않음** — 게이트웨이는 시작 시 `GATEWAY_RELAY_*`를 읽습니다.
게이트웨이를 다시 시작하세요(`hermes gateway restart`).

**기능(버튼, 미디어, 스레드 등)이 일반 텍스트로 조용히 저하됨** — 플랫폼용 커넥터가
핸드셰이크의 `supported_ops`에서 해당 작업을 알리지 않았습니다. 게이트웨이는 커넥터가
처리할 수 없는 작업을 보내는 대신 의도적으로 텍스트 동작으로 대체합니다.
