# 여러 Hermes 인스턴스에 데스크톱 연결하기

로컬 런타임, LAN 또는 VPS의 원격 게이트웨이, SSH 호스트, Hermes Cloud 인스턴스 등 보유한 모든 Hermes 백엔드를 하나의 데스크톱 앱에 등록하고, 나란히 배치된 모든 인스턴스의 에이전트를 사용하세요.

이 문서는 [동시에 여러 게이트웨이 실행하기](./multi-profile-gateways.md)의 데스크톱 측 보완 문서입니다. 해당 문서가 한 컴퓨터에서 여러 게이트웨이를 호스팅하는 방법을 다룬다면, 이 문서는 하나의 데스크톱 앱이 여러 컴퓨터에 연결하는 방법을 다룹니다.

## 연결 레지스트리

**설정 → 연결**에서 에이전트 소스의 이름 있는 레지스트리를 관리합니다. 각 항목은 하나의 *연결*입니다.

| 종류 | 설명 | 인증 |
|---|---|---|
| **로컬** | 이 앱이 컴퓨터에서 관리하는 런타임 | 자동 |
| **원격 게이트웨이** | HTTP(S)로 연결할 수 있는 `hermes serve` 백엔드 — LAN, Tailscale, VPS | 세션 토큰 또는 OAuth |
| **SSH** | SSH로 접속하는 Hermes 설치본. 앱이 터널을 열고 대시보드를 대신 시작합니다 | SSH 키 + 채택된 토큰 |
| **Hermes Cloud** | Nous 계정을 통해 검색되는 호스팅 인스턴스 | 포털 로그인 |

알아 두면 좋은 규칙:

- **모든 연결에는 고유한 장치 이름이 필요합니다**("Homelab", "Work laptop"). 이 이름은 로스터 배지, 핸들, 업데이트 결과 등 인스턴스가 표시되는 모든 곳에 나타납니다.
- **로컬** 항목은 앱이 관리하며 제거할 수 없습니다. 다른 연결을 제거하면 해당 연결의 실행 중인 백엔드와 터널이 종료되지만 인스턴스 자체에는 아무 영향이 없습니다.
- **테스트**는 연결의 HTTP 및 WebSocket 구간을 모두 확인하므로, 통과하면 호스트가 응답했다는 뜻을 넘어 실제로 채팅할 수 있다는 의미입니다.
- Cloud 항목은 직접 입력한 URL에서 가져오는 것이 아니라 Hermes Cloud 로그인/검색 흐름에서 생성됩니다.
- 토큰은 OS 키링으로 암호화되며(키링이 없는 Linux에서 설정 → 게이트웨이와 동일한 평문 저장 옵트인), Electron 메인 프로세스 밖으로 나가지 않습니다.

### 단일 연결 설정에서 마이그레이션

레지스트리를 지원하는 빌드를 처음 실행하면 기존 설정을 자동으로 가져옵니다. 설정 → 게이트웨이의 전역 연결 모드와 프로필별 재정의가 이름 있는 레지스트리 항목으로 변환됩니다(URL/호스트 기준으로 중복 제거). 기존 설정 파일은 수정하지 않으므로 같은 컴퓨터의 이전 빌드도 계속 작동합니다.

## 여러 소스의 에이전트

등록된 모든 연결의 모든 프로필은 하나의 *에이전트*입니다. 통합 로스터는 여러 소스를 사용하는 화면(및 [Bot Mode](https://github.com/NousResearch/Hermes-Bot-Mode) 같은 플러그인)이 표시하는 목록입니다.

- 같은 프로필 이름이 여러 소스에 존재하면 핸들이 **`@name-device`** 형식으로 구분됩니다. Homelab의 `research`는 `@research-homelab`으로 표시되고, 모든 소스에서 고유한 프로필은 이름만 표시됩니다.
- 열거는 즉시 수행되지만 소켓 연결은 지연됩니다. 앱은 모든 소스에 WebSocket으로 연결하지 않고 REST를 통해 에이전트 목록을 가져옵니다. 연결할 수 없는 소스도 로스터 전체를 중단하지 않고 행별로 상태를 보고합니다. SSH 소스는 처음 에이전트를 열 때까지 연결 시점이 지연됩니다(예상치 못한 터널이 생성되지 않음).
- 에이전트를 열면 **해당 에이전트의 소스**에 연결합니다. 채팅, 세션, 메모리는 프로필을 소유한 컴퓨터에 존재하며, 해당 인스턴스를 직접 사용하는 것과 정확히 같습니다.

각 `(connection, profile)` 조합은 자체 백엔드와 소켓을 가지며, 로컬 프로필별 백엔드와 동일한 유휴 정리 방식으로 풀링됩니다. 다른 소스를 살펴보는 동안에도 백그라운드 에이전트는 계속 스트리밍합니다.

## 모든 인스턴스를 한 번에 업데이트

**설정 → 연결 → 모든 인스턴스 업데이트**는 업데이트 가능한 모든 연결에 `hermes update`를 병렬로 전달합니다.

- **로컬**은 앱 자체 업데이트 파이프라인을 통해 업데이트됩니다(설정 → 업데이트와 동일한 흐름).
- **원격 및 SSH** 연결에는 자체 백엔드를 통해 스스로 업데이트하라는 명령이 전달됩니다. 업데이트는 *해당* 컴퓨터에서 실행됩니다.
- **Hermes Cloud** 인스턴스는 플랫폼이 버전을 관리하므로 건너뜁니다.

각 인스턴스는 독립적으로 결과를 보고하므로 연결할 수 없는 장치 하나가 일괄 작업 전체를 멈추지 않습니다. 외부에서 업데이트를 관리하는 백엔드(Docker, Nix)는 행별로 자체 메시지를 표시하며 정중히 거부합니다.

## 플러그인 작성자를 위한 안내

데스크톱 [플러그인 SDK](../developer-guide/desktop-plugin-sdk.md)는 여러 소스 표면을 직접 노출합니다.

- `host.connections()` — 등록된 연결 목록(레이블, 종류, 기본 연결; 토큰 바이트는 포함하지 않음).
- `host.agents()` — 통합 로스터: 미리 계산된 `@name-device` 핸들을 포함해 `(source, profile)`마다 한 행.
- `host.ensureAgent(connectionId, profile)` — 에이전트의 게이트웨이를 활성화하여 이후 `host.request` 호출이 해당 백엔드로 전달되게 함.
- `host.warmAgent(connectionId, profile)` — 소켓을 미리 연결하는 fire-and-forget 작업(호버 의도).

네 가지 API 모두 기능 감지를 사용합니다. 이전 데스크톱 빌드에는 이 API가 없으므로 플러그인은 단일 소스 `profiles.list` 흐름으로 대체해야 합니다. Bot Mode의 여러 소스 로스터가 기준 소비자입니다.

## 문제 해결

- **에이전트는 표시되지만 열리지 않음** — 연결에서 **테스트**를 실행하세요. HTTP는 통과하지만 WebSocket이 실패한다면 프록시, 방화벽 또는 게이트웨이 인증/오리진 보호가 `/api/ws`를 차단하고 있을 가능성이 큽니다.
- **원격 소스가 로스터에 없음** — 해당 백엔드가 중지되었거나 연결할 수 없는 상태입니다. 로스터는 소스 아래에 오류와 함께 표시합니다. SSH 소스는 처음 사용할 때까지 *연결 시점이 지연*된 상태로 표시됩니다. 이는 오류가 아니라 의도된 동작입니다.
- **"다른 연결의 에이전트와 채팅하려면 Hermes Desktop을 업데이트하세요"** — 앱이 여러 연결 스택보다 오래된 버전입니다. 데스크톱 앱 자체를 업데이트하세요.
- **중복된 장치 이름** — 불가능합니다. 저장할 때 이름의 고유성이 강제됩니다. 마이그레이션한 이름이 충돌했다면 접미사가 붙습니다(`Homelab 2`).
