# ASCII 비디오 제작 파이프라인

## 사용 시점

다음과 같은 요청에 사용합니다: ASCII 비디오, 텍스트 아트 비디오, 터미널 스타일 비디오, 문자 아트 애니메이션, 레트로 텍스트 시각화, ASCII 오디오 비주얼라이저, 비디오를 ASCII 아트로 변환, 매트릭스 스타일 효과 또는 모든 종류의 애니메이션 ASCII 출력.

## 구성 내용

ASCII 아트 비디오를 위한 제작 파이프라인 — 모든 형식을 지원합니다. 비디오/오디오/이미지/생성형 입력을 컬러 ASCII 문자 비디오 출력(MP4, GIF, 이미지 시퀀스)으로 변환합니다. 비디오를 ASCII로 변환, 오디오 반응형 음악 비주얼라이저, 생성형 ASCII 아트 애니메이션, 하이브리드 비디오+오디오 반응형, 텍스트/가사 오버레이, 실시간 터미널 렌더링을 다룹니다.

## 크리에이티브 기준

이것은 시각 예술입니다. ASCII 문자가 매체라면, 기준은 영화입니다.

**코드를 한 줄이라도 작성하기 전에** 크리에이티브 콘셉트를 명확히 하세요. 분위기는 무엇인가요? 어떤 시각적 이야기를 전달하나요? 이 프로젝트가 다른 모든 ASCII 비디오와 다른 점은 무엇인가요? 사용자의 프롬프트는 출발점일 뿐입니다. 문자 그대로 옮기지 말고 창의적인 야심을 가지고 해석하세요.

**첫 렌더부터 뛰어나야 합니다.** 여러 번 수정하지 않아도 결과물이 시선을 사로잡아야 합니다. 무언가 평범하거나 밋밋하거나 "AI가 생성한 ASCII 아트"처럼 보인다면 잘못된 것입니다. 결과물을 내보내기 전에 크리에이티브 콘셉트를 다시 생각하세요.

**참고 자료의 익숙한 어휘를 넘어가세요.** 효과 카탈로그, 셰이더 프리셋, 팔레트 라이브러리는 시작을 위한 어휘입니다. 모든 프로젝트에서 새로운 패턴을 조합하고, 변형하고, 발명하세요. 카탈로그는 물감 팔레트일 뿐이며, 그림은 직접 그립니다.

**선제적으로 창의성을 발휘하세요.** 비전에 필요한 경우 스킬의 어휘를 확장하세요. 참고 자료에 비전에 필요한 내용이 없다면 직접 구현하세요. 사용자가 요청하지 않았지만 분명 좋아할 만한 시각적 순간을 하나 이상 포함하세요. 전환, 효과, 작품 전체를 끌어올리는 색상 선택 등이 될 수 있습니다.

**기술적 정확성보다 일관된 미학을 우선하세요.** 비디오의 모든 장면은 통일된 시각 언어로 연결되어야 합니다. 공통된 색온도, 서로 연관된 문자 팔레트, 일관된 움직임의 어휘를 사용하세요. 모든 장면이 서로 다른 무작위 효과를 사용하는 기술적으로 올바른 비디오는 미학적으로 실패한 것입니다.

**촘촘하고, 겹겹이 쌓였으며, 숙고된 결과를 만드세요.** 모든 프레임은 볼 때마다 새로운 보상을 제공해야 합니다. 완전히 평평한 검은 배경은 절대 사용하지 마세요. 항상 다중 그리드 구성을 사용하세요. 장면마다 변화를 주세요. 항상 의도적으로 색을 사용하세요.

## 스택

프로젝트마다 독립 실행 가능한 Python 스크립트 하나를 사용합니다. GPU는 필요하지 않습니다.

| 계층 | 도구 | 목적 |
|------|------|------|
| Core | Python 3.10+, NumPy | 수학, 배열 연산, 벡터화된 효과 |
| Signal | SciPy | FFT, 피크 감지(오디오 모드) |
| Imaging | Pillow (PIL) | 글꼴 래스터화, 프레임 디코딩, 이미지 I/O |
| Video I/O | ffmpeg (CLI) | 입력 디코딩, 출력 인코딩, 오디오 mux |
| Parallel | concurrent.futures | 배치/클립 렌더링을 위한 N개 워커 |
| TTS | ElevenLabs API (선택 사항) | 내레이션 클립 생성 |
| Optional | OpenCV | 비디오 프레임 샘플링, 에지 감지 |

## 파이프라인 아키텍처

모든 모드는 동일한 6단계 파이프라인을 따릅니다.

```
INPUT → ANALYZE → SCENE_FN → TONEMAP → SHADE → ENCODE
```

1. **INPUT** — 소스 자료(비디오 프레임, 오디오 샘플, 이미지 또는 없음)를 로드/디코딩합니다.
2. **ANALYZE** — 프레임별 특성(오디오 대역, 비디오 휘도/에지, 모션 벡터)을 추출합니다.
3. **SCENE_FN** — 픽셀 캔버스(`uint8 H,W,3`)로 장면 함수를 렌더링합니다. `_render_vf()`와 픽셀 블렌드 모드를 사용해 여러 문자 그리드를 합성합니다. `references/composition.md`를 참고하세요.
4. **TONEMAP** — 백분위수 기반의 적응형 밝기 정규화를 적용합니다. `references/composition.md` § Adaptive Tonemap을 참고하세요.
5. **SHADE** — `ShaderChain` + `FeedbackBuffer`를 사용해 후처리합니다. `references/shaders.md`를 참고하세요.
6. **ENCODE** — 원시 RGB 프레임을 ffmpeg로 파이프해 H.264/GIF로 인코딩합니다.

### 섹션별 변화

비디오 전체에 같은 설정을 사용하지 마세요. 각 섹션/장면에 다음을 적용하세요.
- **서로 다른 배경 효과**(또는 2~3개를 합성)
- **서로 다른 문자 팔레트**(분위기에 맞춤)
- **서로 다른 색상 전략**(최소한 다른 색조라도 적용)
- **셰이더 강도 변화**(절정에는 블룸을 더 강하게, 고요한 부분에는 그레인을 더 강하게)
- 파티클이 활성화되어 있다면 **서로 다른 파티클 유형**

### 프로젝트별 발명

모든 프로젝트에서 다음 중 하나 이상을 발명하세요.
- 테마에 맞춘 사용자 지정 문자 팔레트
- 사용자 지정 배경 효과(기존 구성 요소를 조합/변형)
- 사용자 지정 색상 팔레트(브랜드/분위기에 맞춘 이산 RGB 세트)
- 사용자 지정 파티클 문자 집합
- 새로운 장면 전환 또는 시각적 순간

카탈로그에서 고르기만 하지 마세요. 카탈로그는 어휘이고, 시는 직접 씁니다.

## 핵심 구현 참고 사항

### 밝기 — 선형 배수가 아닌 `tonemap()` 사용

이것이 가장 중요한 시각적 문제입니다. ASCII는 검은색 위에서 본질적으로 어둡습니다. **`canvas * N` 배수는 절대 사용하지 마세요.** 하이라이트가 클리핑됩니다. 적응형 톤 매핑을 사용하세요.

```python
def tonemap(canvas, gamma=0.75):
    f = canvas.astype(np.float32)
    lo, hi = np.percentile(f[::4, ::4], [1, 99.5])
    if hi - lo < 10: hi = lo + 10
    f = np.clip((f - lo) / (hi - lo), 0, 1) ** gamma
    return (f * 255).astype(np.uint8)
```

파이프라인: `scene_fn() → tonemap() → FeedbackBuffer → ShaderChain → ffmpeg`

장면별 감마: 기본값 0.75, solarize 0.55, posterize 0.50, 밝은 장면 0.85. 어두운 레이어에는 `overlay`가 아니라 `screen` 블렌드를 사용하세요.

### 글꼴 셀 높이

macOS Pillow에서는 `textbbox()`가 잘못된 높이를 반환합니다. `font.getmetrics()`를 사용하세요: `cell_height = ascent + descent`. `references/troubleshooting.md`를 참고하세요.

### ffmpeg 파이프 데드락

실행 시간이 긴 ffmpeg에서 `stderr=subprocess.PIPE`를 절대 사용하지 마세요. 버퍼가 64KB에서 가득 차 데드락이 발생합니다. 파일로 리디렉션하세요. `references/troubleshooting.md`를 참고하세요.

### 글꼴 호환성

모든 유니코드 문자가 모든 글꼴에서 렌더링되는 것은 아닙니다. 초기화 시 팔레트를 검증하세요. 각 문자를 렌더링하고 빈 출력인지 확인합니다. `references/troubleshooting.md`를 참고하세요.

### 클립별 아키텍처

분할된 비디오(인용문, 장면, 챕터)는 병렬 렌더링과 선택적 재렌더링을 위해 각각 별도의 클립 파일로 렌더링하세요. `references/scenes.md`를 참고하세요.

## 크리에이티브 발산(사용자가 실험적/창의적/독특한 출력을 요청한 경우에만 사용)

사용자가 창의적이거나, 실험적이거나, 놀랍거나, 관습에 얽매이지 않은 출력을 요청하면 가장 적합한 전략을 선택하고 코드를 생성하기 전에 그 단계를 먼저 고민하세요.

- **강제 연결** — 사용자가 여러 분야의 영감을 원할 때("유기적으로 보이게", "산업적 미학")
- **개념적 혼합** — 사용자가 결합할 두 가지를 제시할 때("바다와 음악", "우주 + 캘리그래피")
- **비껴가기 전략** — 사용자가 최대한 자유롭게 열어 두었을 때("놀라게 해줘", "한 번도 본 적 없는 것")

### 강제 연결
1. 시각적 목표와 관련 없는 분야를 하나 고릅니다(기상 시스템, 미생물학, 건축, 유체 역학, 직물 짜기).
2. 그 분야의 핵심 시각/구조 요소를 나열합니다(침식 → 점진적 드러남, 유사분열 → 분할 복제, 직조 → 서로 맞물리는 패턴).
3. 해당 요소를 ASCII 문자와 애니메이션 패턴에 매핑합니다.
4. 종합합니다. 문자 그리드에서 "침식" 또는 "결정화"는 어떤 모습일까요?

### 개념적 혼합
1. 서로 다른 두 시각/개념 공간의 이름을 정합니다(예: 바다의 파도 + 악보).
2. 대응 관계를 매핑합니다(마루 = 높은 음, 골 = 쉼표, 거품 = 스타카토).
3. 선택적으로 혼합합니다. 가장 흥미로운 매핑은 남기고 억지스러운 것은 버립니다.
4. 혼합 안에서만 존재하는 창발적 특성을 발전시킵니다.

### 비껴가기 전략
1. 하나를 고릅니다: "너의 오류를 숨겨진 의도로 존중하라" / "오래된 아이디어를 사용하라" / "가장 가까운 친구라면 어떻게 할까?" / "결함을 강조하라" / "거꾸로 뒤집어라" / "전체가 아닌 일부만" / "반대로"
2. 현재 ASCII 애니메이션 과제에 맞춰 지시를 해석합니다.
3. 코드를 작성하기 전에 그 측면의 통찰을 시각 디자인에 적용합니다.
