# 소셜 미디어 콘텐츠 캘린더

선택한 소셜 플랫폼 전반에 걸쳐 구체적인 캘린더를 계획합니다. 이 스킬은 캠페인 구조, 게시물 브리프, 채널별 조정, 승인 및 게시 확인을 담당하며, `xurl` 같은 플랫폼 스킬은 API 명령을 담당합니다. 커넥터가 없는 플랫폼에서는 확인된 인계가 사용자의 스케줄러용 승인 초안에서 끝나므로, 게시되었다고 주장하지 마세요.

## 사용 시점

- "다음 달 소셜 미디어 캘린더를 만들어 줘."
- "이 출시 계획을 X, LinkedIn, Instagram, TikTok 게시물로 바꿔 줘."
- "캠페인을 초안 작성하고 예약해 줘."
- "이 기사/동영상을 소셜 콘텐츠로 재활용해 줘."

다음에는 사용하지 마세요: 일회성 게시물 하나(플랫폼 스킬을 직접 사용하세요).

## 절차

### 1. 캠페인 제약 조건 정의

목표, 대상, 제안/메시지, 플랫폼, 기간, 게시 빈도, 목소리, 필수/금지 주장, 링크, 추적 규칙, 현지화, 승인/게시 권한을 기록합니다. 제안된 각 게시물에 명확한 비즈니스 목적이 있으면 완료입니다.

### 2. 원본 자료 목록화

`read_file`과 `web_extract`를 사용해 검증된 제품 사실, 출시, 기사, 미디어, 허가를 받은 추천사, 브랜드 자산 및 주요 일정을 수집합니다. 주장 담당자와 만료일을 표시합니다. 뒷받침되지 않은 주장과 누락된 자산이 드러나면 완료입니다.

### 3. 테마와 캘린더 슬롯 구성

교육, 증거, 제품, 커뮤니티, 이벤트, 비하인드, 대화와 같은 유형을 균형 있게 섞습니다. 플랫폼별 게시 빈도와 캠페인 주요 시점을 고려합니다. 날짜, 플랫폼, 테마, 목표가 단순히 같은 내용을 교차 게시하는 것이 아니라 일관된 캘린더를 이루면 완료입니다.

### 4. 플랫폼별 브리프 작성

각 게시물에 훅, 핵심 메시지, 형식, 문구 길이, CTA, 링크, 자산 크기/콘텐츠, 접근성 텍스트, 태그/멘션, 성공 지표를 지정합니다. 플랫폼 간 복사-붙여넣기가 아니라 각 플랫폼에 맞게 조정합니다. 제작자가 숨은 맥락 없이 자산을 만들 수 있으면 완료입니다.

### 5. 문구와 자산 초안 작성

목소리를 위해 `humanizer`를 불러오고, 자산이 필요한 경우 `image_generate` 도구로 시각 자료를 생성합니다. 플랫폼 규범을 준수하면서 사실에 근거한 주장과 공유된 캠페인 정체성을 유지합니다. 모든 캘린더 슬롯에 초안 문구와 자산 상태가 있으면 완료입니다.

### 6. 편집 및 위험 검토

사실 정확성, 어조, 반복, 권리/허가, 접근성, 공개 사항, 링크 목적지, 날짜 적합성, 위기 민감성을 확인합니다. `draft`, `needs review` 또는 `approved`로 표시합니다. 초안에서 게시하지 마세요. 모든 게시물에 처분과 담당자가 있으면 완료입니다.

### 7. 예약 또는 인계

승인 묶음을 제시합니다. 승인된 게시물만 사용 가능한 플랫폼 스킬(`xurl` for X)을 사용해 게시/예약합니다. 커넥터가 없는 플랫폼에서는 승인된 패키지(문구, 자산, 일정)를 사용자의 예약 도구에 전달하고 해당 슬롯을 게시됨이 아니라 인계됨으로 표시합니다. 실제로 게시된 항목은 예약 시간, 계정, 콘텐츠 미리보기, 제공업체 게시물/작업 ID를 다시 읽어 확인합니다. 슬롯별로 확인된 게시 또는 인계 상태가 캘린더에 반영되면 완료입니다.

## 주의할 점

- 모든 플랫폼에 동일한 문구를 사용하기.
- 가치가 낮고 반복적인 게시물로 게시 빈도를 채우기.
- 검증되지 않은 지표, 추천사 또는 미래의 주장을 게시하기.
- 생성된 자산의 완료를 예약된 게시와 혼동하기.
- 인계가 초안에서 끝난 플랫폼에서 "예약됨"이라고 주장하기.

## 확인

- [ ] `draft` 또는 `needs review` 상태에서 게시된 게시물이 없다.
- [ ] 게시된 슬롯에는 제공업체가 확인한 ID가 있고, 인계된 슬롯은 그렇게 표시되어 있다.
- [ ] 게시 전에 권리, 허가 및 공개 사항을 확인했다.
