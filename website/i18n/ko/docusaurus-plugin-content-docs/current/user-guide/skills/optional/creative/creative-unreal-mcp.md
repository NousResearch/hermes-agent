# Unreal Engine MCP 스킬

Hermes MCP 카탈로그의 `unreal-engine` 항목을 위한 보조 스킬입니다. MCP 서버(Epic의 공식 실험용 "Unreal MCP" 플러그인, 내부 ID `ModelContextProtocol`)는 Unreal Editor 프로세스 **내부에서** 실행되며, 타입이 지정된 도구로 에디터 기능을 노출합니다. 이 스킬은 실시간 도구 표면을 탐색하고, 호출을 안전하게 순서화하며, 일반 영어 요청을 실제로 보기 좋은 씬으로 변환하고, 작업을 시각적으로 검증하는 방법을 안내합니다. 사용자는 에디터를 실행하는 것 외에 에디터를 직접 조작할 필요가 없습니다.

## 사용 시점

사용자가 Unreal Engine에서 무엇이든 하려는 경우 사용합니다. 레벨을 만들거나 꾸미고, 액터를 생성/이동/삭제하고, 조명과 분위기를 설정하고, 머티리얼 인스턴스를 만들거나 조정하고, 카메라 샷의 구도를 잡고, 스크린샷이나 렌더를 캡처하고, 에셋을 가져오고, 씬이나 UI를 검사하고, 자동화 테스트를 실행하거나, 에디터를 스크립팅하는 작업이 여기에 해당합니다. 단일 작업("태양을 골든 아워로 만들어")부터 완전한 다단계 프로젝트("모닥불이 있는 분위기 있는 숲속 공터를 만들고 그 장면을 렌더링해")까지 지원합니다.

다음에는 사용하지 않습니다. DCC 방식의 메시 모델링/스컬프팅(Blender에서 모델링한 뒤 결과를 가져오세요) 또는 Unreal C++ 프로젝트 소스 편집(이는 일반적인 코드 작업이므로 터미널을 사용하세요 — 이 스킬은 실시간 에디터를 다룹니다).

## 사전 요구 사항

두 부분을 다음 순서로 준비합니다. Hermes가 연결하기 전에 에디터 측이 실행 중이어야 합니다.

### 에디터 측 일회성 설정

1. 프로젝트가 열린 Unreal Editor **5.8 이상**. (macOS: 전체 Xcode가 설치되어 있고 라이선스가 승인되어야 합니다 — 그렇지 않으면 첫 실행 시 에디터가 종료됩니다. 함정을 참고하세요.)
2. **Edit > Plugins** — **Unreal MCP**를 활성화합니다(Toolset Registry 종속성이 자동으로 활성화됩니다). 메시지가 표시되면 에디터를 다시 시작합니다.
3. 타입이 지정된 도구 세트는 서버와 별도로 제공됩니다. 같은 Plugins 브라우저에서 **AllToolsets** 플러그인도 활성화합니다. Unreal MCP 자체에는 도구가 **전혀** 없습니다 — AllToolsets가 제공된 도구 세트(SceneTools, ActorTools, MaterialInstanceTools, ObjectTools, …)를 제공합니다. 이를 건너뛰면 서버는 연결되지만 에이전트가 호출할 도구가 없습니다.
4. **Edit > Editor Preferences > General > Model Context Protocol** — **Auto Start Server**를 활성화합니다. 기본 바인딩은 `http://127.0.0.1:8000/mcp`입니다(포트/경로는 같은 패널에서 설정 가능하며 서버 이름은 `unreal-mcp`입니다). 대신 수동으로 시작하려면 에디터 콘솔에서 `ModelContextProtocol.StartServer`를 실행합니다(백틱 키).

### Hermes 측 일회성 설정

    hermes mcp install unreal-engine

이 명령은 `http://127.0.0.1:8000/mcp`를 가리키는 `mcp_servers.unreal-engine` HTTP 항목을 작성하고 실시간 서버에서 도구를 탐색합니다. 실제 표면을 탐색할 수 있도록 에디터와 서버가 실행 중일 때 실행하세요. 사용자가 Editor Preferences에서 포트/경로를 변경했다면 `~/.hermes/config.yaml`의 `mcp_servers.unreal-engine` 아래 `url`을 그에 맞게 수정합니다.

Hermes에서는 `ModelContextProtocol.GenerateClientConfig`를 **사용하지 마세요** — 이 명령은 Claude Code/Cursor 등용 `.mcp.json` 형식의 파일을 작성합니다. Hermes는 카탈로그 항목을 통해 `config.yaml`에서 연결합니다.

### 매 세션

1. Unreal Editor를 실행하고 프로젝트 로딩이 끝날 때까지 기다립니다. 서버가 시작되었는지 확인합니다(Output Log에 바인딩 주소가 표시되거나 `ModelContextProtocol.StartServer`를 수동으로 실행).
2. Hermes 세션을 시작합니다. 도구는 `mcp_unreal_engine_*`로 등록됩니다. 도구가 없으면 에디터가 먼저 실행되지 않은 것입니다 — 에디터를 시작한 다음 새 Hermes 세션을 엽니다.
3. 상태 점검: `mcp_unreal_engine_list_toolsets`를 호출하고 도구 세트가 반환되는지 확인합니다.

## 도구 표면: 고정 목록이 아닌 탐색

기본적으로 플러그인은 **도구 검색 모드**로 실행됩니다. `tools/list`는 메타 도구 세 개만 반환하며, 모든 실제 도구는 이 메타 도구를 통해 접근합니다. Hermes에서는 다음과 같이 표시됩니다.

| Hermes 도구 | 용도 |
|---|---|
| `mcp_unreal_engine_list_toolsets` | 등록된 모든 도구 세트의 이름과 설명 |
| `mcp_unreal_engine_describe_toolset` | 이름이 지정된 하나의 도구 세트에 속한 도구의 전체 JSON 스키마 |
| `mcp_unreal_engine_call_tool` | 이름이 지정된 도구를 인수와 함께 호출하고 결과를 반환 |

항상 다음 순서로 탐색합니다.

1. `list_toolsets` → 이 프로젝트에 실제로 어떤 기능 그룹이 있는지 확인합니다(표면은 프로젝트에 따라 다릅니다. 활성화된 플러그인, Game Feature Plugin, 사용자 지정 도구 세트가 모두 기여합니다). 이름은 **정규화된 전체 이름**(`editor_toolset.toolsets.scene.SceneTools`, `EditorToolset.EditorAppToolset`)으로 반환됩니다 — `toolset_name`에 그대로 사용합니다.
2. 필요한 그룹에서 `describe_toolset`을 호출합니다 → 실제 매개변수 스키마를 읽습니다. 매개변수 이름을 추측하지 마세요 — 스키마가 계약입니다.
3. 정규화된 도구 세트 이름, **짧은 도구 이름**(`dotted` 형식이 아닌 `find_actors`), 스키마에 맞는 인수를 사용해 `call_tool`을 호출합니다.

세션에서 알아낸 내용을 캐시합니다. 에디터 측이 변경된 경우(새 플러그인 활성화, 도구 세트 작성, `RefreshTools` 실행)에만 다시 나열합니다.

대체 이른 탐색 모드(Editor Preferences에서 **Enable Tool Search**를 끔)는 모든 도구를 각자의 `mcp_unreal_engine_<tool>` 항목으로 광고합니다. 이 경우 탐색은 `hermes mcp install`/`configure` 시점에 대신 수행됩니다. 도구 검색 모드가 기본값이며 이 스킬이 가정하는 모드입니다. 또한 모든 API 호출에서 스키마 토큰을 제외하므로 이 모드를 선호합니다.

제공된 도구 세트 카탈로그, 사용자 지정 도구 세트 작성, 전체 플러그인 구성/콘솔 명령어 참고 자료는 `references/tool-surface.md`를 참조하세요.

## 운영 루프

모든 Unreal 작업은 동일한 루프를 따릅니다.

1. **먼저 검사합니다.** 도구 세트를 나열한 다음 변경하기 전에 씬/레벨 상태를 조회합니다. 비어 있거나 기본 레벨이라고 절대 가정하지 마세요. 익숙하지 않은 프로젝트에서는 프로젝트에 등록된 Agent Skills도 확인합니다(`call_tool` → `AgentSkillToolset.ListSkills`). 일치하는 프로젝트 스킬의 지침이 이 스킬의 일반 기본값보다 우선합니다.
2. **작고 단일 목적의 호출로 작업합니다.** `call_tool` 하나당 하나의 논리적 단계만 수행합니다. 서버는 도구를 게임 스레드에서 **직렬로 실행**하므로, 하나의 거대한 단일 작업은 작업이 끝날 때까지 에디터 UI를 멈추게 하고 클라이언트 시간 초과를 일으킬 수 있습니다. 예외: 5개를 초과하는 동종 작업 루프는 하나의 `ProgrammaticToolset.execute_tool_script` 호출로 서버 측에서 일괄 처리할 수 있습니다. 이 경우에도 직렬 규칙은 유지됩니다(`references/advanced-workflows.md`).
3. **겹치는 호출을 절대 실행하지 않습니다.** 한 턴에 여러 `mcp_unreal_engine_*` 호출을 일괄 처리하지 마세요 — Hermes는 일괄 호출을 동시에 실행하며, 게임 스레드에 대한 병렬 호출은 교착 상태에 빠지거나 실패합니다. 반드시 한 번 호출하고, 결과를 기다린 다음, 다음 호출을 진행합니다. 이는 일반적인 병렬 도구 호출 지침보다 우선합니다.
4. **모든 결과를 읽습니다.** 많은 도구(블루프린트 컴파일, 머티리얼 편집, 위젯 생성)는 프로토콜 수준의 예외 없이 응답 본문에 성공/실패를 보고합니다. 명시적인 성공이 아닌 것은 모두 중단하고 진단해야 하며, 대수롭지 않게 넘기지 않습니다. 속성을 쓴 뒤에는 값을 다시 읽습니다 — 여러 쓰기 경로가 조용히 아무 작업도 하지 않을 수 있습니다(함정 참고).
5. **시각적·구조적으로 검증합니다.** 각 마일스톤 후 변경한 액터/속성을 조회하여 상태를 확인하고, 구도가 중요한 경우 뷰포트 스크린샷을 캡처합니다(캡처 옵션은 `references/tool-surface.md` 참고; 이미지를 `vision_analyze`로 분석하세요 — 여러분이 아트 디렉터이며 판단해야 합니다).
6. **자주 저장합니다.** 패키지/레벨을 저장하기 전에는 에디터 편집 내용이 메모리에만 있으며, 에디터가 충돌하면 마지막 저장 이후의 모든 내용이 사라집니다. MCP 편집은 안정적으로 실행 취소할 수 없습니다. 대량 변경 전후와 각 마일스톤 후에 저장합니다.
7. **구체적으로 보고합니다.** 액터 레이블, 에셋 경로(`/Game/...`), 캡처/렌더 파일 위치를 보고합니다.

작업 중 적용되는 세계의 규칙:

- 단위는 **센티미터**이고, 축은 **Z-up**, X-forward입니다. 회전은 도 단위입니다(Rotator: X축을 중심으로 Roll, Y축을 중심으로 Pitch, Z축을 중심으로 Yaw). 사람의 눈높이는 약 165cm이고 문은 약 210×90cm입니다. 전체 표는 `references/scene-craft.md`에 있습니다.
- 콘텐츠 경로는 긴 패키지 이름을 사용합니다. 프로젝트 콘텐츠에는 `/Game/Folder/Asset.Asset`, 엔진 프리미티브에는 `/Engine/BasicShapes/Cube.Cube`를 사용합니다.
- 액터 **레이블**(Outliner에서 보이는 값이며 설정 가능하고 고유하지 않음)은 액터 **이름**(내부적으로 고유함)이 아닙니다. 레이블/클래스 쿼리로 액터를 확인한 다음 도구가 반환하는 핸들을 계속 사용하는 것을 선호합니다.
- 임의의 밝기 값보다 물리적으로 타당한 조명 값(럭스/칸델라/켈빈)을 선호합니다. 단, **먼저** 기존 태양의 세기를 읽어 씬의 보정 규칙을 파악해야 합니다. 템플릿 월드는 흔히 `intensity: 10`을 기준으로 보정되어 있으므로 물리적 값을 사용하면 과다 노출됩니다(`references/scene-craft.md`에 수치가 있고 `references/pitfalls.md` #12b에 보정 규칙이 있습니다).

## 일반 영어에서 씬으로

사용자는 사양이 아니라 의도를 제공합니다. 만들기 전에 이를 변환합니다.

1. **브리프를 추출합니다.** 주제, 분위기, 시간대, 실내/실외, 스타일, 결과물(스크린샷? 렌더? 플레이 가능한 레벨?)을 파악합니다. 명확히 해야 할 질문은 최대 한 차례만 하고, 이후 결정합니다 — 여러분은 기술 디렉터이며 Unreal 용어를 사용자에게 되풀이해서 떠넘기지 마세요.
2. **빌드 순서를 계획합니다.** 효과적인 순서는 레벨/환경 셸 → 블로킹(주요 지오메트리/메시 배치) → 조명 + 분위기 → 머티리얼 → 세트 장식/디테일 → 카메라 → 캡처/렌더입니다. 다단계 빌드에서는 계획을 할 일 목록으로 게시합니다.
3. **위의 루프로 빌드합니다.** 한 번에 하나의 마일스톤만 진행하고, 각 마일스톤에서 스크린샷을 찍습니다.
4. **스스로 아트 디렉팅합니다.** 각 스크린샷을 브리프와 비교합니다. 실루엣이 잘 읽히는가? 빛의 방향/세기가 그럴듯한가? 지평선이 정중앙에 있어 밋밋하지 않은가? 사람 키 기준과 비교해 스케일이 맞는가? 다음 단계로 넘어가기 전에 수정합니다.
5. **전달합니다.** 스크린샷/렌더를 파일(`MEDIA:` 경로)로 제공하고, 레벨에 무엇이 있으며 어디에 저장했는지 짧게 요약합니다.

`references/recipes.md`에는 완성된 작업 예시(외부 주간 장면, 분위기 있는 실내, 골든 아워 시네마틱 + 렌더, 에셋 가져오기 및 배치)와 정확한 호출 순서 및 값이 있습니다.

## 함정(항상 염두에 둘 것 — 전체 목록은 references/pitfalls.md)

- **시작 순서가 중요합니다.** 먼저 에디터 + 서버를 실행하고 그다음 Hermes 세션을 시작합니다. `mcp_unreal_engine_*` 도구가 없으면 순서가 잘못된 것입니다.
- **한 번에 한 호출입니다.** 게임 스레드는 직렬이므로 일괄 처리나 겹치는 호출을 하지 않습니다.
- **호출 중 에디터 UI가 멈춥니다.** 이는 게임 스레드 실행 방식에 따른 정상 동작입니다. 오래 걸리는 작업 중에는 사용자에게 알리고 호출을 작게 유지합니다.
- **모달 대화 상자가 모든 작업을 막습니다.** 모달 에디터 대화 상자를 여는(또는 그와 충돌하는) 도구 호출은 사람이 닫을 때까지 멈춥니다. 호출이 무기한 대기하면 사용자에게 에디터에 대화 상자가 있는지 확인하라고 안내합니다.
- **오래 걸리는 작업의 시간 초과.** Hermes의 호출별 기본 시간 제한은 120초입니다. 에셋 가져오기, 대규모 레벨 저장 및 렌더는 이를 초과할 수 있습니다. 렌더/가져오기 중심 세션에서는 `~/.hermes/config.yaml`의 `mcp_servers.unreal-engine.timeout`을 높입니다.
- **오래된 도구 스키마.** 도구 세트를 작성하거나 핫 리로드하거나 플러그인을 활성화한 뒤 에디터 콘솔에서 `ModelContextProtocol.RefreshTools`를 실행하고 `list_toolsets`를 다시 실행합니다. 새로운 C++ `UFUNCTION()`은 에디터를 완전히 다시 시작해야 나타납니다 — Live Coding으로는 노출되지 않습니다.
- **실험용 플러그인.** API와 도구 형태는 엔진 버전에 따라 바뀔 수 있습니다. 이 스킬의 예시를 포함해 기억에 의존하지 말고 `describe_toolset`을 신뢰하세요. 문서와 실시간 스키마가 다르면 실시간 스키마가 우선합니다.
- **서버를 로컬호스트 외부에 노출하지 마세요.** 의도적으로 루프백 전용이며 인증이 없습니다. 더 넓은 주소에 바인딩하라고 제안하지 마세요.
- **라이선스 참고.** 서버는 시작 시 로그를 남깁니다. 플러그인을 통해 연결된 LLM 서비스로 전송되는 데이터는 UE EULA(§6(e))에 따른 Licensed Technology입니다 — 사용자는 자신의 LLM 제공업체가 해당 데이터로 학습하지 않도록 할 책임이 있습니다. 사용자가 데이터 처리에 관해 묻는 경우 이 내용을 알립니다.

## 검증 체크리스트

- [ ] 세션 시작 시 `list_toolsets`가 도구 세트를 반환함(연결 정상)
- [ ] 첫 편집 전에 씬 상태를 조회함(비어 있다고 가정하지 않음)
- [ ] 각 마일스톤 후 변경한 액터/속성을 다시 조회하고 브리프와 비교해 스크린샷을 검토함
- [ ] 각 마일스톤과 마지막에 레벨/변경된 패키지를 저장함
- [ ] 결과물이 디스크에 존재함(스크린샷/렌더 경로를 확인함) 및 절대 경로를 사용자에게 보고함
- [ ] 에디터가 깨끗한 상태임: 보류 중인 모달 창이나 예기치 않은 미저장이 없고, 무엇을 어디에 생성/변경했는지 사용자에게 정확히 알림
