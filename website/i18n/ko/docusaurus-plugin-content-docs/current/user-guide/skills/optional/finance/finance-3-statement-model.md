# 3개 재무제표 재무 모델 템플릿 완성

손익계산서, 대차대조표, 현금흐름표 사이의 적절한 연결을 포함하는 통합 재무 모델 템플릿을 완성하고 채웁니다.

## ⚠️ 핵심 원칙 — 템플릿을 채우기 전에 읽으세요

**하드코드보다 수식 우선(절대 원칙):**
- 모든 예측 셀, 롤포워드, 연결, 소계는 반드시 Excel 수식이어야 합니다 — 미리 계산한 값을 사용하지 마세요.
- Python/openpyxl을 사용할 때는 수식 문자열(`ws["D15"] = "=D14*(1+Assumptions!$B$5)"`)을 작성하고, 계산 결과(`ws["D15"] = 12500`)를 작성하지 마세요.
- 하드코드 숫자를 포함해야 하는 셀은 오직 다음뿐입니다: (1) 과거 실제값, (2) Assumptions 탭의 가정 동인.
- Python에서 값을 계산한 뒤 그 결과를 셀에 작성하고 있다면 — 멈추세요. 대신 수식을 작성하세요.
- 이유: 시나리오를 전환하거나 가정을 변경할 때 모델이 유연하게 반응해야 합니다. 하드코드는 모든 후속 무결성 검사를 조용히 깨뜨립니다.

**사용자와 단계별로 검증하세요:**
1. **템플릿 매핑 후** → 확인한 탭/섹션을 사용자에게 보여 주고 셀을 변경하기 전에 확인받습니다.
2. **과거값 입력 후** → 사용자에게 과거값 블록을 보여 주고 값/기간이 원본 데이터와 일치하는지 확인받습니다.
3. **IS 예측 구축 후** → 소계 검사를 실행하고 사용자에게 예측 IS를 보여 준 뒤 BS로 이동하기 전에 확인받습니다.
4. **BS 구축 후** → 모든 기간의 대차대조표 검사(자산 = 부채 + 자본)를 사용자에게 보여 주고 CF로 이동하기 전에 확인받습니다.
5. **CF 구축 후** → 현금 연결 검사(CF 기말 현금 = BS 현금)를 사용자에게 보여 주고 최종 확정 전에 확인받습니다.
6. **전체 모델을 처음부터 끝까지 한 번에 채운 뒤 완성본으로 제시하지 마세요** — 각 재무제표 단계에서 멈추고 작업 내용을 보여 주어 오류를 조기에 발견합니다.

## 서식 — 전문적인 파란색/회색 팔레트(템플릿/사용자가 별도로 지정하지 않은 경우 기본값)

**색상을 최소화하세요.** 셀 채우기에는 파란색과 회색만 사용하세요. 녹색, 노란색, 주황색 또는 여러 강조 색상을 추가하지 마세요 — 깔끔한 모델은 절제된 색상을 사용합니다.

| 요소 | 채우기 | 글꼴 |
|---|---|---|
| 섹션 헤더(IS / BS / CF 제목) | 진한 파란색 `#1F4E79` | 흰색 굵게 |
| 열 헤더(FY2024A, FY2025E 등) | 연한 파란색 `#D9E1F2` | 검은색 굵게 |
| 입력 셀(과거값, 가정 동인) | 연한 회색 `#F2F2F2` 또는 흰색 | 파란색 `#0000FF` |
| 수식 셀 | 흰색 | 검은색 |
| 탭 간 연결 | 흰색 | 녹색 `#008000` |
| 검사 행 / 주요 합계 | 중간 파란색 `#BDD7EE` | 검은색 굵게 |

**파란색 3가지 + 회색 1가지 + 흰색이 전부입니다.** 템플릿 자체의 색상 체계가 있다면 템플릿을 따르세요.

글꼴 색상은 셀의 종류(입력/수식/연결)를 나타냅니다. 채우기 색상은 현재 위치(헤더/데이터/검사)를 나타냅니다.

## 모델 구조

### 템플릿 탭 구성 식별

템플릿마다 탭 이름 지정 방식과 구성이 다릅니다. 입력하기 전에 모든 탭을 검토하여 템플릿 구조를 파악하세요. 다음은 일반적인 탭 이름과 해당 탭에서 흔히 찾을 수 있는 내용입니다.

| 일반적인 탭 이름 | 찾아볼 내용 |
|------------------|------|
| IS, P&L, Income Statement | 손익계산서 |
| BS, Balance Sheet | 대차대조표 |
| CF, CFS, Cash Flow | 현금흐름표 |
| WC, Working Capital | 운전자본 스케줄 |
| DA, D&A, Depreciation, PP&E | 감가상각 및 상각 스케줄 |
| Debt, Debt Schedule | 부채 스케줄 |
| NOL, Tax, DTA | 순영업손실 스케줄 |
| Assumptions, Inputs, Drivers | 동인 가정 및 입력값 |
| Checks, Audit, Validation | 오류 검사 대시보드 |

**템플릿 검토 체크리스트**
- 템플릿에 어떤 탭이 있는지 식별합니다(모든 템플릿에 모든 스케줄이 포함되는 것은 아닙니다).
- 위에 나열되지 않은 템플릿 전용 탭이 있는지 기록합니다.
- 탭 간 종속성을 파악합니다(예: 어떤 스케줄이 주요 재무제표에 값을 공급하는지).
- 각 탭에서 입력 셀과 수식 셀의 위치를 찾습니다.

### 템플릿 구조 이해

데이터가 올바른 위치에 입력되고 기존 수식이 유지되도록, 템플릿을 채우기 전에 기존 레이아웃을 숙지하세요.

**행 구조 식별**
- 각 탭 상단에서 모델 제목을 찾습니다.
- 섹션 헤더와 시각적 구분을 식별합니다.
- $ millions, %, x 등을 나타내는 단위 행을 찾습니다.
- 실제값과 추정 기간을 구분하는 열 헤더를 확인합니다.
- 기간 레이블(예: FY2024A, FY2025E)을 확인합니다.
- 입력 셀과 수식 셀을 식별합니다(일반적으로 글꼴 색상으로 구분).

**열 구조 식별**
- 가장 왼쪽 열의 항목 레이블을 확인합니다.
- 예측 연도보다 과거 연도가 앞에 있는지 확인합니다.
- 과거 기간과 예측 기간을 구분하는 시각적 테두리를 확인합니다.
- 모든 탭에서 열 순서가 일관적인지 확인합니다.

**명명된 범위 사용**
템플릿은 주요 입력과 출력에 명명된 범위를 사용하는 경우가 많습니다. 데이터를 입력하기 전에 다음을 수행하세요.
- 템플릿의 기존 명명된 범위를 검토합니다(Excel의 수식 → 이름 관리자).
- 일반적인 명명된 범위에는 매출 성장률, 비용 비율, 주요 출력(순이익, EBITDA, 총부채, 현금), 시나리오 선택 셀이 포함됩니다.
- 이러한 명명된 범위에 값을 공급하는 셀에 입력값이 들어가는지 확인합니다.

### 예측 기간
- 템플릿은 일반적으로 마지막 과거 연도부터 향후 5년을 예측합니다.
- 과거(A) 열과 예측(E) 열이 명확히 구분되어 있는지 확인합니다.
- 열이 회계연도 표기(예: FY2024A, FY2025E)를 사용하는지 확인합니다.

## 마진 분석

**참고: 다음 마진 분석은 사용자가 요청했거나 템플릿에서 명시적으로 요구한 경우에만 수행해야 합니다. 요청이 없으면 이 섹션을 건너뛰세요.**

영업 효율성을 추적하고 동종 기업과 비교할 수 있도록 손익계산서(IS) 탭에서 수익성 마진을 계산하고 표시합니다.

### 포함할 핵심 마진

| 마진 | 수식 | 측정 대상 |
|--------|---------|------------------|
| 매출총이익률 | 매출총이익 / 매출 | 가격 결정력, 생산 효율성 |
| EBITDA 마진 | EBITDA / 매출 | 핵심 영업 수익성 |
| EBIT 마진 | EBIT / 매출 | D&A 반영 후 영업 수익성 |
| 순이익률 | 순이익 / 매출 | 최종 수익성 |

### 마진을 포함한 손익계산서 레이아웃

각 이익 항목 바로 아래에 마진 비율을 표시합니다.
- 매출총이익 아래에 매출총이익률 %
- EBIT 아래에 EBIT 마진 %
- EBITDA 아래에 EBITDA 마진 %
- 순이익 아래에 순이익률 %

## 신용 지표

**참고: 다음 신용 분석은 사용자가 요청했거나 템플릿에서 명시적으로 요구한 경우에만 수행해야 합니다. 요청이 없으면 이 섹션을 건너뛰세요.**

재무 건전성, 부채 수용 능력, 약정 준수 여부를 평가할 수 있도록 대차대조표(BS) 탭에서 신용/레버리지 지표를 계산하고 표시합니다.

### 포함할 핵심 신용 지표

| 지표 | 수식 | 측정 대상 |
|--------|---------|------------------|
| 총부채 / EBITDA | 총부채 / LTM EBITDA | 레버리지 배수 |
| 순부채 / EBITDA | (총부채 - 현금) / LTM EBITDA | 현금을 차감한 레버리지 |
| 이자보상배율 | EBITDA / 이자비용 | 부채 상환 능력 |
| 부채 / 총자본 | 총부채 / (총부채 + 자본) | 자본 구조 |
| 부채 / 자본 | 총부채 / 총자본 | 재무 레버리지 |
| 유동비율 | 유동자산 / 유동부채 | 단기 유동성 |
| 당좌비율 | (유동자산 - 재고) / 유동부채 | 즉각적인 유동성 |

### 신용 지표 계층 검사

상승 시나리오가 가장 강한 신용 프로필을 보이는지 검증합니다.
- 레버리지: Upside < Base < Downside (낮을수록 우수)
- 커버리지: Upside > Base > Downside (높을수록 우수)
- 유동성: Upside > Base > Downside (높을수록 우수)

### 약정 준수 추적

부채 약정이 알려져 있다면 실제 지표를 약정 기준값과 비교하는 명시적인 준수 검사를 추가합니다.

## 시나리오 분석(Base / Upside / Downside)

Assumptions 탭에서 CHOOSE 또는 INDEX/MATCH 수식을 사용하는 시나리오 전환(드롭다운)을 사용합니다.

| 시나리오 | 설명 |
|----------|-------------|
| Base Case | 경영진 가이던스 또는 컨센서스 추정치 |
| Upside Case | 가이던스를 웃도는 성장, 마진 확대 |
| Downside Case | 추세를 밑도는 성장, 마진 축소 |

**민감도 분석 대상 주요 동인**: 매출 성장률, 매출총이익률, SG&A %, DSO/DIO/DPO, CapEx %, 이자율, 세율.

**시나리오 감사 검사**: 전환 시 모든 재무제표가 변경되는지, 모든 시나리오에서 BS가 균형을 이루는지, 현금이 연결되는지, 계층이 유지되는지(Upside > Base > Downside: NI, EBITDA, FCF, 마진) 확인합니다.

## SEC 제출자료 데이터 추출

템플릿에 SEC 제출자료(10-K, 10-Q)에서 데이터를 가져오는 작업이 명시적으로 필요한 경우, 자세한 추출 지침은 [references/sec-filings.md](https://github.com/NousResearch/hermes-agent/blob/main/optional-skills/finance/3-statement-model/references/sec-filings.md)를 참조하세요. 이 참고자료는 규제 제출자료에서 공개 기업 데이터를 가져와 템플릿을 채울 때만 필요합니다.

## 모델 템플릿 완성

이 섹션은 기존 수식을 보존하고 데이터 무결성을 보장하면서 모든 3개 재무제표 재무 모델 템플릿을 완성하기 위한 일반적인 지침을 제공합니다.

### 1단계: 템플릿 구조 분석

데이터를 입력하기 전에 템플릿의 구조를 철저히 검토하여 아키텍처를 파악하세요.

**입력 셀과 수식 셀 식별**
- 입력 셀과 수식 셀을 구분하는 시각적 단서(글꼴 색상, 셀 음영)를 찾습니다.
- 일반적인 규칙: 파란색 글꼴 = 입력값, 검은색 글꼴 = 수식, 녹색 글꼴 = 다른 시트에 대한 연결
- Excel의 선행 셀/종속 셀 추적(수식 → 선행 셀 추적)을 사용하여 셀 관계를 파악합니다.
- 주요 입력을 제어할 수 있는 명명된 범위가 있는지 확인합니다(수식 → 이름 관리자).

**템플릿 흐름 매핑**
- 어떤 탭이 다른 탭에 값을 공급하는지 식별합니다(예: Assumptions → IS → BS → CF).
- 보조 스케줄과 주요 재무제표 간의 연결을 기록합니다.
- 입력 전에 템플릿의 구체적인 항목과 구조를 문서화합니다.

### 2단계: 수식을 깨뜨리지 않고 데이터 채우기

**데이터 입력 황금 규칙**

| 규칙 | 설명 |
|-------------|-------------|
| 입력 셀만 편집 | 수식이 포함된 셀은 의도적으로 수식을 교체하는 경우가 아니면 절대 덮어쓰지 않습니다. |
| 셀 참조 보존 | 데이터를 복사할 때 원본 서식으로 수식을 덮어쓰지 않도록 값 붙여넣기(Ctrl+Shift+V)를 사용합니다. |
| 템플릿 단위 일치 | 입력하기 전에 템플릿이 천 단위, 백만 단위 또는 실제값을 사용하는지 확인합니다. |
| 부호 규칙 준수 | 템플릿의 기존 부호 규칙을 따릅니다(예: 비용을 양수 또는 음수로 표시). |
| 순환 참조 확인 | 템플릿이 반복 계산을 사용하는 경우 반복 계산 사용이 켜져 있는지 확인합니다. |

**안전한 데이터 입력 절차**
1. 입력용으로 지정된 정확한 셀을 식별합니다(일반적으로 강조 표시되거나 레이블이 지정됨).
2. 먼저 과거 데이터를 입력한 다음 해당 기간의 수식이 올바르게 계산되는지 확인합니다.
3. 예측 계산에 값을 공급하는 가정 동인을 입력합니다.
4. 계산된 출력을 검토하여 수식이 의도대로 작동하는지 확인합니다.
5. 수식 셀을 수정해야 한다면 수정 전에 원래 수식을 기록합니다.

**미리 작성된 수식 처리**
- 아직 채우지 않은 셀을 수식이 참조한다면 모든 입력이 완료될 때까지 일시적인 오류(#REF!, #DIV/0!)가 발생할 수 있습니다.
- 수식이 예상과 다른 결과를 내면 선행 셀을 추적하여 누락되거나 잘못된 입력을 찾습니다.
- 모든 탭에서 수식 종속성을 확인하지 않고 행/열을 삭제하지 마세요.

### 3단계: 수식 검증

**수식 무결성 검사**

템플릿 출력을 신뢰하기 전에 수식이 올바르게 작동하는지 검증합니다.

| 검사 유형 | 방법 |
|------------|--------|
| 선행 셀 추적 | 수식 셀 선택 → 수식 → 선행 셀 추적으로 올바른 입력을 참조하는지 확인 |
| 종속 셀 추적 | 주요 입력이 예상 출력 셀로 전달되는지 확인 |
| 수식 평가 | 수식 → 수식 계산을 사용하여 복잡한 계산을 단계별로 확인 |
| 하드코드 확인 | 예측 수식은 하드코드 값을 포함하지 않고 가정을 참조해야 함 |
| 알려진 값으로 테스트 | 간단한 테스트 값을 입력하여 수식이 예상 결과를 내는지 확인 |
| 탭 간 일관성 | 모든 예측 기간에 동일한 수식 로직이 적용되는지 확인 |

**주의할 일반적인 수식 문제**
- 복사할 때 잘못된 결과를 만드는 절대/상대 참조 혼용
- 외부 파일 또는 삭제된 범위에 대한 연결 손상(#REF! 오류)
- 매출이 증가하기 전 초기 기간의 0으로 나누기(#DIV/0! 오류)
- 순환 참조 경고(이자 계산에서 의도된 것일 수 있음)
- 예측 열 간 수식 불일치(차이를 찾으려면 Ctrl+\\ 사용)

**탭 간 연결 검증**
- 여러 탭에 표시되는 값이 중복이 아니라 연결되어 있는지 확인합니다.
- 스케줄 합계가 주요 재무제표의 해당 항목과 일치하는지 확인합니다.
- 모든 탭에서 기간 레이블이 일치하는지 확인합니다.

### 4단계: 시트별 품질 검사

템플릿을 채운 후 각 시트에서 다음 검사를 수행합니다.

**손익계산서(IS) 품질 검사**
- 매출 수치가 과거 기간의 원본 데이터와 일치
- 모든 비용 항목이 보고된 합계와 일치
- 소계(매출총이익, EBIT, EBT, 순이익)가 올바르게 계산
- 세금 계산 로직이 적절함(손실을 올바르게 처리)
- 예측 동인이 가정 탭을 참조함(하드코드 없음)
- 기간별 변화 방향이 합리적임

**대차대조표(BS) 품질 검사**
- 모든 기간에 대해 자산 = 부채 + 자본(주요 검사)
- 현금 잔액이 현금흐름표 기말 현금과 일치
- 운전자본 계정이 보조 스케줄과 일치(해당하는 경우)
- 이익잉여금이 올바르게 롤포워드됨: 전기 이익잉여금 + 순이익 - 배당금 +/- 조정 = 기말 이익잉여금
- 부채 잔액이 부채 스케줄과 일치(해당하는 경우)
- 모든 대차대조표 항목의 부호가 적절함(자산은 양수, 대부분의 부채는 양수)

**현금흐름표(CF) 품질 검사**
- CFO 상단의 순이익이 손익계산서 순이익과 일치
- 비현금 가산 항목(D&A, SBC 등)이 원본 스케줄/재무제표와 일치
- 운전자본 변동의 부호가 올바름(자산 증가 = 현금 사용 = 음수)
- CapEx가 PP&E 스케줄 또는 고정자산 롤포워드와 일치
- 재무활동이 BS의 부채 및 자본 계정 변동과 일치
- 기말 현금이 대차대조표 현금과 일치
- 기초 현금이 전기 기말 현금과 같음

**보조 스케줄 품질 검사**
- 기초 잔액이 전기 기말 잔액과 같음
- 롤포워드 로직이 완전함(기초 + 추가 - 차감 = 기말)
- 스케줄 합계가 주요 재무제표 항목과 일치
- 계산에 사용된 가정이 Assumptions 탭과 일치

### 5단계: 재무제표 간 무결성 검사

개별 시트를 검증한 후 3개 재무제표가 올바르게 통합되었는지 확인합니다.

| 검사 | 수식 | 예상 결과 |
|-------|---------|-----------------|
| 대차대조표 균형 | 자산 - 부채 - 자본 | = 0 |
| 현금 연결 | CF 기말 현금 - BS 현금 | = 0 |
| 순이익 연결 | IS 순이익 - CF 기초 순이익 | = 0 |
| 이익잉여금 | 전기 이익잉여금 + 순이익 - 배당금 - BS 기말 이익잉여금 | = 0 (필요에 따라 SBC/기타 항목 조정) |

### 6단계: 최종 검토

모델이 완성되었다고 판단하기 전에 다음을 수행합니다.
- 모든 시나리오(해당하는 경우)를 전환하여 각 시나리오에서 검사가 통과하는지 확인합니다.
- 모든 #REF!, #DIV/0!, #VALUE!, #NAME? 오류를 검토하고 해결하거나 문서화합니다.
- 모든 입력 셀이 채워졌는지 확인합니다(자리표시자 값 검색).
- 모든 탭에서 단위가 일관적인지 확인합니다.
- 추가 수정 전에 깨끗한 버전을 저장합니다.

### 검사 범주

**섹션 1: 통화 일관성**
- 통화가 Assumptions에 식별되고 문서화됨
- 모든 탭에서 통화 기호와 배율이 일관됨
- 단위 행이 모델 통화와 일치

**섹션 2: 대차대조표 무결성**
- 자산 = 부채 + 자본(각 기간)
- 수식: 자산 - 부채 - 자본(반드시 = 0)

**섹션 3: 현금흐름 무결성**
- 현금이 BS와 연결됨(CF 기말 현금 = BS 현금)
- 월별 현금과 연간 현금: 월별 기말 현금 = 연간 기말 현금
- NI가 IS와 연결됨(CF 순이익 = IS 순이익)
- D&A가 스케줄과 연결됨
- SBC가 IS와 연결됨
- ΔAR, ΔInventory, ΔAP가 WC 스케줄과 연결됨
- CapEx가 DA 스케줄과 연결됨

**섹션 4: 이익잉여금**
- RE 롤포워드 검사: 전기 이익잉여금 + 순이익 + SBC - 배당금 = 기말 이익잉여금
- 디버깅을 위해 구성요소별 내역 표시

**섹션 5: 운전자본**
- AR, Inventory, AP가 BS와 연결됨
- DSO, DIO, DPO 합리성 검사(정상 범위를 벗어나면 표시)

**섹션 6: 부채 스케줄**
- 총부채가 BS와 연결됨(유동 부채 + 장기 부채)
- 이자 계산이 IS와 연결됨

**섹션 6b: 자본 조달**
- 자본 발행 대금이 BS 보통주/APIC 증가액과 연결됨
- 자본으로 인한 현금 증가 = 자본 계정 증가액(반드시 균형)
- 자본 조달 연결: ΔCommon Stock/APIC (BS) - Equity Issuance (CFF)(반드시 = 0)
- 0년 차 자본 연결: Equity Raised (Year 0) - Beginning Equity Capital (Year 1)

**섹션 6c: NOL 스케줄**
- 기초 NOL(1년 차 / 설립) = 0(신규 사업은 NOL 0에서 시작)
- EBT < 0일 때만 NOL 증가(손실이 실제로 발생해야 NOL 생성)
- DTA가 BS와 연결됨(NOL 스케줄 DTA = BS 이연법인세자산)
- NOL 사용량 ≤ EBT의 80%(2017년 이후 연방 제한)
- NOL 잔액은 음수가 아님(가용 잔액보다 많이 사용할 수 없음)
- EBT < 0일 때만 NOL 생성
- 과세소득이 ≤ 0이면 세금비용 = 0

**섹션 7: 시나리오 계층**
- 절대 지표: Upside > Base > Downside (NI, EBITDA, FCF)
- 마진: Upside > Base > Downside (GM%, EBITDA%, NI%)
- 신용 지표: 레버리지의 경우 Upside < Base < Downside(반대 방향)

**섹션 8: 수식 무결성**
- COGS, S&M, G&A, R&D, SBC가 매출 비율로 계산됨(하드코드 없음)
- 예측 연도 전체에서 수식이 일관됨
- #REF!, #DIV/0!, #VALUE! 오류 없음

**섹션 9: 신용 지표 기준값**
- 약정 기준값에 따라 지표를 녹색/노란색/빨간색으로 표시
- 모든 위험 신호 요약

### 마스터 검사 수식

모든 섹션의 상태를 하나의 마스터 검사로 집계합니다.
- 모든 섹션 통과 → "✓ ALL CHECKS PASS"
- 하나라도 실패 → "✗ ERRORS DETECTED - REVIEW BELOW"

### 빠른 디버깅 절차

마스터 상태에 오류가 표시될 때:
1. 스크롤하여 빨간색으로 강조된 섹션을 찾습니다.
2. 어떤 검사 범주에서 실패했는지 식별합니다.
3. 원본 탭으로 이동하여 조사합니다.
4. 근본 원인을 수정합니다.
5. Checks 탭으로 돌아가 해결 여부를 확인합니다.
