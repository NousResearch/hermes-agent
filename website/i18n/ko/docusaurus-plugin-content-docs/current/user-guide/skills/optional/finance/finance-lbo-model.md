## 중요 지침 — 먼저 읽기

Python/openpyxl을 사용합니다. 수식 문자열을 작성한 뒤(`ws["D20"] = "=B5*B6"`), 전달 전에 `excel-author` 스킬의 `recalc.py` 헬퍼를 실행합니다.

### 핵심 원칙
* **모든 계산은 Excel 수식이어야 합니다** — Python에서 값을 계산하여 셀에 결과를 하드코딩하는 행위는 절대 금지합니다. openpyxl을 사용할 때는 `cell.value = "=B5*B6"`(수식 문자열)를 작성하며, `cell.value = 1250`(계산된 결과)는 작성하지 않습니다. 입력이 변경되면 모델이 동적으로 업데이트되어야 합니다.
* **템플릿 구조를 사용합니다** — `examples/LBO_Model.xlsx` 또는 사용자가 제공한 템플릿의 구성을 따릅니다. 자체 레이아웃을 만들지 않습니다.
* **적절한 셀 참조를 사용합니다** — 모든 수식은 적절한 셀을 참조해야 합니다. 다른 셀에서 가져와야 하는 숫자를 직접 입력하지 않습니다.
* **부호 규칙의 일관성을 유지합니다** — 템플릿의 부호 규칙을 따릅니다(일부는 현금 유출을 음수로, 일부는 양수로 사용). 전체에서 일관성을 유지합니다.
* **섹션별로 작업하고 각 단계에서 사용자에게 확인받습니다** — 한 번에 한 섹션을 완성하고, 작성한 내용을 사용자에게 보여주며, 해당 섹션의 검증을 실행하고, 다음 섹션으로 이동하기 전에 확인을 받습니다. 전체 모델을 처음부터 끝까지 만든 후 제시하지 마세요. 이후 섹션은 이전 섹션에 의존하므로, 수익률을 모두 만든 뒤 Sources & Uses의 오류를 발견하면 모든 부분을 다시 작업해야 합니다.

### 수식 색상 규칙
* **파란색 (0000FF)**: 하드코딩된 입력 — 다른 셀을 참조하지 않는 직접 입력 숫자
* **검은색 (000000)**: 계산 수식 — 연산자 또는 함수를 사용하는 모든 수식(`=B4*B5`, `=SUM()`, `=-MAX(0,B4)`)
* **보라색 (800080)**: **같은 탭**의 셀 링크 — 계산 없이 직접 참조(`=B9`, `=B45`)
* **초록색 (008000)**: **다른 탭**의 셀 링크 — 시트 간 참조(`=Assumptions!B5`, `='Operating Model'!C10`)

### 채우기 색상 팔레트 — 전문적인 파란색 및 회색 (사용자/템플릿이 별도로 지정하지 않는 한 기본값)
* **최소한으로 사용합니다** — 셀 채우기에는 파란색과 회색만 사용합니다. 초록색, 노란색, 빨간색 또는 여러 강조 색상을 추가하지 마세요. 전문적인 LBO 모델은 절제된 색상 사용을 원칙으로 합니다.
* **기본 채우기 팔레트:**
  * **섹션 헤더** (Sources & Uses, Operating Model 등): 흰색 굵은 텍스트와 진한 파란색 `#1F4E79`
  * **열 헤더** (Year 1, Year 2 등): 검은색 굵은 텍스트와 연한 파란색 `#D9E1F2`
  * **입력 셀**: 연한 회색 `#F2F2F2`(또는 흰색) — 파란색 *글꼴*이 신호이며 채우기는 부차적입니다.
  * **수식/계산 셀**: 흰색, 채우기 없음
  * **핵심 출력** (IRR, MOIC, Exit Equity): 검은색 굵은 텍스트와 중간 파란색 `#BDD7EE`
* **팔레트는 이것이 전부입니다.** 파란색/검은색/보라색/초록색 **글꼴** 색상은 입력, 수식 및 링크를 구분하기 위한 것입니다. 위의 **채우기** 팔레트와는 별개이며, 둘을 함께 사용합니다.
* 참고: 위의 파란색/검은색/보라색/초록색 **글꼴** 색상은 입력과 수식을 구분하기 위한 것입니다. 템플릿이 자체 색상을 사용하는 경우 템플릿을 따릅니다.

### 숫자 서식 표준
* **통화**: `$#,##0;($#,##0);"-"` 또는 템플릿에 따라 `$#,##0.0`
* **백분율**: `0.0%` (소수점 한 자리)
* **배수**: `0.0"x"` (소수점 한 자리)
* **MOIC/상세 비율**: `0.00"x"` (정밀도를 위해 소수점 두 자리)
* **모든 숫자 셀**: 오른쪽 정렬

## 템플릿 분석 단계 - 먼저 수행

수식을 채우기 전에 템플릿을 철저히 검토합니다:

1. **구조를 매핑합니다** — 각 섹션의 위치와 상호 관계를 파악합니다. 어떤 섹션이 다른 섹션에 데이터를 제공하는지 기록합니다.

2. **타임라인을 이해합니다** — 어떤 열이 어떤 기간을 나타내는지 확인합니다. “Closing” 또는 “Pro Forma” 열이 있는지, 예측 기간이 어디서 시작되는지 확인합니다.

3. **입력 셀과 수식 셀을 식별합니다** — 템플릿은 입력이 필요한 셀과 수식이 필요한 셀을 나타내기 위해 색상 코드, 테두리 또는 음영을 사용하는 경우가 많습니다. 이러한 규칙을 준수합니다.

4. **기존 레이블을 주의 깊게 읽습니다** — 행 레이블은 필요한 계산을 정확히 알려줍니다. 추측하지 말고 템플릿이 요구하는 내용을 읽습니다.

5. **기존 수식을 확인합니다** — 일부 템플릿은 부분적으로 채워져 있습니다. 특별히 요청받지 않는 한 작동하는 수식을 덮어쓰지 않습니다.

6. **템플릿별 규칙을 기록합니다** — 부호 규칙, 소계 구조, 섹션 간 일치해야 하는 항목, 구성 방식, 구성 요소별 탭 분리 여부 등을 기록합니다.

## 일반적인 문제 영역

다음 계산 패턴은 LBO 모델 전반에서 자주 문제를 일으킵니다. 이러한 영역을 만날 때 특히 주의합니다:

### 균형을 맞춰야 하는 섹션
* 두 섹션이 같아야 하는 경우(예: Sources = Uses), 일반적으로 한 항목이 “플러그” 또는 균형 조정 수치가 됩니다.
* 플러그 항목을 식별하고 차이로 계산합니다.

### 세금 계산
* 세금 수식은 관련 소득 항목과 세율만 참조해야 합니다.
* 관련 없는 섹션(예: 부채 스케줄)을 참조해서는 **안 됩니다**.
* 손실이 세금 절감 효과를 발생시키는지 아니면 단순히 무시되는지 고려합니다.

### 이자 및 순환 참조
* 현금 흐름의 영향을 받는 잔액을 참조하면 이자 계산에 순환성이 생길 수 있습니다.
* 순환 참조를 끊으려면 **기초 잔액**(평균 또는 기말 잔액이 아님)을 사용합니다.
* 패턴: 이자 → 현금 흐름 → 상환 → 기말 잔액 (이자가 기말 잔액을 사용하면 다시 처음으로 돌아갑니다.)

### 부채 상환 / 현금 스윕
* 여러 부채 트랜치가 있는 경우 일반적으로 우선순위 순서가 있습니다.
* 현금 스윕은 우선순위 워터폴을 따라야 합니다.
* 잔액은 음수가 될 수 없으므로 `MAX` 또는 `MIN` 함수를 적절히 사용합니다.

### 수익률 계산 (IRR/MOIC)
* 현금 흐름의 부호가 올바라야 합니다: 투자 = 음수, 회수금 = 양수
* XIRR을 사용하는 경우 해당 날짜가 필요합니다.
* IRR을 사용하는 경우 현금 흐름은 연속된 기간이어야 합니다.
* MOIC = 총 회수금 / 총 투자금

### 민감도 표
* **홀수 차원을 사용합니다** (5×5 또는 7×7) — 4×4 또는 6×6은 절대 사용하지 않습니다. 홀수 차원은 진정한 중앙 셀을 보장합니다.
* **중앙 셀 = 기본 사례입니다.** 모델의 실제 가정을 중심으로 행과 열의 축 값을 대칭적으로 구성합니다(예: 기본 진입 배수가 10.0x라면 축 = `[8.0x, 9.0x, 10.0x, 11.0x, 12.0x]`). 중앙 셀의 IRR/MOIC는 모델의 실제 IRR/MOIC 출력과 반드시 같아야 합니다. 이것이 표가 올바르게 연결되었다는 증거입니다.
* **중앙 셀을 강조 표시합니다** — 굵은 글꼴과 중간 파란색 채우기(`#BDD7EE`)로 기본 사례를 시각적으로 고정합니다.
* Excel의 DATA TABLE 함수는 openpyxl에서 작동하지 않을 수 있으므로, 행/열 헤더를 참조하는 명시적 수식을 대신 작성합니다.
* 각 셀에는 서로 다른 값이 표시되어야 합니다 — 모두 같다면 수식이 올바르게 변하지 않는 것입니다.
* 혼합 참조를 사용합니다(예: 행 입력에는 `$A5`, 열 입력에는 `B$4`).

- [ ] 가정에 대한 링크가 올바릅니다.

### 대차대조표 (해당하는 경우)
- [ ] 자산 = 부채 + 자본 (반드시 균형을 이뤄야 함)
- [ ] 모든 항목이 적절한 스케줄 또는 롤포워드에 연결됩니다.
- [ ] 기초 잔액 = 이전 기간 기말 잔액
- [ ] 확인 행이 포함되어 있고 0을 표시합니다.

### 현금 흐름 (해당하는 경우)
- [ ] 올바른 손익 수치에서 시작합니다.
- [ ] 비현금 항목이 적절히 가감됩니다.
- [ ] 운전자본 변동의 부호가 올바릅니다.
- [ ] 기말 현금 = 기초 현금 + 순현금흐름
- [ ] 현금 잔액이 명세서 간 일관됩니다.

### 지원 스케줄
- [ ] 롤포워드 스케줄이 균형을 이룹니다(기초 + 변동 = 기말).
- [ ] 스케줄이 주요 명세서에 올바르게 연결됩니다.
- [ ] 계산 항목이 적절한 동인을 사용합니다.
- [ ] 모든 기간이 일관되게 계산됩니다.

### 부채/자금 조달 스케줄 (해당하는 경우)
- [ ] 기초 잔액이 Sources 또는 이전 기간에 연결됩니다.
- [ ] 이자가 적절한 잔액(일반적으로 기초 잔액)에 대해 계산됩니다.
- [ ] 상환이 가용 현금과 우선순위를 따릅니다.
- [ ] 기말 잔액이 음수가 될 수 없습니다.
- [ ] 트랜치별 합계가 올바르게 합산됩니다.

### 수익률/출력 분석
- [ ] 출구/터미널 가치가 올바르게 계산됩니다.
- [ ] 모든 관련 조정 항목이 포함됩니다.
- [ ] 현금 흐름의 부호가 올바릅니다(투자는 음수, 회수금은 양수).
- [ ] IRR/MOIC 수식이 전체 범위를 참조합니다.
- [ ] 결과가 해당 시나리오에 합리적입니다.

### 민감도 표 (해당하는 경우)
- [ ] 그리드 차원이 홀수입니다(5×5 또는 7×7) — 진정한 중앙 셀이 있습니다.
- [ ] 행과 열의 축 값이 기본 사례를 중심으로 대칭입니다(`[base-2Δ, base-Δ, base, base+Δ, base+2Δ]`).
- [ ] 중앙 셀 출력이 모델의 실제 IRR/MOIC와 같습니다 — 표가 올바르게 연결되었음을 확인합니다.
- [ ] 중앙 셀이 강조 표시됩니다(중간 파란색 채우기 `#BDD7EE`, 굵은 글꼴).
- [ ] 행과 열 헤더에 적절한 입력 값이 포함됩니다.
- [ ] 각 데이터 셀에 수식이 포함됩니다(하드코딩하지 않음).
- [ ] 각 데이터 셀에 서로 다른 값이 표시됩니다.
- [ ] 값이 예상 방향으로 움직입니다(출구 배수 증가 → IRR 증가 등).

### 서식
- [ ] 하드코딩된 입력은 파란색입니다(0000FF).
- [ ] 계산 수식은 검은색입니다(000000).
- [ ] 같은 탭 링크는 보라색입니다(800080).
- [ ] 다른 탭 링크는 초록색입니다(008000).
- [ ] 모든 숫자가 오른쪽 정렬됩니다.
- [ ] 전체에 적절한 숫자 서식이 적용됩니다.
- [ ] 어떤 셀에도 오류 값(#REF!, #DIV/0!, #VALUE!, #NAME?)이 표시되지 않습니다.

### 논리적 타당성 검사
- [ ] 숫자의 규모가 합리적입니다.
- [ ] 추세가 타당합니다(성장, 감소, 안정화가 예상대로 나타남).
- [ ] 명백히 잘못된 값이 없습니다(양수여야 하는 값의 음수, 불가능한 백분율 등).
- [ ] 핵심 출력이 해당 분석 유형에 합리적인 범위 안에 있습니다.

## 피해야 할 일반적인 오류

| 오류 | 발생하는 문제 | 해결 방법 |
|-------|-----------------|------------|
| 계산 값 하드코딩 | 입력이 변경되어도 모델이 업데이트되지 않음 | 항상 원본 셀을 참조하는 수식을 사용합니다. |
| 복사 후 잘못된 셀 참조 | 수식이 잘못된 셀을 가리킴 | 모든 링크를 확인하고 적절한 `$` 고정을 사용합니다. |
| 순환 참조 오류 | 모델을 계산할 수 없음 | 이자 유형 계산에는 기초 잔액을 사용하여 순환을 끊습니다. |
| 섹션의 균형이 맞지 않음 | 일치해야 하는 합계가 일치하지 않음 | 한 항목이 플러그인지 확인합니다(차이로 계산). |
| 불가능한 음수 잔액 | 가용 금액보다 많이 상환/사용함 | `MAX(0, ...)` 또는 `MIN` 함수를 적절히 사용합니다. |
| IRR/수익률 오류 | 부호가 잘못되었거나 범위가 불완전함 | 현금 흐름 부호를 확인하고 수식이 모든 기간을 포함하는지 확인합니다. |
| 민감도 표가 같은 값을 표시함 | 수식이 입력에 따라 변하지 않음 | 셀 참조를 확인합니다 — 혼합 참조가 필요합니다(`$A5`, `B$4`). |
| 롤포워드가 연결되지 않음 | 기초 ≠ 이전 기말 | 기간 간 링크를 확인합니다. |
| 부호 규칙이 일관되지 않음 | 가감이 반대로 처리됨 | 전체에서 템플릿의 규칙을 일관되게 따릅니다. |

## 사용자와 함께 작업하기 — 섹션별 체크포인트

* **템플릿 구조가 불명확하면** 진행하기 전에 질문합니다.
* **사용자의 요구 사항이 템플릿과 충돌하면** 선호 사항을 확인합니다.
* **각 주요 섹션을 완료한 후에는** 다음으로 진행하기 전에 **중지하고 사용자에게 확인받습니다**:
  - **Sources & Uses 후** → 균형 잡힌 표를 보여주고, 플러그가 올바른지 확인하며, 운영 모델을 작성하기 전에 승인을 받습니다.
  - **Operating Model / Projections 후** → 예상 손익계산서를 보여주고, 성장률과 마진이 올바른지 확인하며, 부채 스케줄로 넘어가기 전에 승인을 받습니다.
  - **Debt Schedule 후** → 기초/기말 잔액과 이자를 보여주고, 워터폴 로직을 확인하며, 수익률로 넘어가기 전에 승인을 받습니다.
  - **Returns (IRR/MOIC) 후** → 현금 흐름 시계열과 출력을 보여주고, 부호와 범위를 확인하며, 민감도 표로 넘어가기 전에 승인을 받습니다.
  - **민감도 표 후** → 각 셀이 변하는지 보여주고, 기본 사례가 예상한 위치에 도달하는지 확인합니다.
* **검증 중 오류가 발견되면** 다음 섹션으로 이동하기 전에 수정합니다.
* **작업 과정을 보여줍니다** — 도움이 될 때 핵심 수식이나 가정을 설명합니다.
* **각 섹션에서 확인하지 않고 완성된 모델을 제시하지 않습니다** — 잘못된 셀 참조를 IRR이 깨진 뒤 역추적하는 것보다 원본에서 발견하는 편이 빠릅니다.

**이 스킬은 템플릿에 올바른 수식, 적절한 서식 및 검증된 계산을 채워 투자은행 수준의 LBO 모델을 생성합니다. 스킬은 재무 정확성과 전문적인 표현 기준을 보장하면서 모든 템플릿 구조에 맞게 조정됩니다.**


## 데이터 출처 — MCP 우선, 웹 대체

아래의 많은 문단은 “S&P Kensho MCP / Daloopa MCP / FactSet MCP를 사용하라”고 안내합니다. 이는 원래 Cowork 컨텍스트의 상용 금융 데이터 MCP입니다. Hermes에서는:

- **구조화된 금융 데이터 MCP가 구성되어 있다면**(Hermes는 MCP를 지원합니다 — `native-mcp` 스킬 참고) 시점 기준 비교 기업, 선례 거래 및 공시 자료에 우선 사용합니다.
- **그 외에는** 다음으로 대체합니다:
  - 미국 공시 자료는 SEC EDGAR(`https://www.sec.gov/cgi-bin/browse-edgar`)에 대한 `web_search` / `web_extract`
  - 보도 자료와 실적 자료는 회사 IR 페이지
  - 대화형 데이터 포털은 `browser_navigate`
  - 사용자가 제공한 데이터(컨텍스트에 데이터가 없을 때는 명시적으로 요청)
- **절대 조작하지 않습니다.** 배수, 선례 또는 공시 수치를 출처로 확인할 수 없다면 해당 셀을 `[UNSOURCED]`로 표시하고 사용자에게 알립니다.
