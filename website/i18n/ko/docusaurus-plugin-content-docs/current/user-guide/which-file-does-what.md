# 각 파일의 역할

"에이전트에게 뭔가 말했는데 잊어버렸어요." "에이전트의 두뇌는 어느 파일인가요?" "SOUL.md를 편집했는데 왜 제 이름을 모를까요?" 이 질문들은 모두 같은 문제로 귀결됩니다. Hermes Agent는 여러 Markdown 파일의 영향을 받으며, 각 파일의 역할은 서로 다릅니다. 이 페이지에서 모든 파일을 한곳에 정리합니다. 각 파일을 자세히 알아보려면 [영구 메모리](/user-guide/features/memory), [성격 및 SOUL.md](/user-guide/features/personality), [컨텍스트 파일](/user-guide/features/context-files) 링크를 따라가세요.

## 핵심 표

| 파일 | 저장 내용 | 작성 주체 | 에이전트가 보는 시점 | 위치 |
|------|---------------|---------------|------------------------|----------------|
| **SOUL.md** | 에이전트의 기본 정체성 — 성격, 말투, 커뮤니케이션 방식, 문체상 피해야 할 것 | 사용자. Hermes는 파일이 없을 때 자동으로 시작 파일을 생성하며, 기존 파일은 절대 덮어쓰지 않음 | 세션 시작 시 시스템 프롬프트의 1번 슬롯 | `~/.hermes/SOUL.md`(또는 사용자 지정 홈의 경우 `$HERMES_HOME/SOUL.md`) — 작업 디렉터리에는 절대 생성되지 않음 |
| **USER.md** | 사용자 프로필 — 이름, 역할, 선호 사항, 커뮤니케이션 방식, 기대 사항 | 에이전트가 `memory` 도구를 통해 작성(저장 시 `write_approval`로 승인 여부를 설정하거나 `hermes journey edit`으로 항목을 편집할 수 있음) | 세션 시작 시 고정된 스냅샷으로 시스템 프롬프트에 주입 | `~/.hermes/memories/` |
| **MEMORY.md** | 에이전트의 개인 메모 — 환경 정보, 프로젝트 규칙, 도구의 특이 사항, 학습한 내용 | 에이전트가 `memory` 도구를 통해 작성(USER.md와 동일한 승인 및 편집 옵션) | 세션 시작 시 고정된 스냅샷으로 시스템 프롬프트에 주입 | `~/.hermes/memories/` |
| **AGENTS.md** | 프로젝트 지침, 규칙, 아키텍처 — 명령, 포트, 경로, 저장소별 워크플로 | 사용자(또는 프로젝트 작성자) | 시작 시 작업 디렉터리에서 시스템 프롬프트에 로드되며, 에이전트가 하위 디렉터리로 이동할 때 중첩된 파일을 점진적으로 탐색 | 프로젝트 작업 디렉터리 및 하위 디렉터리 |
| **.hermes.md** / **HERMES.md** | AGENTS.md와 같은 프로젝트 지침이지만 Hermes 전용이며 우선순위가 가장 높음 | 사용자 | 시작 시 시스템 프롬프트에 로드(AGENTS.md보다 먼저 발견되면 우선) | 프로젝트 — 탐색은 git 루트까지 상위 디렉터리로 진행 |

:::info 세션당 프로젝트 컨텍스트 파일 하나
세션마다 하나의 프로젝트 컨텍스트 유형만 로드되며, 먼저 일치하는 파일이 사용됩니다: `.hermes.md` → `AGENTS.md` → `CLAUDE.md` → `.cursorrules`. `SOUL.md`는 에이전트 정체성으로 항상 별도로 로드되며 이 우선순위 체인에 포함되지 않습니다. `CLAUDE.md`와 `.cursorrules` 호환성을 포함한 전체 목록은 [컨텍스트 파일](/user-guide/features/context-files)을 참조하세요.
:::

간단히 정리하면:

- **SOUL.md**는 에이전트가 *어떤 존재인지*를 정의합니다 — 어디서나 따라야 하는 내용이라면 여기에 둡니다.
- **USER.md**는 *사용자가 누구인지*를 정의합니다 — 에이전트가 사용자를 위해 관리합니다.
- **MEMORY.md**는 에이전트가 *무엇을 배웠는지*를 기록합니다 — 이 파일도 에이전트가 직접 관리합니다.
- **AGENTS.md**(또는 `.hermes.md`)는 *프로젝트가 필요로 하는 것*을 정의합니다 — 프로젝트에 속한 내용이라면 여기에 둡니다.

## "방금 말한 내용을 왜 잊었나요?"

메모리(`MEMORY.md` 및 `USER.md`)는 세션 시작 시 한 번 캡처한 **고정된 스냅샷**으로 시스템 프롬프트에 주입됩니다. 에이전트가 세션 중간에 내용을 저장하면 변경 사항은 즉시 디스크에 보존되지만 다음 세션이 시작될 때까지 시스템 프롬프트에는 나타나지 않습니다. 이는 성능을 위해 LLM의 접두사 캐시를 보존하도록 의도된 동작이며, 도구 응답에는 항상 최신 상태가 표시되므로 아무것도 손실되지 않습니다. 새 세션을 시작하면 업데이트된 메모리가 반영됩니다. 자세한 내용은 [시스템 프롬프트에 메모리가 표시되는 방식](/user-guide/features/memory#how-memory-appears-in-the-system-prompt)을 참조하세요.

## 자주 혼동하는 부분

### "SOUL.md에 내 정보를 적었는데 USER.md는 비어 있어요"

`SOUL.md`와 `USER.md`는 서로 연결되지 않는 별개의 시스템입니다. `SOUL.md`는 **사용자가** 직접 편집하는 성격 파일로, 말투와 정체성을 형성하며 그 내용이 프롬프트의 1번 슬롯에 원문 그대로 주입됩니다. `USER.md`는 영구 메모리의 일부이며 **에이전트가** `memory` 도구를 통해 작성합니다. USER.md에 자신에 관한 정보를 넣고 싶다면 에이전트에게("간결한 답변을 선호한다고 기억해 줘"처럼) 말하면 에이전트가 저장합니다. SOUL.md를 편집해도 메모리가 채워지지 않으며, 메모리 항목을 변경해도 페르소나가 바뀌지 않습니다. 지속적인 말투와 성격 지침에는 SOUL.md를 사용하고, 선호 사항과 프로필 정보는 메모리에 맡기세요. [SOUL.md에는 무엇을 넣어야 하나요?](/user-guide/features/personality#what-should-go-in-soulmd) 및 [두 대상 설명](/user-guide/features/memory#two-targets-explained)을 참조하세요.

### "세션 중간에 이름을 말했는데 못 들은 척해요"

에이전트가 이름을 메모리에 저장했다면 저장은 성공한 것입니다. `memory` 도구의 응답 또는 `hermes journey list`로 확인하세요. 현재 보이는 현상은 위의 고정 스냅샷 규칙 때문입니다. 시스템 프롬프트는 세션 중간에 새로 고쳐지지 않으므로 *주입된* 메모리 블록에는 여전히 세션 시작 시점의 상태가 표시됩니다. 에이전트는 현재 대화 안에서 사용자가 말한 내용을 계속 사용할 수 있으며(컨텍스트에 들어 있음), 저장된 항목은 다음 세션부터 시스템 프롬프트에 포함됩니다. 세션 실행 중 `SOUL.md`나 `AGENTS.md`를 편집하는 경우도 마찬가지입니다. 컨텍스트는 세션 시작 시 구성되므로 변경 사항을 반영하려면 세션을 다시 시작하세요.

:::tip 빠른 결정 가이드
- 에이전트가 **말하는 방식**을 바꾸고 싶나요? `~/.hermes/SOUL.md`를 편집하세요 — [성격 및 SOUL.md](/user-guide/features/personality).
- 에이전트가 **사실을 기억**하기를 원하나요? 그냥 말하세요 — 에이전트가 메모리에 직접 저장합니다. [영구 메모리](/user-guide/features/memory).
- **프로젝트 규칙**을 설정하고 싶나요? 프로젝트에 `AGENTS.md`(또는 `.hermes.md`)를 두세요 — [컨텍스트 파일](/user-guide/features/context-files).
- **임시로** 성격을 바꿔야 하나요? `/personality`를 사용하세요 — 파일을 편집할 필요 없이 세션 수준으로 덮어씁니다.
:::
